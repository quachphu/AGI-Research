To solve this problem, we need to determine the maximum number of smoke breaks Vasya, a cashier, can take during his workday. The key is to identify the gaps between customer service times and calculate how many breaks of a given duration can fit into these gaps.

### Approach
1. **Input Handling**: Read the number of customers, the length of the workday, and the duration of each smoke break.
2. **Identify Gaps**: Calculate the gaps before the first customer arrives, between consecutive customers, and after the last customer leaves until the end of the workday.
3. **Calculate Breaks**: For each identified gap, determine how many full smoke breaks of the given duration can fit into that gap. Sum these values to get the total number of breaks.

### Solution Code
```python
n, L, a = map(int, input().split())
customers = [tuple(map(int, input().split())) for _ in range(n)]

previous_end = 0
total = 0

for t, l in customers:
    gap = t - previous_end
    total += gap // a
    previous_end = t + l

# Check the time after the last customer
gap = L - previous_end
total += gap // a

print(total)
```

### Explanation
1. **Reading Input**: The input is read and parsed into the number of customers `n`, the length of the workday `L`, the duration of each smoke break `a`, and the list of customers' arrival times and service durations.
2. **Initialization**: Initialize `previous_end` to track the end time of the last customer served and `total` to accumulate the number of breaks.
3. **Processing Each Customer**: For each customer, calculate the gap between the end of the previous customer's service and the start of the current customer's service. Compute how many breaks fit into this gap and update `total`.
4. **Final Gap**: After processing all customers, calculate the gap between the end of the last customer's service and the end of the workday. Add the number of breaks that fit into this final gap to `total`.
5. **Output**: Print the total number of breaks.

This approach efficiently processes each customer and the gaps in linear time, making it suitable for large input sizes up to the problem constraints.
