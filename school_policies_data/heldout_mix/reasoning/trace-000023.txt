class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0]*(self.n +1)
    
    def update(self, index, delta):
        # 1-based index
        while index <= self.n:
            self.tree[index] += delta
            index += index & -index
    
    def query(self, index):
        # sum from 1..index
        res = 0
        while index >0:
            res += self.tree[index]
            index -= index & -index
        return res

To solve this problem, we need to determine the maximum number of orders a factory can fulfill if it starts maintenance on a specific day. The factory's production capacity changes before and after the maintenance period, and we need to efficiently handle updates to orders and queries about the maximum orders that can be fulfilled.

### Approach
1. **Data Structures**: Use two Fenwick Trees (Binary Indexed Trees) to efficiently compute prefix sums for production capacity before maintenance and suffix sums for production capacity after maintenance.
2. **Prefix and Suffix Sums**: 
   - **Prefix Sum**: Track the sum of orders that can be fulfilled with the current production capacity (b) before the maintenance period.
   - **Suffix Sum**: Track the sum of orders that can be fulfilled with the full production capacity (a) after the maintenance period.
3. **Handling Updates**: For each update, adjust the values in the Fenwick Trees to reflect the new orders and their impact on the production capacity constraints.
4. **Query Processing**: For each query, compute the sum of orders that can be fulfilled before and after the maintenance period using the prefix and suffix sums.

### Solution Code
```python
import sys

class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0] * (self.n + 1)  # 1-based indexing

    def update(self, index, delta):
        while index <= self.n:
            self.tree[index] += delta
            index += index & -index

    def query(self, index):
        res = 0
        while index > 0:
            res += self.tree[index]
            index -= index & -index
        return res

def main():
    input = sys.stdin.read().split()
    ptr = 0
    n = int(input[ptr]); ptr += 1
    k = int(input[ptr]); ptr += 1
    a = int(input[ptr]); ptr += 1
    b = int(input[ptr]); ptr += 1
    q = int(input[ptr]); ptr += 1

    orders = [0] * (n + 2)  # 1-based to n

    prefix_b_tree = FenwickTree(n)
    suffix_a_tree = FenwickTree(n)

    for _ in range(q):
        if input[ptr] == '1':
            # Update query
            di = int(input[ptr+1])
            ai = int(input[ptr+2])
            ptr += 3
            current = orders[di]
            new_val = current + ai
            # Update prefix_b_tree (min with b)
            delta_b = min(new_val, b) - min(current, b)
            prefix_b_tree.update(di, delta_b)
            # Update suffix_a_tree (min with a)
            delta_a = min(new_val, a) - min(current, a)
            suffix_a_tree.update(di, delta_a)
            orders[di] = new_val
        else:
            # Query
            pi = int(input[ptr+1])
            ptr += 2
            end_repair = pi + k - 1
            sum_before = prefix_b_tree.query(pi - 1)
            sum_after_start = end_repair + 1
            if sum_after_start > n:
                sum_after = 0
            else:
                total_a = suffix_a_tree.query(n)
                sum_up_to = suffix_a_tree.query(sum_after_start - 1)
                sum_after = total_a - sum_up_to
            total = sum_before + sum_after
            print(total)

if __name__ == "__main__":
    main()
```

### Explanation
- **Fenwick Trees**: These are used to maintain prefix sums for the current production capacity (b) and suffix sums for the full production capacity (a). This allows efficient updates and range queries.
- **Updates**: When an order update is received, we adjust the contributions of the affected day in both Fenwick Trees to reflect the new order count and its impact on production limits.
- **Queries**: For each query, we compute the sum of orders that can be fulfilled before the maintenance period using the prefix sum and after the maintenance period using the suffix sum. The days during maintenance are ignored as no production occurs.

This approach ensures that both updates and queries are handled efficiently, making the solution scalable for large input sizes.
