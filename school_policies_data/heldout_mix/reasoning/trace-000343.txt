To solve this problem, we need to generate a string of length `n` where each character is 'O' if its position (starting from 1) is part of the Fibonacci sequence, and 'o' otherwise. The Fibonacci sequence is defined such that the first two terms are 1, and each subsequent term is the sum of the previous two terms.

### Approach
1. **Generate Fibonacci Terms**: Generate all Fibonacci numbers up to `n`. This involves starting with the first two terms (both 1) and iteratively generating subsequent terms until the next term exceeds `n`.
2. **Check Membership**: For each position from 1 to `n`, check if the position is a Fibonacci number generated in the previous step. If it is, use 'O'; otherwise, use 'o'.
3. **Build the Result String**: Construct the result string by iterating through each position and appending the appropriate character based on the check.

### Solution Code
```python
n = int(input())

# Generate the Fibonacci sequence terms up to n
fib_terms = []
if n >= 1:
    a, b = 1, 1
    fib_terms.append(a)
    if n >= 2:
        fib_terms.append(b)
    while True:
        next_term = a + b
        if next_term > n:
            break
        fib_terms.append(next_term)
        a, b = b, next_term

fib_set = set(fib_terms)

result = []
for i in range(1, n + 1):
    if i in fib_set:
        result.append('O')
    else:
        result.append('o')

print(''.join(result))
```

### Explanation
1. **Generating Fibonacci Terms**: We start with the initial terms 1 and 1. Using a loop, we generate subsequent terms by summing the previous two terms. This continues until the next term exceeds `n`.
2. **Membership Check**: Using a set to store the Fibonacci terms allows for efficient membership checking. This ensures that each position check (whether it is a Fibonacci number) is done in constant time.
3. **Constructing the Result**: By iterating from 1 to `n` and checking each position against the set of Fibonacci terms, we build the result string efficiently.

This approach ensures that we generate the required string in linear time relative to `n`, making it efficient even for the upper constraint of `n = 1000`.
