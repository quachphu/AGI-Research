To solve this problem, we need to determine which tasks can be executed on the available servers at their respective start times and which tasks are ignored due to insufficient server availability. Each task requires a specific number of servers, and once a server starts a task, it remains busy for the duration of the task. The goal is to efficiently track server availability and handle each task accordingly.

### Approach
1. **Track Server Availability**: Maintain an array where each element represents the time at which a server (identified by its index) becomes available. Initially, all servers are available at time 0.
2. **Process Each Task**: For each task, check the availability of servers at the given start time. If enough servers are available, select the required number of servers with the smallest IDs, update their availability, and compute the sum of their IDs. If insufficient servers are available, record the task as ignored.

### Solution Code
```python
import sys

def main():
    n, q = map(int, sys.stdin.readline().split())
    available = [0] * (n + 1)  # Using 1-based indexing

    for _ in range(q):
        ti, ki, di = map(int, sys.stdin.readline().split())
        available_servers = []
        for server_id in range(1, n + 1):
            if available[server_id] <= ti:
                available_servers.append(server_id)
        if len(available_servers) >= ki:
            selected = available_servers[:ki]
            print(sum(selected))
            new_time = ti + di
            for s in selected:
                available[s] = new_time
        else:
            print(-1)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input consists of the number of servers and tasks, followed by the tasks' details (start time, required servers, and duration).
2. **Server Availability Tracking**: An array `available` is used to track when each server will be free. The index corresponds to the server ID.
3. **Processing Tasks**: For each task, we determine which servers are available at the start time by checking their availability times. If enough servers are available, we select the smallest IDs, update their availability times, and output the sum of their IDs. If not enough servers are available, we output -1.

This approach efficiently checks server availability for each task and updates their status, ensuring that the solution handles up to the maximum constraints effectively.
