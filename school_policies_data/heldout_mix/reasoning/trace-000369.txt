To solve this problem, we need to determine the maximum total amount of points that can be given to Azurim using special chats of denominations 500, 1000, 5000, and 10000. The goal is to maximize the sum of these points while ensuring that each transaction does not leave the remaining points negative.

### Approach
The optimal approach is to use a greedy algorithm, which involves selecting the largest denomination possible at each step until the remaining points can no longer be divided by any of the denominations. This approach works because using larger denominations first minimizes the number of transactions and maximizes the sum of points given.

1. **Sort Denominations in Descending Order**: Start with the largest denomination (10000) and proceed to smaller ones (5000, 1000, 500).
2. **Iterate Through Denominations**: For each denomination, determine how many times it can be used given the current remaining points.
3. **Update Total Points and Remaining Points**: Subtract the used points from the remaining points and add the used points to the total sum.
4. **Terminate Early**: If the remaining points become zero, terminate the loop early as no further transactions are possible.

### Solution Code
```python
def calculate_max_points():
    P = int(input())
    denominations = [10000, 5000, 1000, 500]
    total = 0
    for d in denominations:
        if P >= d:
            count = P // d
            total += count * d
            P -= count * d
        if P == 0:
            break
    print(total)

calculate_max_points()
```

### Explanation
- **Input Handling**: The input is read as an integer representing the total points available.
- **Denomination Processing**: The denominations are processed in descending order to maximize the sum of points used in each step.
- **Greedy Selection**: For each denomination, the maximum possible number of uses is calculated, which helps in quickly reducing the remaining points and accumulating the total points given.
- **Early Termination**: If at any point the remaining points reach zero, the loop terminates early to avoid unnecessary checks.

This approach ensures that the solution is both efficient and optimal, handling the constraints and input size effectively.
