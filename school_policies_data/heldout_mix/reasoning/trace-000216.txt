To solve this problem, we need to determine the minimum number of coins required to form the value specified in each query using coins that are integer powers of 2. If it's not possible to form the value, we should return -1 for that query.

### Approach
1. **Input Reading and Preprocessing**: Read the input values efficiently, especially given the constraints where the number of coins (n) and queries (q) can be up to 200,000 each.
2. **Frequency Count of Coin Values**: Convert each coin value into its exponent form (since each coin is a power of 2) and maintain a frequency count of these exponents.
3. **Processing Queries**: For each query, use a greedy approach to determine the minimum number of coins needed by starting from the highest possible exponent down to the smallest. This ensures we use the largest coins first, minimizing the number of coins used.

### Solution Code
```python
import sys

def main():
    input = sys.stdin.read().split()
    ptr = 0
    n, q = int(input[ptr]), int(input[ptr+1])
    ptr += 2
    a = list(map(int, input[ptr:ptr+n]))
    ptr += n
    queries = [int(input[ptr + i]) for i in range(q)]
    
    counts = [0] * 32  # Maximum exponent needed is 30 (since 2^30 is ~1e9)
    for num in a:
        d = num.bit_length() - 1
        counts[d] += 1
    
    results = []
    for b in queries:
        remaining = b
        total = 0
        for d in range(30, -1, -1):
            if remaining <= 0:
                break
            current_val = 1 << d
            if current_val > remaining:
                continue
            max_possible = remaining // current_val
            available = counts[d]
            use = min(max_possible, available)
            total += use
            remaining -= use * current_val
        results.append(total if remaining == 0 else -1)
    
    print('\n'.join(map(str, results)))

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the large possible input size. This helps in reducing the overhead of multiple I/O operations.
2. **Frequency Array**: We convert each coin value to its exponent form (e.g., 8 becomes 2^3, so exponent 3) and count how many coins exist for each exponent. This allows quick access to the number of coins available for any given power of 2.
3. **Greedy Approach for Queries**: For each query, we start from the highest exponent (30) down to 0. For each exponent, we check how many coins of that exponent can be used without exceeding the remaining value needed. We use as many of these coins as possible, reducing the remaining value accordingly. If we can reduce the remaining value to zero, we record the number of coins used; otherwise, we return -1.

This approach ensures that we efficiently use the largest coins first, minimizing the total number of coins used, which is optimal for the problem constraints. The time complexity is O(n + q * 31), which is efficient given the constraints.
