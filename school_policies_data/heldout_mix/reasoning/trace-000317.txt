To solve this problem, we need to determine the number of operations Tokitsukaze will perform to discard all special items from a list of items, considering the shifting of items after each discard. The challenge is to efficiently compute this without simulating each step due to the large possible size of the input.

### Approach
1. **Understanding the Problem**: Each operation involves discarding all special items from the first page that contains at least one special item. After discarding, all subsequent items shift left to fill the empty positions, which affects the pages of the remaining items.
2. **Key Insight**: Instead of simulating each shift, track the number of items removed so far and adjust the positions of the remaining items accordingly. This allows us to determine the correct page for each item dynamically.
3. **Efficient Batch Processing**: Process the items in batches where each batch corresponds to all items in the current page. Use binary search to quickly find the range of items in the current page.

### Solution Code
```python
import bisect

n, m, k = map(int, input().split())
p = list(map(int, input().split()))

total_removed = 0
operations = 0
i = 0

while i < m:
    current_p = p[i] - total_removed
    page = (current_p - 1) // k
    page_end = (page + 1) * k
    max_p_in_page = page_end + total_removed
    j = bisect.bisect_right(p, max_p_in_page, i, m) - 1
    count = j - i + 1
    total_removed += count
    operations += 1
    i = j + 1

print(operations)
```

### Explanation
1. **Reading Input**: The input values are read and stored, including the number of items, the number of special items, the page size, and the list of special item positions.
2. **Tracking Removals**: The variable `total_removed` keeps track of the number of items discarded so far. This helps adjust the positions of the remaining items.
3. **Page Calculation**: For each item starting from the current index, compute its adjusted position and determine the current page. The end of this page is calculated to find the maximum position that can be part of the current batch.
4. **Binary Search**: Using binary search, efficiently find the last item that falls within the current page. This allows us to process all items in the current page in one operation.
5. **Update Counters**: After processing each batch, update the total number of removed items, increment the operation count, and move to the next batch of items.

This approach ensures that we efficiently process each batch of items in logarithmic time relative to the number of special items, making it feasible even for large input sizes.
