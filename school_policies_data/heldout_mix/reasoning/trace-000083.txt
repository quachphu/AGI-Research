To solve this problem, we need to determine the k-th identifier pronounced by the robots in a specific sequence. The key challenge is to efficiently find the k-th element without explicitly generating the entire sequence, which would be computationally infeasible for large values of n and k.

### Approach
1. **Understanding the Sequence**: Each robot pronounces the identifiers of all previous robots followed by their own. This means the i-th robot contributes i elements to the sequence.
2. **Sum of Elements**: The total number of elements up to the i-th robot is given by the sum of the first i natural numbers, which is i*(i+1)/2.
3. **Binary Search for the Block**: Use binary search to find the smallest robot index m such that the sum of the first m natural numbers is at least k. This helps us identify which robot's block contains the k-th element.
4. **Position within Block**: Once the block (robot) is identified, compute the exact position within that block to determine the k-th element.

### Solution Code
```python
n, k = map(int, input().split())
ids = list(map(int, input().split()))

low, high = 1, n
m = n  # Initialize with the maximum possible value

while low <= high:
    mid = (low + high) // 2
    total = mid * (mid + 1) // 2
    if total >= k:
        m = mid
        high = mid - 1
    else:
        low = mid + 1

pos_in_block = k - (m - 1) * m // 2
print(ids[pos_in_block - 1])
```

### Explanation
1. **Binary Search for Block Identification**: The binary search efficiently narrows down the robot (block) that contains the k-th element. By checking the midpoint of the current search range, we adjust the range based on whether the cumulative sum of elements up to that midpoint is sufficient to include k.
2. **Position Calculation**: Once the block is identified, the position within the block is calculated by subtracting the cumulative elements of all previous blocks from k. This gives the exact position within the current block, which directly maps to the robot's identifier in the given list.

This approach ensures that we efficiently determine the k-th element in O(log n) time complexity due to the binary search, making it suitable for large input sizes as specified in the problem constraints.
