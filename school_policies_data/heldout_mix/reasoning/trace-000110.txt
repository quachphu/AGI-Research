To solve this problem, we need to determine the minimum number of operations required to convert a given number into a lucky number (a number consisting only of the digits 4 and 7). The allowed operations are adding 1, replacing a digit with any non-zero digit, and adding a non-zero leading digit.

### Approach
1. **Cost Modification (cost_mod)**: Calculate the number of digits that need to be changed to 4 or 7 to make the number a lucky number of the same length.
2. **Next Lucky Number of Same Length**: Generate the smallest lucky number greater than or equal to the given number by modifying digits from left to right, ensuring the number remains valid.
3. **Check Small Numbers**: For numbers with up to 4 digits, check the next 1000 increments to see if any of them form a lucky number, as this is feasible for small lengths.
4. **Compare Costs**: The minimum number of operations will be the smaller value between the cost_mod and the steps required to reach the next lucky number by incrementing (if feasible).
