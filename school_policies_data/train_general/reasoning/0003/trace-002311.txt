To solve this problem, we need to implement the Caesar Cipher encryption technique, which involves shifting each character in a message by a specified key. The solution must handle both uppercase and lowercase letters separately while preserving non-alphabetic characters and the case of each letter.

### Approach
1. **Input Handling**: Read the number of test cases. For each test case, read the key and the message.
2. **Key Adjustment**: Since the key can be larger than the number of letters in the alphabet (26), reduce the key modulo 26 to handle wrap-around cases.
3. **Character Shifting**: For each character in the message:
   - If it is a lowercase letter, shift it within the range 'a' to 'z'.
   - If it is an uppercase letter, shift it within the range 'A' to 'Z'.
   - Non-alphabetic characters are left unchanged.
4. **Construct Encrypted Message**: Collect the shifted characters and form the encrypted message for each test case.

### Solution Code
```python
def caesar_cipher():
    import sys
    t = int(sys.stdin.readline())
    for _ in range(t):
        k = int(sys.stdin.readline())
        message = sys.stdin.readline().rstrip('\n')
        adjusted_key = k % 26
        encrypted = []
        for c in message:
            if c.islower():
                shifted = (ord(c) - ord('a') + adjusted_key) % 26
                encrypted.append(chr(ord('a') + shifted))
            elif c.isupper():
                shifted = (ord(c) - ord('A') + adjusted_key) % 26
                encrypted.append(chr(ord('A') + shifted))
            else:
                encrypted.append(c)
        print(''.join(encrypted))

caesar_cipher()
```

### Explanation
1. **Reading Input**: The code reads the number of test cases `t` and then processes each test case by reading the key `k` and the message.
2. **Key Adjustment**: The key is adjusted using modulo 26 to handle cases where the key is larger than 26, ensuring it wraps around correctly.
3. **Character Processing**: Each character in the message is checked. If it is a lowercase or uppercase letter, it is shifted by the adjusted key. Non-alphabetic characters are added to the result without modification.
4. **Output**: The encrypted message for each test case is constructed and printed.

This approach ensures that the encryption is efficient and handles all edge cases, such as large keys and mixed-case messages, while preserving non-alphabetic characters.
