To solve this problem, we need to form the maximum number of teams from a group of programmers such that each team meets a specific skill requirement. The requirement is that the product of the number of programmers in a team and the minimum skill of any programmer in that team must be at least a given value \( x \).

### Approach
1. **Sort the Skills**: The key insight is to sort the programmers' skills in descending order. This allows us to form teams starting with the highest skills, which helps in meeting the requirement more efficiently.
2. **Greedy Team Formation**: Iterate through the sorted skills and form teams in a greedy manner. For each programmer, add them to the current team and check if the product of the current team size and the current programmer's skill (which will be the minimum skill in the team due to sorting) meets or exceeds \( x \). If it does, count this as a valid team and reset the current team size to start forming a new team.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    ptr = 0
    t = int(input[ptr])
    ptr += 1
    for _ in range(t):
        n, x = map(int, input[ptr:ptr+2])
        ptr += 2
        a = list(map(int, input[ptr:ptr+n]))
        ptr += n
        a.sort(reverse=True)
        current_group = 0
        count = 0
        for num in a:
            current_group += 1
            if current_group * num >= x:
                count += 1
                current_group = 0
        print(count)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the constraints.
2. **Sorting**: The skills array is sorted in descending order to facilitate forming teams with the highest possible minimum skill early.
3. **Greedy Team Formation**: As we iterate through the sorted skills, we maintain a count of the current team size. Each time the product of the current team size and the current skill meets or exceeds \( x \), we increment the team count and reset the current team size to start forming a new team.
4. **Output**: For each test case, the number of valid teams is printed.

This approach ensures that we efficiently form the maximum number of valid teams by leveraging sorting and a greedy strategy, which works within the problem's constraints.
