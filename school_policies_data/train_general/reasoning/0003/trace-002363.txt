### Approach
The key insight is that the optimal sequence alternates between giving 1 and 2 stones as much as possible. This approach minimizes the total number of stones used per step, allowing for the maximum number of steps. 

1. **Binary Search**: We use binary search to efficiently determine the maximum number of steps (k) such that the sum of the sequence of stones given does not exceed the total number of stones (n).
2. **Sum Calculation**: For each potential number of steps (k), we calculate the minimum possible sum. This sum varies based on whether k is even or odd:
   - **Even k**: The sum is \(3 \times (k / 2)\).
   - **Odd k**: The sum is \(3 \times ((k - 1) / 2) + 1\).

### Solution Code
```python
n = int(input())
low = 0
high = 2 * n
ans = 0

while low <= high:
    mid = (low + high) // 2
    if mid % 2 == 0:
        current_sum = (3 * mid) // 2
    else:
        current_sum = (3 * mid - 1) // 2
    if current_sum <= n:
        ans = mid
        low = mid + 1
    else:
        high = mid - 1

print(ans)
```

### Explanation
1. **Binary Search Setup**: We initialize the search range from 0 to \(2 \times n\). This range is chosen because the maximum possible number of steps (k) for a given n is bounded by \(2 \times n\).
2. **Mid Calculation**: For each midpoint (mid) in the binary search, we determine if the minimum sum of stones for mid steps is within the limit of n.
3. **Adjust Search Range**: If the current sum is within the limit, we update the answer and move the lower bound up. Otherwise, we adjust the upper bound down.
4. **Result**: The binary search concludes with the maximum valid number of steps (k) stored in `ans`.

This approach efficiently narrows down the possible number of steps using binary search, ensuring an optimal solution even for large values of n up to \(10^9\).
