To solve this problem, we need to determine the minimum number of currency notes required to sum up to a given amount \( N \) using the denominations Rs. 1, 2, 5, 10, 50, and 100. The solution should efficiently handle multiple test cases.

### Approach
1. **Greedy Algorithm**: The optimal approach for this problem is to use a greedy algorithm. This involves starting with the largest denomination and using as many of these notes as possible, then moving to the next largest denomination, and repeating this process until the entire amount \( N \) is accounted for. This approach works because each larger denomination is a multiple of the smaller ones, ensuring that using larger denominations first will always yield the minimum number of notes.

2. **Denomination Order**: The denominations are processed in descending order (100, 50, 10, 5, 2, 1) to ensure that we use the largest possible notes first, minimizing the total count.

3. **Efficiency**: For each test case, the algorithm processes each denomination once, making the time complexity \( O(1) \) per test case. Given the constraints (up to 1000 test cases), this approach is efficient and feasible.

### Solution Code
```python
import sys

def main():
    t = int(sys.stdin.readline())
    denominations = [100, 50, 10, 5, 2, 1]
    for _ in range(t):
        n = int(sys.stdin.readline().strip())
        count = 0
        remaining = n
        for d in denominations:
            count += remaining // d
            remaining = remaining % d
            if remaining == 0:
                break
        print(count)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The code reads the number of test cases \( T \) followed by \( T \) integers \( N \) from standard input.
2. **Processing Each Test Case**: For each amount \( N \), the algorithm initializes the count of notes to zero and processes each denomination in descending order.
3. **Greedy Calculation**: For each denomination, the algorithm calculates how many notes of that denomination can be used (using integer division), updates the remaining amount, and breaks early if the remaining amount becomes zero.
4. **Output**: The result for each test case is printed immediately after computation, ensuring minimal memory usage and efficient output handling.

This approach ensures that we always use the minimum number of notes by leveraging the structure of the currency denominations, providing an optimal and efficient solution.
