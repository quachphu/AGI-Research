To solve this problem, we need to determine the smallest amount of money that cannot be minimized using the greedy algorithm when paying with coins of denominations 1, A, and B. If the greedy algorithm is always optimal, we should return -1.

### Approach
1. **Understanding Greedy Algorithm**: The greedy algorithm works by using as many of the largest coin as possible, then the next largest, and so on. For example, given coins 1, A, and B (where A < B), the greedy approach would first use as many B coins as possible, then A coins, and finally 1 coins.

2. **Key Insight**: The greedy algorithm fails when there exists a smaller number of coins that can be formed by using a combination of smaller denominations instead of the largest. This typically happens when the next multiple of A after B is smaller than the sum of B and the remainder when B is divided by A.

3. **Mathematical Formulation**:
   - If B is a multiple of A, the greedy algorithm is always optimal, so we return -1.
   - If B is not a multiple of A, we check if the smallest multiple of A greater than B (denoted as (m+1)*A, where m is B//A) is a better solution than using B and some smaller coins. This is determined by checking if the remainder adjustment (A - (B % A)) is greater than m.

### Solution Code
```python
A, B = map(int, input().split())

if B % A == 0:
    print(-1)
else:
    c = B % A
    m = B // A
    if (A - c) > m:
        print((m + 1) * A)
    else:
        print(-1)
```

### Explanation
1. **Check Divisibility**: If B is divisible by A, the greedy algorithm will always work, so we print -1.
2. **Calculate Remainder and Quotient**: Compute the remainder (c) when B is divided by A and the quotient (m).
3. **Check Condition**: Determine if adjusting the remainder (A - c) is greater than the quotient (m). If true, the smallest non-optimal amount is (m + 1) * A. Otherwise, print -1.

This approach efficiently determines the result using simple arithmetic checks, ensuring optimal performance even for large values of A and B.
