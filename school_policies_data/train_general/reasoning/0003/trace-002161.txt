To solve this problem, we need to sort a list of restaurants based on specific criteria: first by the lexicographical order of their city names, and then by their scores in descending order if they are in the same city. The goal is to output the identification numbers of the restaurants in this sorted order.

### Approach
1. **Input Reading**: Read the number of restaurants and their respective details (city name, score, and identification number).
2. **Data Storage**: Store each restaurant's details as a tuple containing the city name, score, and identification number.
3. **Sorting**: Sort the list of restaurants using a custom key. The primary key is the city name in lexicographical order, and the secondary key is the negative of the score (to sort scores in descending order).
4. **Output**: Print the identification numbers of the sorted restaurants.

### Solution Code
```python
def main():
    n = int(input())
    data = []
    for i in range(n):
        s, p = input().split()
        data.append((s, int(p), i + 1))
    
    data.sort(key=lambda x: (x[0], -x[1]))
    
    for item in data:
        print(item[2])

main()
```

### Explanation
1. **Reading Input**: The input is read using `input()`, where the first line gives the number of restaurants, `n`. Each subsequent line contains the city name and score of a restaurant.
2. **Storing Data**: Each restaurant's details are stored as a tuple `(city, score, id)`, where `id` is the 1-based index of the restaurant as read from the input.
3. **Sorting**: The list of tuples is sorted using `sort()` with a custom key. The key is a lambda function that returns a tuple `(city, -score)`. This ensures that sorting is done first by city name lexicographically and then by score in descending order.
4. **Output**: After sorting, the identification numbers (third element of each tuple) are printed in the sorted order.

This approach efficiently handles the constraints and ensures the correct order of restaurants as required. The time complexity is dominated by the sorting step, which is \(O(n \log n)\), where \(n\) is the number of restaurants. This is efficient given the problem constraints.
