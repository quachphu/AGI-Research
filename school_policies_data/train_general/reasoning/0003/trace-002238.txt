To solve this problem, we need to determine if all the bills Polycarp has collected can fit into a wallet of given dimensions after each query. The solution must efficiently handle up to 500,000 queries, making it crucial to optimize the checking process.

### Approach
1. **Understanding Bill Fit**: Each bill can fit into a wallet if, after possible rotation, the bill's dimensions are less than or equal to the wallet's dimensions. This can be rephrased by considering the maximum and minimum dimensions of both the bills and the wallet.
2. **Key Observations**:
   - For a bill with dimensions `x` and `y`, we need to track the maximum of `max(x, y)` across all bills (let's call this `max_a`).
   - Similarly, we need to track the maximum of `min(x, y)` across all bills (let's call this `max_b`).
3. **Check Query Logic**: For each check query, determine the maximum and minimum dimensions of the wallet. If `max_a` is less than or equal to the maximum wallet dimension and `max_b` is less than or equal to the minimum wallet dimension, all bills fit.

### Solution Code
```python
import sys

def main():
    input = sys.stdin.read().split()
    ptr = 0
    n = int(input[ptr])
    ptr += 1
    max_a = 0
    max_b = 0
    res = []
    for _ in range(n):
        cmd = input[ptr]
        if cmd == '+':
            x = int(input[ptr + 1])
            y = int(input[ptr + 2])
            ptr += 3
            a = max(x, y)
            b = min(x, y)
            if a > max_a:
                max_a = a
            if b > max_b:
                max_b = b
        else:
            h = int(input[ptr + 1])
            w = int(input[ptr + 2])
            ptr += 3
            H = max(h, w)
            W = min(h, w)
            if max_a <= H and max_b <= W:
                res.append("YES")
            else:
                res.append("NO")
    print('\n'.join(res))

if __name__ == "__main__":
    main()
```

### Explanation
- **Reading Input Efficiently**: The input is read all at once and split into a list for efficient processing.
- **Tracking Maximums**: For each bill added, we update `max_a` (the maximum of the larger dimensions of all bills) and `max_b` (the maximum of the smaller dimensions of all bills).
- **Processing Check Queries**: For each check query, we compute the maximum (`H`) and minimum (`W`) dimensions of the wallet. If both `max_a` and `max_b` are within these dimensions, the answer is "YES"; otherwise, it's "NO".

This approach ensures each query is processed in constant time, making the solution efficient and scalable for large inputs.
