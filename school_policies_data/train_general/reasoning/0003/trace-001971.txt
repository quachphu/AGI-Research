To solve this problem, we need to generate the nth number in a series composed exclusively of the digits 3 and 4. The series starts with 3, 4, 33, 34, 43, 44, 333, and so on. The challenge is to determine the nth number efficiently by leveraging a pattern similar to binary numbers but with 3 and 4 instead of 0 and 1.

### Approach
1. **Identify the Number of Digits (m):** The numbers in the series are grouped by their digit lengths. Each group with m digits contains 2^m numbers. The starting index of each group can be determined using the formula 2^(m+1) - 2. We need to find the smallest m such that the starting index of the m-digit group is greater than or equal to n.

2. **Determine the Position within the Group:** Once we know the digit length m, we calculate the position within this group using the formula `index = n - (2^m - 2) - 1`.

3. **Convert to Binary and Replace Digits:** Convert the index to a binary string, pad it with leading zeros to ensure it has m digits, then replace each 0 with 3 and each 1 with 4 to form the final number.

### Solution Code
```python
n = int(input())

m = 1
while (2 ** (m + 1) - 2) < n:
    m += 1

index = n - (2 ** m - 2) - 1
binary_str = bin(index)[2:].zfill(m)
result = binary_str.replace('0', '3').replace('1', '4')

print(result)
```

### Explanation
1. **Finding the Digit Length (m):** We start with m=1 and incrementally check if the starting index of the next group (2^(m+1) - 2) is less than n. This loop continues until we find the correct m where the group contains the nth number.

2. **Calculating the Index:** The index within the group is computed by adjusting n to the start of the current group. This index is then converted to a binary string.

3. **Generating the Result:** The binary string is padded to ensure it has m digits. Each binary digit is then replaced: 0 becomes 3 and 1 becomes 4, forming the desired number in the series.

This approach efficiently narrows down the group and position, then uses binary conversion and substitution to generate the result, ensuring optimal performance even for the upper constraint of n=100.
