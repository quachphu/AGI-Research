To solve this problem, we need to split athletes into two teams such that the difference between the strongest athlete in the first team and the weakest athlete in the second team is minimized. The optimal solution involves sorting the strengths of the athletes and finding the minimum difference between consecutive elements in the sorted list.

### Approach
1. **Sort the Strengths**: By sorting the list of strengths, we can easily check the minimum difference between consecutive elements. This is because the smallest difference between any two elements in a sorted list will always be between consecutive elements.
2. **Compute Consecutive Differences**: After sorting, iterate through the list and compute the differences between each pair of consecutive elements. The smallest of these differences is the answer for that test case.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    idx = 0
    t = int(input[idx])
    idx += 1
    for _ in range(t):
        n = int(input[idx])
        idx += 1
        s = list(map(int, input[idx:idx + n]))
        idx += n
        s.sort()
        min_diff = float('inf')
        for i in range(n - 1):
            diff = s[i + 1] - s[i]
            if diff < min_diff:
                min_diff = diff
        print(min_diff)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given multiple test cases. The input is split into a list of strings for easy processing.
2. **Sorting**: Each list of strengths is sorted to bring the closest values next to each other.
3. **Finding Minimum Difference**: By iterating through the sorted list and computing the difference between each consecutive pair, we keep track of the smallest difference encountered. This value is printed as the result for each test case.

This approach ensures that we efficiently determine the optimal split using sorting and a single linear pass through the list, resulting in a time complexity of O(n log n) per test case due to the sorting step. This is efficient and handles the problem constraints effectively.
