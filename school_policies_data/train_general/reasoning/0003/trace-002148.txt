To solve this problem, we need to determine the final positions of dancers on a stage after they start moving and potentially collide. The key insight is that collisions between vertical and horizontal dancers can be efficiently modeled by grouping dancers based on a specific parameter and then permuting their destinations within each group.

### Approach
1. **Group Dancers by Parameter**: Each vertical dancer (moving upwards) and horizontal dancer (moving rightwards) is grouped based on a computed parameter `s`. For vertical dancers, `s = xi - ti`, and for horizontal dancers, `s = yi - ti`.
2. **Sort and Merge Destinations**: Within each group, vertical dancers are sorted by their x-coordinate, and horizontal dancers are sorted by their y-coordinate in descending order. The destinations of these dancers are then merged into a single list.
3. **Rotate Destinations**: The merged list of destinations is rotated to the left by the number of horizontal dancers in the group. This rotation effectively swaps the destinations of the dancers to account for collisions.
4. **Assign Final Positions**: The rotated destinations are assigned back to the dancers, ensuring that vertical and horizontal dancers receive their new positions based on the rotation.

### Solution Code
```python
import sys
from collections import defaultdict

def main():
    n, w, h = map(int, sys.stdin.readline().split())
    groups = defaultdict(lambda: {'vertical': [], 'horizontal': []})
    dancers = []

    for i in range(n):
        gi, pi, ti = map(int, sys.stdin.readline().split())
        dancers.append((gi, pi, ti, i))
        if gi == 1:
            s = pi - ti
            groups[s]['vertical'].append((gi, pi, ti, i))
        else:
            s = pi - ti
            groups[s]['horizontal'].append((gi, pi, ti, i))

    final_positions = [None] * n

    for s_key in groups:
        group = groups[s_key]
        verticals = group['vertical']
        horizontals = group['horizontal']
        m = len(verticals)
        n_h = len(horizontals)
        if m == 0 and n_h == 0:
            continue

        sorted_vert = sorted(verticals, key=lambda x: x[1])
        sorted_hori = sorted(horizontals, key=lambda x: -x[1])

        merged = []
        for v in sorted_vert:
            merged.append((v[1], h))
        for hh in sorted_hori:
            merged.append((w, hh[1]))

        rotated = merged[n_h:] + merged[:n_h]

        for i in range(len(sorted_vert)):
            gi, pi, ti, idx = sorted_vert[i]
            final_positions[idx] = rotated[i]

        for j in range(len(sorted_hori)):
            gi, pi, ti, idx = sorted_hori[j]
            final_positions[idx] = rotated[m + j]

    for pos in final_positions:
        print(pos[0], pos[1])

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read and parsed into a list of dancers, each with their group, position, and waiting time.
2. **Grouping by Parameter**: Dancers are grouped into vertical and horizontal lists based on their computed parameter `s`.
3. **Sorting and Merging**: Vertical dancers are sorted by their x-coordinate, and horizontal dancers by their y-coordinate in descending order. Their destinations are merged into a single list.
4. **Rotating Destinations**: The merged list is rotated to the left by the number of horizontal dancers in the group, effectively swapping their destinations.
5. **Assigning Final Positions**: The rotated destinations are assigned back to the dancers, ensuring the correct final positions based on collisions.

This approach efficiently handles collisions by leveraging grouping and permutation of destinations, ensuring optimal performance even for large inputs.
