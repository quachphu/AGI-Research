### Approach
The solution involves using binary search to find the maximum number of teams that can be formed. The key steps are:

1. **Upper Bound Calculation**: The maximum possible number of teams is limited by the total number of participants divided by 3, as each team requires 3 members. This gives us an upper bound of \((n + m) // 3\).

2. **Binary Search**: We perform a binary search on the number of teams (t) to check if it is feasible to form t teams. For a given t, we need to check if there exists a valid distribution of team types (1 experienced + 2 newbies and 2 experienced + 1 newbie) that uses up to t teams.

3. **Feasibility Check**: For each midpoint value (t) during the binary search, we check if there exists a valid number of teams of each type such that the constraints are satisfied. This involves ensuring that the number of experienced participants and newbies used does not exceed the available numbers.

### Solution Code
```python
def max_teams():
    import sys
    n, m = map(int, sys.stdin.readline().split())
    low = 0
    high = (n + m) // 3
    ans = 0
    while low <= high:
        mid = (low + high) // 2
        # Calculate the possible range for b (number of type B teams)
        lower_b = max(2 * mid - m, 0)
        upper_b = min(n - mid, mid)
        if lower_b <= upper_b:
            ans = mid
            low = mid + 1
        else:
            high = mid - 1
    print(ans)

max_teams()
```

### Explanation
1. **Reading Input**: The input values for the number of experienced participants (n) and newbies (m) are read from standard input.

2. **Binary Search Setup**: The search range for the number of teams (t) is initialized from 0 to \((n + m) // 3\).

3. **Midpoint Check**: For each midpoint value (mid), we determine the feasible range for the number of teams of type B (2 experienced + 1 newbie). The lower bound for type B teams is determined by the requirement that newbies must not be overused, and the upper bound is determined by the availability of experienced participants.

4. **Adjusting Search Range**: If the midpoint value is feasible, we update the answer and adjust the search range to explore higher values. If not, we adjust the range to explore lower values.

This approach efficiently narrows down the possible number of teams using binary search, ensuring an optimal solution with a time complexity of \(O(\log(n + m))\), which is efficient given the problem constraints.
