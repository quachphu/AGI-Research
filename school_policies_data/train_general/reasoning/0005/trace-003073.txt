To solve this problem, we need to generate a different permutation of a given array such that the fingerprint of the new permutation matches the fingerprint of the original permutation. The fingerprint is defined as the sorted array of sums of adjacent elements in the permutation. 

### Approach
The key insight to solve this problem is to recognize that reversing the given permutation will always yield a valid solution. This is because the sums of adjacent elements in the reversed permutation are the same as those in the original permutation, but in reverse order. Since the fingerprint is the sorted list of these sums, reversing the permutation preserves the fingerprint while ensuring the new permutation is different from the original.

### Solution Code
```python
import sys

t = int(sys.stdin.readline())
for _ in range(t):
    n = int(sys.stdin.readline())
    p = list(map(int, sys.stdin.readline().split()))
    p_reversed = p[::-1]
    print(' '.join(map(str, p_reversed)))
```

### Explanation
1. **Reading Input:** The code reads the number of test cases and processes each test case individually.
2. **Reversing the Permutation:** For each test case, the given permutation is reversed. This reversal ensures that the new permutation is different from the original while maintaining the same fingerprint.
3. **Output the Result:** The reversed permutation is printed as the result for each test case.

This approach works efficiently because reversing an array is an O(n) operation, which is optimal for the given constraints (n ≤ 100 and up to 668 test cases). The reversed permutation is guaranteed to be different from the original, and its fingerprint will match the original's fingerprint when sorted.
