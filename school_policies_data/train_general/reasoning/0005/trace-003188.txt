To solve this problem, we need to efficiently answer two types of queries on an array of stone costs. The first type of query asks for the sum of a subarray, while the second type asks for the sum of a subarray of the sorted version of the original array. Given the constraints, a brute force approach would be too slow, so we use prefix sums to allow each query to be answered in constant time.

### Approach
1. **Prefix Sum Arrays**: We precompute two prefix sum arrays. One for the original array and another for the sorted version of the array. This allows us to quickly compute the sum of any subarray in constant time.
2. **Handling Queries**: For each query, depending on its type, we use the corresponding prefix sum array to compute the sum of the specified subarray.

### Solution Code
```python
import sys

def main():
    n = int(sys.stdin.readline())
    v = list(map(int, sys.stdin.readline().split()))
    sorted_v = sorted(v)
    
    # Compute prefix sums for the original array
    prefix_original = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix_original[i] = prefix_original[i - 1] + v[i - 1]
    
    # Compute prefix sums for the sorted array
    prefix_sorted = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix_sorted[i] = prefix_sorted[i - 1] + sorted_v[i - 1]
    
    m = int(sys.stdin.readline())
    for _ in range(m):
        t, l, r = map(int, sys.stdin.readline().split())
        if t == 1:
            res = prefix_original[r] - prefix_original[l - 1]
        else:
            res = prefix_sorted[r] - prefix_sorted[l - 1]
        print(res)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read using `sys.stdin.readline()` for efficiency, especially given the large possible input size.
2. **Prefix Sum Calculation**: We construct two prefix sum arrays:
   - `prefix_original` for the original array, where `prefix_original[i]` is the sum of the first `i` elements of the original array.
   - `prefix_sorted` for the sorted array, where `prefix_sorted[i]` is the sum of the first `i` elements of the sorted array.
3. **Query Processing**: For each query, depending on the type, we compute the sum of the subarray using the appropriate prefix sum array. The sum from index `l` to `r` is computed as `prefix[r] - prefix[l-1]`, which allows each query to be answered in O(1) time.

This approach ensures that both the preprocessing and query handling are efficient, making the solution suitable for large input sizes.
