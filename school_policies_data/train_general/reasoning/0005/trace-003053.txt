To solve this problem, we need to determine the minimum amount of money Takahashi needs to buy exactly M cans of energy drinks from various stores, each offering a certain number of cans at a specific price. The optimal strategy is to prioritize purchasing from the cheapest stores first.

### Approach
1. **Input Reading**: Read the number of stores (N) and the required cans (M).
2. **Store Data Collection**: Collect each store's price per can (A_i) and the maximum cans available (B_i).
3. **Sorting**: Sort the stores based on the price per can in ascending order to prioritize cheaper purchases.
4. **Greedy Purchase**: Iterate through the sorted list of stores, buying as many cans as possible from each store until the required M cans are met. This approach ensures that we minimize the total cost by always using the cheapest available options first.

### Solution Code
```python
import sys

def main():
    n, m = map(int, sys.stdin.readline().split())
    stores = []
    for _ in range(n):
        a, b = map(int, sys.stdin.readline().split())
        stores.append((a, b))
    
    stores.sort()
    total = 0
    remaining = m
    for a, b in stores:
        if remaining <= 0:
            break
        take = min(b, remaining)
        total += take * a
        remaining -= take
    print(total)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read using `sys.stdin.readline` for efficiency, especially given the constraints where N can be up to 100,000.
2. **Sorting Stores**: The stores are sorted by their price per can (A_i) in ascending order. This ensures that we always consider the cheapest available options first.
3. **Greedy Purchase**: For each store in the sorted list, we buy as many cans as possible (up to the store's limit or the remaining required cans). This continues until we have met the required M cans. The total cost is accumulated and printed once all necessary purchases are made.

This approach efficiently minimizes the total cost by leveraging sorting and a greedy algorithm, ensuring optimal performance even for the upper constraint limits. The time complexity is dominated by the sorting step, which is O(N log N), making it suitable for large inputs.
