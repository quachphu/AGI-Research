To solve this problem, we need to count the number of ways to paint the vertices of a tree such that no two adjacent vertices are both black. The solution must be computed modulo \(10^9 + 7\).

### Approach
1. **Tree Structure**: The problem involves a tree, which is an acyclic connected graph. This allows us to use dynamic programming (DP) with a post-order traversal to efficiently compute the number of valid colorings for each subtree.
2. **Dynamic Programming (DP) States**:
   - `white[u]`: The number of ways to paint the subtree rooted at node `u` if `u` is painted white.
   - `black[u]`: The number of ways to paint the subtree rooted at node `u` if `u` is painted black.
3. **Transitions**:
   - If node `u` is white, its children can be either white or black. Thus, `white[u]` is the product of the sum of `white[v]` and `black[v]` for all children `v`.
   - If node `u` is black, all its children must be white. Thus, `black[u]` is the product of `white[v]` for all children `v`.
4. **Post-order Traversal**: Using an iterative approach with a stack to avoid recursion limits, we process each node after all its children have been processed. This ensures that we can compute the DP values correctly.

        edges[x].append(y)
        edges[y].append(x)
    
    white = [1] * (n + 1)
    black = [1] * (n + 1)
    stack = [(1, -1, False)]  # (node, parent, visited)
    
    while stack:
        u, parent, visited = stack.pop()
        if not visited:
            stack.append((u, parent, True))
            for v in reversed(edges[u]):
                if v != parent:
                    stack.append((v, u, False))
        else:
            for v in edges[u]:
                if v != parent:
                    white[u] = white[u] * (white[v] + black[v]) % MOD
                    black[u] = black[u] * white[v] % MOD
    
    print((white[1] + black[1]) % MOD)

    main()

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially for large inputs. The adjacency list `edges` is built to represent the tree.
2. **Base Case Handling**: If there is only one node, the result is directly 2 (both possible colorings).
3. **Iterative Post-order Traversal**: Using a stack, we simulate the post-order traversal. Nodes are processed twice: first to push their children onto the stack, and second to compute their DP values after their children have been processed.
4. **Dynamic Programming Updates**: For each node processed in post-order, we update `white[u]` and `black[u]` based on the DP values of its children, ensuring all operations are modulo \(10^9 + 7\).

This approach efficiently computes the number of valid colorings in \(O(N)\) time and space, making it suitable for large trees up to \(10^5\) nodes.
