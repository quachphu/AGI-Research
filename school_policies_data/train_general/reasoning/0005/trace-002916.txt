To solve this problem, we need to determine the minimum number of Nimbdas Bhallaladeva has to pay to loot all the houses in Maahishmati, given different values of K. The strategy involves paying for a house and then looting up to K other houses for free in each step. The goal is to minimize the total cost by strategically choosing which houses to pay for.

### Approach
1. **Sort the Houses**: First, sort the list of houses based on the number of gold plates in ascending order. This allows us to consider the smallest values first, which minimizes the total cost when we have to pay.
2. **Prefix Sum Array**: Compute a prefix sum array of the sorted list. This array helps in quickly calculating the sum of the first m smallest elements.
3. **Calculate Minimum Cost for Each Query**: For each query value K, determine the number of paid steps required. This is done by computing the ceiling of N divided by (K + 1), which gives the number of paid houses needed. Using the prefix sum array, we can then directly get the sum of the smallest m elements, where m is the number of paid steps.

### Solution Code
```python
n = int(input())
a = list(map(int, input().split()))
a.sort()
prefix = [0] * (n + 1)
for i in range(n):
    prefix[i+1] = prefix[i] + a[i]
q = int(input())
for _ in range(q):
    k = int(input())
    m = (n + k) // (k + 1)
    print(prefix[m])
```

### Explanation
1. **Sorting the Houses**: By sorting the houses in ascending order, we ensure that when we select the smallest elements to pay for, we minimize the total cost.
2. **Prefix Sum Array**: The prefix sum array allows efficient calculation of the sum of the first m elements in constant time. This is crucial given the constraints where both N and Q can be up to 100,000.
3. **Handling Each Query**: For each query K, the number of paid steps (m) is calculated using the formula `(n + k) // (k + 1)`, which effectively computes the ceiling of N divided by (K + 1). This ensures that each paid step allows looting up to K houses for free, thus minimizing the number of paid steps and the total cost.

This approach efficiently computes the minimum cost for each query in O(1) time after an initial O(N log N) sorting step, making it suitable for large input sizes.
