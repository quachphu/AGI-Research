To solve this problem, we need to efficiently handle two types of operations on an array of holes: updating the power of a hole and simulating the trajectory of a ball thrown into a hole. The challenge lies in optimizing these operations to handle large input sizes efficiently.

### Approach
The solution involves using a square root decomposition technique to balance the trade-off between update and query operations. This technique involves dividing the array into blocks of size approximately √N. Each block is preprocessed to store information about jumps within the block, allowing us to answer queries and perform updates in O(√N) time.

1. **Preprocessing**: For each block, compute the number of steps required to exit the block, the next hole the ball will jump to after exiting the block, and the last hole visited within the block.
2. **Updates**: When the power of a hole is updated, recompute the preprocessing steps for the entire block containing that hole.
3. **Queries**: Simulate the ball's path by jumping through blocks using the precomputed information, accumulating the total steps and tracking the last hole visited before exiting the array.

### Solution Code
```python
import sys
import math

def main():
    input = sys.stdin.read().split()
    ptr = 0
    N = int(input[ptr])
    ptr += 1
    M = int(input[ptr])
    ptr += 1
    a = list(map(int, input[ptr:ptr+N]))
    ptr += N
    a = [0] + a  # 1-based indexing

    B = int(math.sqrt(N)) 
    # To handle cases where B might be too small, adjust if necessary
    if B * B < N:
        B += 1

    steps = [0] * (N + 2)  # steps[i]
    next_hole = [0] * (N + 2)
    last_in_block = [0] * (N + 2)

    def compute_block(block):
        start = block * B + 1
        end = (block + 1) * B
        if end > N:
            end = N
        for i in range(end, start - 1, -1):
            jump = i + a[i]
            if jump > end or jump > N:
                steps[i] = 1
                next_hole[i] = jump
                last_in_block[i] = i
            else:
                steps[i] = steps[jump] + 1
                next_hole[i] = next_hole[jump]
                last_in_block[i] = last_in_block[jump]

    # Precompute all blocks initially
    max_block = (N - 1) // B
    for block in range(max_block + 1):
        compute_block(block)

    # Process each query
    for _ in range(M):
        query = input[ptr]
        ptr += 1
        if query == '0':
            a_pos = int(input[ptr])
            ptr += 1
            b = int(input[ptr])
            ptr += 1
            a[a_pos] = b
            block = (a_pos - 1) // B
            compute_block(block)
        else:
            a_pos = int(input[ptr])
            ptr += 1
            current = a_pos
            total_steps = 0
            last = current
            while current <= N:
                total_steps += steps[current]
                last = last_in_block[current]
                current = next_hole[current]
            print(last, total_steps)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Preprocessing**: Each block is processed in reverse order to compute the steps required to exit the block, the next hole after exiting, and the last hole visited within the block. This allows efficient jumps during queries.
2. **Updates**: When updating a hole's power, only the block containing that hole needs to be reprocessed, ensuring updates are efficient.
3. **Queries**: By leveraging the precomputed block information, each query efficiently jumps through blocks, accumulating steps and tracking the last hole visited, resulting in an optimal query time.

This approach ensures both updates and queries are handled in O(√N) time, making the solution efficient for large input sizes.
