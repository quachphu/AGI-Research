To solve this problem, we need to find the minimum possible value of the sum of the digits of two positive integers A and B such that their sum equals a given integer N. The approach involves iterating through possible values of A and calculating the corresponding B to determine the minimum sum of their digits.

### Approach
1. **Problem Analysis**: The goal is to split the integer N into two parts A and B such that the sum of their individual digits is minimized. The key insight is that the sum of the digits of A and B can be minimized by checking each possible pair (A, B) where A ranges from 1 to N//2. This reduces the number of iterations by half since A and B are interchangeable.

2. **Sum of Digits Calculation**: For each number, the sum of its digits can be efficiently calculated using modulo and division operations to extract each digit and sum them.

3. **Iterate and Check**: For each possible value of A from 1 to N//2, compute B as N - A, then calculate the sum of the digits of both A and B. Track the minimum sum encountered during the iteration.

### Solution Code
```python
def sum_digits(n):
    s = 0
    while n > 0:
        s += n % 10
        n = n // 10
    return s

n = int(input())
min_sum = float('inf')
for a in range(1, n // 2 + 1):
    b = n - a
    current_sum = sum_digits(a) + sum_digits(b)
    if current_sum < min_sum:
        min_sum = current_sum
print(min_sum)
```

### Explanation
1. **sum_digits Function**: This helper function calculates the sum of the digits of a given number by repeatedly extracting the last digit using modulo 10 and then removing the last digit using integer division by 10.

2. **Main Logic**: The main part of the code reads the input value N and initializes `min_sum` to a large value. It then iterates through each possible value of A from 1 to N//2. For each A, it calculates B as N - A and determines the sum of the digits of both A and B. The minimum sum encountered during these iterations is tracked and printed as the result.

This approach ensures that we efficiently explore all possible splits of N into A and B, while keeping the computational complexity manageable even for the upper constraint of N being 100,000.
