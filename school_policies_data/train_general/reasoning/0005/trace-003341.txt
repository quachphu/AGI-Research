To solve this problem, we need to determine the largest possible xor-sum that Grisha can obtain by selecting up to k candies from a bag containing candies labeled from 1 to n. The key insight here is that the xor-sum can be maximized by leveraging the properties of bitwise operations.

### Approach
1. **Understanding XOR Properties**: The xor-sum of a set of numbers can be maximized by ensuring that each bit in the result is set to 1 if possible. This involves finding the highest possible number where all bits up to the highest bit of n are set.
2. **Bit Length Insight**: The highest bit set in the number n can be determined using the `bit_length()` method in Python, which gives the number of bits required to represent n in binary. The maximum xor-sum is then derived from this bit length.
3. **Special Case Handling**: If k is 1, the maximum xor-sum is simply n itself since Grisha can only take one candy. For k ≥ 2, the maximum xor-sum is determined by setting all bits up to the highest bit of n, which is calculated as \(2^{\text{bit_length}} - 1\).

### Solution Code
```python
n, k = map(int, input().split())
if k == 1:
    print(n)
else:
    print((1 << n.bit_length()) - 1)
```

### Explanation
1. **Reading Input**: The input values n and k are read from standard input.
2. **Handling k = 1**: If Grisha can take only one candy, the maximum xor-sum is the value of the candy itself, which is n.
3. **Calculating Maximum XOR for k ≥ 2**: 
   - The `bit_length()` method determines the number of bits required to represent n. For example, if n is 4 (binary 100), `bit_length()` returns 3.
   - The maximum xor-sum is computed as \( (1 << \text{bit_length}) - 1 \), which effectively sets all bits up to the highest bit of n. For n = 4, this results in \( (1 << 3) - 1 = 8 - 1 = 7 \).

This approach efficiently computes the maximum xor-sum using bitwise operations, ensuring optimal performance even for very large values of n (up to \(10^{18}\)).
