To solve this problem, we need to compute the first K digits after the decimal point of the fraction 103993/33102, truncated (not rounded) to K digits. For K=0, we simply output "3", otherwise, we output "3." followed by the first K digits after the decimal point.

### Approach
1. **Precomputation**: Since the problem constraints allow K up to 1,000,000 and the sum of K over all test cases does not exceed 1,000,000, we precompute the first 1,000,000 digits of the fraction 103993/33102 once. This avoids redundant calculations for each test case.
2. **Long Division**: We use manual long division to compute each digit after the decimal point. This involves repeatedly multiplying the remainder by 10, dividing by the denominator to get the next digit, and updating the remainder.
3. **Efficient Query Handling**: After precomputing the digits, each test case can be answered in O(1) time by slicing the precomputed string to the required length.

### Solution Code
```python
numerator = 103993
denominator = 33102

# Precompute the decimal digits after the decimal point up to 1e6 digits
max_k = 10**6
remainder = numerator % denominator
digits = []
for _ in range(max_k):
    remainder *= 10
    digit = remainder // denominator
    digits.append(str(digit))
    remainder = remainder % denominator
digits_str = ''.join(digits)

import sys

def main():
    t = int(sys.stdin.readline())
    for _ in range(t):
        k = int(sys.stdin.readline())
        if k == 0:
            print(3)
        else:
            # Using sys.stdout.write for potentially faster output
            sys.stdout.write('3.')
            sys.stdout.write(digits_str[:k])
            sys.stdout.write('\n')

if __name__ == "__main__":
    main()
```

### Explanation
1. **Precomputation**: We start by calculating the integer part of the fraction (which is 3) and then compute the digits after the decimal point using long division. Each digit is determined by multiplying the remainder by 10, dividing by the denominator, and updating the remainder. This process is repeated up to 1,000,000 times to generate all required digits.
2. **Handling Queries**: For each test case, we read the value of K. If K is 0, we output "3". Otherwise, we output "3." followed by the first K digits from our precomputed string. This approach ensures that each query is handled efficiently after the initial precomputation.

This method ensures that we handle up to the maximum constraints efficiently, leveraging precomputation to minimize repeated work and using efficient string operations to quickly generate the required output for each test case.
