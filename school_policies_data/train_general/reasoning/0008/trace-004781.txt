To solve this problem, we need to determine if it's possible to color the border cells of an n x n grid such that the top row, rightmost column, bottom row, and leftmost column each have a specified number of black cells. The key challenge is to account for the overlapping corners, which contribute to two counts each.

### Approach
1. **Problem Analysis**: The problem requires checking if the given counts of black cells (U, R, D, L) can be satisfied considering the corners of the grid. Each corner cell belongs to two rows or columns, so we need to check all possible combinations of these corners being black or white.
2. **Corner Combinations**: There are four corners (top-left, top-right, bottom-left, bottom-right), each of which can be either black (1) or white (0). This gives us 16 possible combinations to check.
3. **Check Validity**: For each combination of corners, we calculate the remaining number of black cells needed for each row and column after accounting for the corners. These remaining cells must be non-negative and not exceed the number of non-corner cells in their respective row or column.

### Solution Code
```python
import sys
from itertools import product

def check_puzzle():
    t = int(sys.stdin.readline())
    for _ in range(t):
        n, U, R, D, L = map(int, sys.stdin.readline().split())
        possible = False
        max_avail = n - 2
        # Iterate all possible corner combinations (tl, tr, bl, br)
        for corners in product([0, 1], repeat=4):
            tl, tr, bl, br = corners
            # Calculate remaining for each direction
            u_rem = U - (tl + tr)
            r_rem = R - (tr + br)
            d_rem = D - (bl + br)
            l_rem = L - (tl + bl)
            # Check if all remainings are within valid range
            if all(0 <= rem <= max_avail for rem in [u_rem, r_rem, d_rem, l_rem]):
                possible = True
                break
        print("YES" if possible else "NO")

check_puzzle()
```

### Explanation
1. **Reading Input**: The input is read from standard input. The first line gives the number of test cases.
2. **Iterating Over Test Cases**: For each test case, we read the values of n, U, R, D, and L.
3. **Generating Corner Combinations**: Using `itertools.product`, we generate all 16 possible combinations of the four corners being black or white.
4. **Checking Validity**: For each combination, we calculate the remaining cells needed for each row and column after accounting for the corners. If all remainders are within the valid range (0 to n-2), the combination is valid.
5. **Output Result**: If any valid combination is found, we print "YES"; otherwise, we print "NO".

This approach efficiently checks all possible configurations of corners and ensures that the remaining cells can be feasibly colored to meet the given constraints.
