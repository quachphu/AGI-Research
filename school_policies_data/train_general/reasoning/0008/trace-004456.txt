To solve this problem, we need to efficiently count the number of inversions in a given sequence. An inversion is a pair of indices (i, j) such that i < j and a[i] > a[j]. Given the constraints, a direct approach using Bubble Sort would be too slow, so we use a more efficient method involving a Fenwick Tree (Binary Indexed Tree) with coordinate compression.

### Approach
1. **Coordinate Compression**: Since the values of the elements can be very large, we first compress these values into ranks based on their sorted order. This allows us to use a Fenwick Tree efficiently.
2. **Fenwick Tree (BIT)**: We use a Fenwick Tree to keep track of the count of elements processed so far. By iterating through the array from right to left, we can query the number of elements smaller than the current element that have already been processed, which gives the number of inversions contributed by the current element.

### Solution Code
```python
class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0] * (self.n + 1)
    
    def update(self, idx, delta=1):
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & -idx
    
    def query(self, idx):
        res = 0
        while idx > 0:
            res += self.tree[idx]
            idx -= idx & -idx
        return res

n = int(input())
A = list(map(int, input().split()))
sorted_A = sorted(A)
rank = {v: i+1 for i, v in enumerate(sorted_A)}

ft = FenwickTree(n)
count = 0

for num in reversed(A):
    r = rank[num]
    count += ft.query(r - 1)
    ft.update(r)

print(count)
```

### Explanation
1. **Coordinate Compression**: We first sort the array to create a mapping from each element to its rank. This allows us to handle large values efficiently by converting them into indices that fit within the range of the Fenwick Tree.
2. **Fenwick Tree Operations**: 
   - **Update**: For each element processed from right to left, we update the Fenwick Tree to include the rank of the current element.
   - **Query**: For each element, we query the Fenwick Tree to find how many elements with a smaller rank (i.e., smaller values) have already been processed. This count is added to the total inversion count.
3. **Efficiency**: Both the coordinate compression and the Fenwick Tree operations (update and query) run in O(n log n) time, making the solution efficient enough for large input sizes up to 200,000 elements.
