To solve this problem, we need to determine the town where King Takahashi will end up after using teleporters exactly K times starting from Town 1. Given the constraints, a brute force approach is infeasible, so we need an optimized solution using cycle detection in the sequence of towns visited.

### Approach
1. **Cycle Detection**: The sequence of towns visited will eventually form a cycle. We need to detect this cycle to avoid redundant calculations.
2. **Path Tracking**: Track the sequence of towns visited until a cycle is detected. This path helps in identifying the start of the cycle and its length.
3. **Cycle Handling**: Once a cycle is detected, determine the number of steps before the cycle starts (prefix) and the length of the cycle. Using these values, compute the result efficiently using modular arithmetic if K exceeds the length of the prefix.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    N = int(input[0])
    K = int(input[1])
    A = list(map(int, input[2:2+N]))
    
    path = []
    visited = dict()
    current = 1
    
    while current not in visited:
        visited[current] = len(path)
        path.append(current)
        current = A[current - 1]  # Convert to 0-based index for the list
    
    cycle_start = visited[current]
    cycle_length = len(path) - cycle_start
    
    if K < len(path):
        print(path[K])
    else:
        remainder = (K - cycle_start) % cycle_length
        print(path[cycle_start + remainder])
    
if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read and parsed into the number of towns (N), the number of teleportations (K), and the list of teleportation targets (A).
2. **Path Tracking**: We simulate the teleportations starting from Town 1, recording each visited town in a list (`path`) and using a dictionary (`visited`) to track the step at which each town was first visited.
3. **Cycle Detection**: When a town is revisited, we determine the start of the cycle (`cycle_start`) and its length (`cycle_length`).
4. **Result Calculation**: If K is within the initial non-cyclic part (prefix), we directly return the result from the path. If K exceeds the prefix length, we compute the position within the cycle using modular arithmetic to avoid unnecessary iterations.

This approach efficiently handles large values of K by leveraging cycle detection and modular arithmetic, ensuring the solution runs in O(N) time complexity.
