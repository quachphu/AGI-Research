The challenge lies in handling up to 100,000 queries efficiently, which requires a precomputation strategy to avoid excessive repeated calculations.

### Approach
1. **Precomputation for Efficient Query Handling**:
   - For each possible step value \( K \) (from 1 to 10), precompute the positions and prefix sums of elements that would be included in the sum for each possible starting position modulo \( K \).
   - This involves creating lists of positions and corresponding elements for each combination of \( K \) and modulus value \( m \) (from 0 to \( K-1 \)). These lists are then used to compute prefix sums, which allow for quick range sum calculations.

2. **Binary Search for Range Queries**:
   - For each query, determine the relevant precomputed lists based on the given \( K \) and the starting position modulo \( K \).
   - Use binary search to quickly find the range of indices within the precomputed positions that fall within the query's specified range. This allows us to compute the sum using the precomputed prefix sums in logarithmic time.

### Solution Code
```python
import bisect

def main():
    import sys
    input = sys.stdin.read
    data = input().split()
    idx = 0
    N = int(data[idx])
    idx += 1
    Q = int(data[idx])
    idx += 1
    
    A = list(map(int, data[idx:idx+N]))
    idx += N
    
    # Precompute for K=1 to 10
    pre = [None] * 11  # pre[K] for K from 0 to 10
    
    for K in range(1, 11):
        # Initialize for each K and m=0 to K-1
        pre[K] = [ ([], []) for _ in range(K) ]
        for pos in range(1, N+1):
            m = (pos - 1) % K
            pre[K][m][0].append(pos)
            pre[K][m][1].append(A[pos-1])
        
        # Compute prefix sums for each m in K
        for m in range(K):
            positions, elements = pre[K][m]
            prefix = [0]
            current = 0
            for e in elements:
                current += e
                prefix.append(current)
            pre[K][m] = (positions, prefix)
    
    # Process queries
    output = []
    for _ in range(Q):
        L = int(data[idx])
        idx +=1
        R = int(data[idx])
        idx +=1
        K_val = int(data[idx])
        idx +=1
        
        m = (L - 1) % K_val
        positions, prefix = pre[K_val][m]
        
        # Find left_idx: first position >= L
        left_idx = bisect.bisect_left(positions, L)
        if left_idx >= len(positions) or positions[left_idx] > R:
            output.append('0')
            continue
        
        # Find right_idx: last position <= R
        right_idx = bisect.bisect_right(positions, R) - 1
        if right_idx < left_idx:
            output.append('0')
            continue
        
        total = prefix[right_idx +1] - prefix[left_idx]
        output.append(str(total))
    
    print('\n'.join(output))

if __name__ == "__main__":
    main()
```

   - We then compute prefix sums for these lists, which allows us to quickly calculate the sum of any sublist.

2. **Query Handling**:
   - For each query, we determine the modulus \( m \) based on the starting position \( L \). Using binary search, we find the range of indices in the precomputed positions that fall within the query's range [L, R].
   - Using the precomputed prefix sums, we efficiently compute the sum of the elements in this range, ensuring each query is handled in logarithmic time relative to the number of elements involved.

This approach ensures that each query is answered in \( O(\log M) \) time, where \( M \) is the number of elements relevant to the query's \( K \) and modulus, making the solution efficient even for large input sizes.
