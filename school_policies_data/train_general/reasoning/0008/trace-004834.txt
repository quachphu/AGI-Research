To solve this problem, we need to find the starting index of k consecutive planks in a fence that have the minimal total height. The solution must efficiently handle large input sizes, up to 150,000 planks.

### Approach
The problem can be efficiently solved using the sliding window technique. This approach allows us to compute the sum of each consecutive k elements in linear time, O(n), by reusing the sum of the previous window. Here's the step-by-step approach:

1. **Initial Sum Calculation**: Compute the sum of the first k elements to initialize the sliding window.
2. **Sliding Window Technique**: Iterate through the list starting from the k-th element. For each new element, adjust the current sum by subtracting the element that is no longer in the window and adding the new element that enters the window.
3. **Track Minimum Sum**: Keep track of the minimum sum encountered and the corresponding starting index of the window.

This approach ensures that each element is processed exactly once, leading to an optimal time complexity of O(n).

### Solution Code
```python
import sys

def find_min_planks():
    n, k = map(int, sys.stdin.readline().split())
    h = list(map(int, sys.stdin.readline().split()))
    
    current_sum = sum(h[:k])
    min_sum = current_sum
    best_start = 0
    
    for i in range(k, n):
        current_sum += h[i] - h[i - k]
        if current_sum < min_sum:
            min_sum = current_sum
            best_start = i - k + 1
    
    print(best_start + 1)

find_min_planks()
```

### Explanation
1. **Reading Input**: The input values are read using `sys.stdin` for efficiency, especially with large input sizes.
2. **Initial Sum Calculation**: The sum of the first k elements is computed to initialize the sliding window.
3. **Sliding Window Adjustment**: For each subsequent element, the window is adjusted by removing the contribution of the element that is sliding out of the window and adding the contribution of the new element sliding into the window.
4. **Tracking Minimum**: The minimum sum and its corresponding starting index are updated whenever a smaller sum is found. The starting index is converted to 1-based indexing before printing.

This method ensures that we efficiently find the optimal solution with a time complexity of O(n), making it suitable for large input sizes.
