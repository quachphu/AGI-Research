### Approach
1. **Understand the Movement**: Each square has a value indicating how many steps to move clockwise. The next position is determined by `(current position + value) % N`, where `N` is the number of squares.
2. **Graph Representation**: Represent the game as a directed graph where each node (square) points to the next node based on the movement rule.
3. **Cycle Detection**: In this graph, each node has exactly one outgoing edge. The key insight is that only nodes part of a cycle can return to themselves. Thus, the problem reduces to finding all nodes in cycles.
4. **Efficient Cycle Detection**: Use a depth-first search (DFS) approach to traverse each node, tracking visited nodes and detecting cycles using a dictionary to map nodes to their positions in the traversal path.

```python
                    cycle_length = len(path) - pos[current]
                    result += cycle_length
                break
            visited[current] = True
            path.append(current)
            pos[current] = len(path) - 1
            current = next_node[current]

print(result)
```

### Explanation
1. **Reading Input**: The input consists of the number of squares `N` and the list of values on each square.
2. **Next Node Calculation**: Compute the next node for each square using `(current index + value) % N`.
3. **Cycle Detection**: For each unvisited node, traverse the graph while keeping track of the current path. If a node is revisited and found in the current path, a cycle is detected. The length of the cycle is calculated and added to the result.
4. **Result Calculation**: The total number of nodes in all detected cycles is the answer, as these nodes can return to themselves (Agari).

This approach efficiently detects cycles in O(N) time complexity, ensuring it handles the upper constraint of N = 100,000 efficiently.
