To solve this problem, we need to determine if a given number eventually becomes 1 after repeatedly squaring each of its digits and summing the results. If it does, we output "YES"; otherwise, we output "NO". 

### Approach
1. **Problem Analysis**: The problem is a variation of the "Happy Number" problem. A number is considered happy if, after repeatedly squaring its digits and summing the results, it eventually reaches 1. If it enters a cycle that does not include 1, it is not a happy number.
2. **Cycle Detection**: Numbers that do not lead to 1 will enter a known cycle. This cycle includes the numbers 4, 16, 37, 58, 89, 145, 42, 20, and 0. If any of these numbers are encountered during the process, we can immediately conclude that the number is not happy.
3. **Algorithm**:
   - For each number, repeatedly compute the sum of the squares of its digits.
   - Check if the result is 1 (happy number) or if it enters the known cycle (not a happy number).

### Solution Code
```python
def next_num(n):
    total = 0
    for c in str(n):
        total += int(c) ** 2
    return total

def is_jumping(n):
    cycle = {0, 4, 16, 37, 58, 89, 145, 42, 20}
    while True:
        if n == 1:
            return True
        if n in cycle:
            return False
        n = next_num(n)

t = int(input())
for case in range(t):
    n = int(input().strip())
    result = is_jumping(n)
    print(f"Case #{case + 1}:{'YES' if result else 'NO'}")
```

### Explanation
1. **next_num Function**: This function takes a number, squares each of its digits, and returns the sum of these squares.
2. **is_jumping Function**: This function checks if a number eventually becomes 1. It uses a set of known cycle numbers to detect non-happy numbers efficiently. If the number becomes 1, it returns "YES". If it encounters any number in the known cycle, it returns "NO".
3. **Main Loop**: Reads the number of test cases and processes each number. For each number, it uses the `is_jumping` function to determine the result and prints it in the required format.

This approach efficiently handles all possible inputs within the constraints, ensuring that we detect cycles quickly and avoid infinite loops.
