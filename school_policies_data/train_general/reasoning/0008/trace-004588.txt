To solve this problem, we need to determine the minimum number of jumps required to reach the end of an array of rocks, where each rock's value indicates the maximum jump length from that position. The solution involves a greedy algorithm that efficiently tracks the farthest reachable index at each step, ensuring the minimum jumps are calculated.

### Approach
1. **Initialization**: Track the farthest index reachable (`farthest`), the current end of the reachable indices (`current_end`), and the number of jumps (`jumps`).
2. **Iterate through the rocks**: For each rock, update the farthest index that can be reached from the current position.
3. **Check for necessary jumps**: When the current index reaches the `current_end`, increment the jump count and update `current_end` to the farthest reachable index. If the farthest index reaches or exceeds the last rock, break out of the loop early.

This approach ensures that each jump is made from the optimal position, minimizing the total number of jumps required.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    ptr = 0
    T = int(input[ptr])
    ptr += 1
    for _ in range(T):
        N = int(input[ptr])
        ptr += 1
        rockNum = list(map(int, input[ptr:ptr + N]))
        ptr += N
        if N == 1:
            print(0)
            continue
        current_end = 0
        farthest = 0
        jumps = 0
        for i in range(N - 1):
            farthest = max(farthest, i + rockNum[i])
            if i == current_end:
                jumps += 1
                current_end = farthest
                if current_end >= N - 1:
                    break
        print(jumps)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints.
2. **Loop Through Test Cases**: For each test case, read the number of rocks and their respective values.
3. **Edge Case Handling**: If there's only one rock, no jumps are needed (though the problem constraints ensure this case is not present).
4. **Greedy Algorithm**: By iterating through each rock and updating the farthest reachable index, we ensure that each jump is made from the optimal position. When the current index reaches the end of the previously reachable indices, a jump is counted, and the reachable indices are updated.
5. **Early Termination**: If the farthest reachable index meets or exceeds the last rock, the loop breaks early to save computation.

This approach efficiently computes the minimum jumps in linear time, making it suitable for large input sizes as specified in the problem constraints.
