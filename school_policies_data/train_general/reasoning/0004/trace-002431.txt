To solve this problem, we need to determine the minimum number of bridges to remove so that all given travel requests between pairs of islands are blocked. Each request specifies a pair of islands between which travel should be impossible, and we need to ensure that at least one bridge on the path between each pair is removed.

### Approach
1. **Problem Analysis**: The islands are arranged in a straight line connected by bridges. Each request (a_i, b_i) requires that travel between the a_i-th and b_i-th islands be blocked. This can be achieved by removing at least one bridge in the interval [a_i, b_i - 1].

2. **Greedy Algorithm**: The optimal strategy involves sorting the intervals by their right endpoints. By always removing the bridge at the rightmost endpoint of the current interval, we can cover as many subsequent intervals as possible, minimizing the number of bridges removed.

3. **Steps**:
   - Convert each request (a_i, b_i) into an interval [a_i, b_i - 1].
   - Sort these intervals by their right endpoints.
   - Iterate through the sorted intervals, removing the bridge at the right endpoint if the interval is not already covered by the last removed bridge.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    idx = 0
    N = int(input[idx])
    idx += 1
    M = int(input[idx])
    idx += 1
    intervals = []
    for _ in range(M):
        a = int(input[idx])
        idx += 1
        b = int(input[idx])
        idx += 1
        s = a
        e = b - 1
        intervals.append((s, e))
    # Sort intervals by their end points
    intervals.sort(key=lambda x: x[1])
    count = 0
    last = -1
    for s, e in intervals:
        if s > last:
            count += 1
            last = e
    print(count)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read and parsed into integers representing the number of islands, requests, and each request's start and end points.
2. **Interval Conversion**: Each request (a_i, b_i) is converted into an interval [a_i, b_i - 1] to represent the range of bridges that need to be considered for removal.
3. **Sorting**: The intervals are sorted by their right endpoints to facilitate the greedy approach.
4. **Greedy Selection**: By iterating through the sorted intervals and removing the bridge at the right endpoint of the current interval if it is not covered by the last removed bridge, we ensure the minimum number of bridges are removed while covering all requests.

This approach efficiently solves the problem in O(M log M) time due to sorting, which is suitable given the problem constraints.
