class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0] * (self.n + 1)  # 1-based indexing

    def update(self, idx, delta):
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & -idx

    def query(self, idx):
        res = 0
        while idx > 0:
            res += self.tree[idx]
            idx -= idx & -idx
        return res

import bisect

class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0] * (self.n + 1)
    
    def update(self, idx, delta):
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & -idx
    
    def query(self, idx):
        res = 0
        while idx > 0:
            res += self.tree[idx]
            idx -= idx & -idx
        return res

n = int(input())
segments = []
for i in range(n):
    l, r = map(int, input().split())
    segments.append( (l, r, i) )

# Sort the segments by l in ascending order
segments.sort(key=lambda x: x[0])

sorted_r = [seg[1] for seg in segments]
sorted_r.sort()

max_rank = n  # since all r are unique, sorted_r has length n

ft = FenwickTree(max_rank)

answer = [0] * n

# Process in reverse order
for seg in reversed(segments):
    l, r, idx = seg
    rank = bisect.bisect_left(sorted_r, r) + 1  # because ranks are 1-based
    count = ft.query(rank - 1)
    answer[idx] = count
    ft.update(rank, 1)

for ans in answer:
    print(ans)

To solve this problem, we need to determine how many segments are completely contained within each given segment on a line. The solution must be efficient due to the constraints, where the number of segments can be as large as 200,000.

### Approach
1. **Sort Segments by Start Points**: First, sort all segments by their left endpoints in ascending order. This allows us to process each segment in an order where we can efficiently check subsequent segments for containment.
2. **Coordinate Compression**: Since the endpoints can be very large, we use coordinate compression on the right endpoints to efficiently manage these values using a Fenwick Tree (Binary Indexed Tree).
3. **Fenwick Tree for Efficient Counting**: Using a Fenwick Tree, we can efficiently count the number of segments that end before the current segment's end point. This helps in determining how many segments are contained within the current segment.

### Solution Code
```python
import bisect

class FenwickTree:
    def __init__(self, size):
        self.n = size
        self.tree = [0] * (self.n + 1)  # 1-based indexing
    
    def update(self, idx, delta):
        while idx <= self.n:
            self.tree[idx] += delta
            idx += idx & -idx
    
    def query(self, idx):
        res = 0
        while idx > 0:
            res += self.tree[idx]
            idx -= idx & -idx
        return res

n = int(input())
segments = []
for i in range(n):
    l, r = map(int, input().split())
    segments.append((l, r, i))

# Sort segments by their left endpoint
segments.sort(key=lambda x: x[0])

# Extract and sort the right endpoints for coordinate compression
sorted_r = [seg[1] for seg in segments]
sorted_r.sort()

# Create a Fenwick Tree with size equal to the number of segments
ft = FenwickTree(n)

# Initialize the answer list
answer = [0] * n

# Process each segment in reverse order of their sorted left endpoints
for seg in reversed(segments):
    l, r, original_idx = seg
    # Find the rank of the current r in the sorted_r list
    rank = bisect.bisect_left(sorted_r, r) + 1  # +1 for 1-based indexing
    # Query the Fenwick Tree for the count of elements less than current r
    count = ft.query(rank - 1)
    answer[original_idx] = count
    # Update the Fenwick Tree with the current rank
    ft.update(rank, 1)

# Print the results in the order of the original input
for ans in answer:
    print(ans)
```

### Explanation
1. **Sorting Segments**: By sorting the segments based on their left endpoints, we ensure that any segment processed later in the sorted list has a starting point greater than or equal to the current segment's starting point. This simplifies checking for containment.
2. **Coordinate Compression**: This step maps the right endpoints to a smaller range, allowing efficient use of the Fenwick Tree. The right endpoints are sorted and assigned ranks, which are used in the Fenwick Tree operations.
3. **Fenwick Tree Operations**: The Fenwick Tree is used to keep track of the right endpoints of the segments processed so far. For each segment, we query the number of right endpoints that are less than the current segment's right endpoint. This count gives the number of segments contained within the current segment.

This approach ensures that each segment is processed in O(log n) time, leading to an overall time complexity of O(n log n), which is efficient enough for the problem constraints.
