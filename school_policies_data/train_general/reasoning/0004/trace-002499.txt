To solve this problem, we need to determine the number of ways to split an array into three non-empty contiguous parts such that each part has the same sum. The solution must be efficient enough to handle large input sizes up to 100,000 elements.

### Approach
1. **Check Divisibility by 3**: If the total sum of the array is not divisible by 3, it's impossible to split the array into three equal parts, so the answer is immediately 0.
2. **Prefix Sum Calculation**: Compute the prefix sums of the array to efficiently check the sums of potential subarrays.
3. **Identify Valid Split Points**: Collect indices where the prefix sum equals one-third of the total sum (potential start of the second part) and indices where the prefix sum equals two-thirds of the total sum (potential end of the second part).
4. **Count Valid Combinations**: For each valid end index of the second part, count how many valid start indices exist before it using binary search for efficiency.

### Solution Code
```python
import bisect

n = int(input())
arr = list(map(int, input().split()))

prefix = [0] * n
prefix[0] = arr[0]
for i in range(1, n):
    prefix[i] = prefix[i-1] + arr[i]

total = prefix[-1]

if total % 3 != 0:
    print(0)
else:
    target = total // 3
    two_target = 2 * target

    i_list = []
    max_i = n - 3  # 0-based, i can be up to n-3
    for i in range(max_i + 1):
        if prefix[i] == target:
            i_list.append(i)

    j_list = []
    max_j = n - 2  # j can be up to n-2 (0-based)
    for j in range(max_j + 1):
        if prefix[j] == two_target:
            j_list.append(j)

    res = 0
    for j in j_list:
        cnt = bisect.bisect_left(i_list, j)
        res += cnt

    print(res)
```

### Explanation
1. **Divisibility Check**: The total sum of the array is checked for divisibility by 3. If not divisible, the result is 0.
2. **Prefix Sum Array**: This array helps in quickly determining the sum of any subarray. The prefix sum at index `i` gives the sum of the array elements from the start up to index `i`.
3. **Collect Valid Indices**:
   - `i_list` collects indices where the prefix sum equals one-third of the total sum. These are potential end indices of the first part.
   - `j_list` collects indices where the prefix sum equals two-thirds of the total sum. These are potential end indices of the second part.
4. **Binary Search for Counting**: For each valid end index `j` in `j_list`, we use binary search to count how many valid start indices `i` (from `i_list`) are before `j`, ensuring non-empty parts.

This approach ensures that we efficiently count valid splits in linear time with the help of prefix sums and binary search, making it suitable for large input sizes.
