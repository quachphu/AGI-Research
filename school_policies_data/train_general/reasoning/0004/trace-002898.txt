To solve this problem, we need to round an integer \( n \) to the nearest multiple of another integer \( b \). If \( n \) is exactly halfway between two multiples of \( b \), we round up to the larger multiple.

### Approach
1. **Understanding the Rounding Rule**: When \( n \) is halfway between two multiples of \( b \), we round up to the larger multiple. For example, if \( n = 5 \) and \( b = 10 \), \( 5 \) is halfway between \( 0 \) and \( 10 \), so we round up to \( 10 \).

2. **Mathematical Insight**: The key insight is to adjust \( n \) by adding half of \( b \) (integer division) before performing the division. This adjustment ensures that when \( n \) is exactly halfway, the division result will round up to the next multiple of \( b \).

3. **Formula**: The formula used is \((n + (b // 2)) // b * b\). This formula works by:
   - Adding half of \( b \) to \( n \) to handle the midpoint case.
   - Using integer division to find the nearest quotient.
   - Multiplying back by \( b \) to get the nearest multiple.

### Solution Code
```python
import sys

def main():
    input = sys.stdin.read().split()
    T = int(input[0])
    idx = 1
    for _ in range(T):
        n = int(input[idx])
        b = int(input[idx + 1])
        idx += 2
        rounded = (n + b // 2) // b * b
        print(rounded)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints. The first value \( T \) is the number of test cases.
2. **Processing Each Test Case**: For each test case, we read \( n \) and \( b \).
3. **Applying the Formula**: For each pair \( (n, b) \), we compute the nearest multiple using the formula \((n + (b // 2)) // b * b\).
4. **Output the Result**: The result for each test case is printed immediately.

This approach ensures that we handle all edge cases, including exact midpoints, efficiently and correctly. The time complexity is \( O(T) \), where \( T \) is the number of test cases, making the solution very efficient even for the upper constraint limits.
