To solve this problem, we need to determine the minimum number of additional submissions required to achieve a specific success rate on Codeforces. The success rate is given as a fraction \( p/q \), and we need to adjust the current submissions \( x \) (successful) and \( y \) (total) to meet this rate.

### Approach
1. **Immediate Check**: If the current success rate \( x/y \) already matches \( p/q \), no additional submissions are needed.
2. **Edge Cases**:
   - If \( p = 0 \), the target success rate is 0. This is only possible if \( x = 0 \).
   - If \( p = q \), the target success rate is 1. This is only possible if \( x = y \).
3. **General Case** (0 < p < q):
   - Compute the minimum integer \( n \) such that:
     - \( p \times n \geq x \) (minimum submissions to reach at least \( p \times n \) successful submissions).
     - \( q \times n \geq y \) (minimum submissions to reach at least \( q \times n \) total submissions).
     - \( (q - p) \times n \geq y - x \) (ensures non-negative unsuccessful submissions added).

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read
    data = input().split()
    t = int(data[0])
    index = 1
    for _ in range(t):
        x = int(data[index])
        y = int(data[index+1])
        p = int(data[index+2])
        q = int(data[index+3])
        index += 4
        
        if x * q == p * y:
            print(0)
            continue
        
        if p == 0:
            print(0 if x == 0 else -1)
            continue
        
        if p == q:
            print(0 if x == y else -1)
            continue
        
        # Now handle 0 < p < q
        a_min = (x + p - 1) // p
        b_min = (y + q - 1) // q
        yx_diff = y - x
        qp_diff = q - p
        if yx_diff > 0:
            c_min = (yx_diff + qp_diff - 1) // qp_diff
        else:
            c_min = 0
        
        n = max(a_min, b_min, c_min)
        k = q * n - y
        print(k)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the constraints.
2. **Immediate Check**: If the current ratio \( x/y \) matches \( p/q \), the answer is 0.
3. **Edge Cases Handling**: Direct checks for \( p = 0 \) and \( p = q \) scenarios.
4. **General Case Calculation**:
   - **a_min**: Minimum \( n \) such that \( p \times n \geq x \).
   - **b_min**: Minimum \( n \) such that \( q \times n \geq y \).
   - **c_min**: Ensures non-negative unsuccessful submissions. If \( y > x \), compute the minimum \( n \) such that the difference between new total and new successful submissions is non-negative.
5. **Result Calculation**: The required number of additional submissions \( k \) is derived from the maximum \( n \) value that satisfies all constraints.

This approach efficiently calculates the minimum submissions needed using integer arithmetic and ensures all edge cases are handled appropriately.
