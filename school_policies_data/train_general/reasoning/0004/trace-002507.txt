There are n queries to process, the i-th will be received at moment ti and needs to be processed for di units of time. All ti are guaranteed to be distinct.

When a query appears server may react in three possible ways: 

  1. If server is free and query queue is empty, then server immediately starts to process this query. 
  2. If server is busy and there are less than b queries in the queue, then new query is added to the end of the queue. 
  3. If server is busy and there are already b queries pending in the queue, then new query is just rejected and will never be processed. 



As soon as server finished to process some query, it picks new one from the queue (if it's not empty, of course). If a new query comes at some moment x, and the server finishes to process another query at exactly the same moment, we consider that first query is picked from the queue and only then new query appears.

For each query find the moment when the server will finish to process it or print -1 if this query will be rejected.

Input

The first line of the input contains two integers n and b (1 ≤ n, b ≤ 200 000) — the number of queries and the maximum possible size of the query queue.

Then follow n lines with queries descriptions (in chronological order). Each description consists of two integers ti and di (1 ≤ ti, di ≤ 109), where ti is the moment of time when the i-th query appears and di is the time server needs to process it. It is guaranteed that ti - 1 < ti for all i > 1.

Output

Print the sequence of n integers e1, e2, ..., en, where ei is the moment the server will finish to process the i-th query (queries are numbered in the order they appear in the input) or  - 1 if the corresponding query will be rejected.

To solve this problem, we need to simulate the workflow of a one-thread server processing incoming queries with a queue of limited size. The server processes queries immediately if it's free, adds them to the queue if it's busy and the queue isn't full, or rejects them if the queue is full.

### Approach
1. **Initialization**: Start with the server free (`current_end` set to 0) and an empty queue.
2. **Processing Queries**: For each incoming query:
   - **Process the Queue**: Before handling the new query, process as many queued queries as possible up to the current query's arrival time.
   - **Check Server Status**: If the server is free, process the new query immediately. If the server is busy, add the query to the queue if there's space; otherwise, reject it.
3. **Final Processing**: After all queries have been handled, process any remaining queries in the queue to determine their end times.

### Solution Code
```python
import sys
from collections import deque

def main():
    input = sys.stdin.read().split()
    ptr = 0
    n, b = int(input[ptr]), int(input[ptr+1])
    ptr += 2
    queries = []
    for _ in range(n):
        ti = int(input[ptr])
        di = int(input[ptr+1])
        queries.append((ti, di))
        ptr += 2
    
    current_end = 0
    q = deque()
    ans = [-1] * n
    
    for i in range(n):
        ti, di = queries[i]
        # Process as many queued queries as possible up to ti
        while q and current_end <= ti:
            d, idx = q.popleft()
            current_end += d
            ans[idx] = current_end
        
        # Check if server is free to process current query
        if current_end <= ti:
            current_end = ti + di
            ans[i] = current_end
        else:
            if len(q) < b:
                q.append((di, i))
            else:
                ans[i] = -1
    
    # Process any remaining queries in the queue
    while q:
        d, idx = q.popleft()
        current_end += d
        ans[idx] = current_end
    
    print(' '.join(map(str, ans)))

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read and parsed into a list of tuples representing each query's arrival time and processing duration.
2. **Queue Processing**: Before handling each new query, the server processes as many queued queries as possible up to the current query's arrival time. This ensures that the server is always in the correct state (busy or free) when evaluating the new query.
3. **Immediate Processing**: If the server is free when a new query arrives, it processes the query immediately, updating the server's end time and recording the result.
4. **Queue Management**: If the server is busy, the query is added to the queue if there's space; otherwise, it is rejected. The queue ensures queries are processed in FIFO order.
5. **Final Processing**: After all incoming queries are handled, any remaining queries in the queue are processed to determine their end times.

This approach efficiently handles up to 200,000 queries with a time complexity of O(n), ensuring optimal performance by leveraging a deque for queue operations.
