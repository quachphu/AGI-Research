To solve this problem, we need to determine the minimum number of Kinder Surprise eggs to buy to ensure we get at least one sticker and one toy, regardless of their distribution inside the eggs. The solution involves calculating the worst-case scenario where we might pick the maximum number of eggs containing only stickers or only toys, and then adding one more egg to ensure we get both.

### Approach
1. **Problem Analysis**: Each egg can contain a sticker, a toy, or both. The key insight is that in the worst case, we might pick all eggs that contain only stickers or only toys. We need to find the maximum number of such eggs and add one more to ensure we get both a sticker and a toy.
2. **Formulation**: For each query, compute the number of eggs that could contain only stickers (n - t) and only toys (n - s). The maximum of these two values gives the worst-case scenario. Adding 1 to this maximum ensures we get at least one egg with both a sticker and a toy.
3. **Algorithm**: For each test case, compute the maximum value of (n - s) and (n - t), then add 1 to this maximum to get the result.

### Solution Code
```python
import sys

def main():
    input = sys.stdin.read().split()
    T = int(input[0])
    idx = 1
    for _ in range(T):
        n = int(input[idx])
        s = int(input[idx+1])
        t = int(input[idx+2])
        idx += 3
        a = n - s
        b = n - t
        res = max(a, b) + 1
        print(res)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints.
2. **Processing Each Query**: For each test case, the values of n, s, and t are extracted.
3. **Calculating Worst-Case Scenario**: The maximum number of eggs that could contain only stickers or only toys is determined using `max(n - s, n - t)`.
4. **Result Calculation**: Adding 1 to the maximum value ensures that even in the worst case, we get at least one egg containing both a sticker and a toy.

This approach efficiently computes the solution in constant time for each query, making it suitable for large input sizes up to the given constraints.
