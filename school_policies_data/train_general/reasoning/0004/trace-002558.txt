The solution involves tracking the hierarchy changes over time and using efficient tree traversal techniques to answer the queries.

### Approach
1. **Hierarchy Tracking**: Track the hierarchy changes using a parent array where each employee's parent is recorded once it is set. Additionally, track the time (event index) when each parent-child relationship was established.

2. **DFS for Ancestry Check**: Perform a Depth-First Search (DFS) to compute in-time and out-time for each employee. This helps in quickly determining if one employee is an ancestor of another using in-time and out-time intervals.

3. **Binary Lifting for Efficient Queries**: Use binary lifting to precompute the maximum time parameter (event index) for each node's ancestors up to log2(n) steps. This allows efficient computation of the maximum time parameter along the path between two nodes.

4. **Query Processing**: For each query, check if the employee is an ancestor of the packet's starting employee using the precomputed in-time and out-time. If they are, use the binary lifting table to compute the maximum time parameter along the path and determine if the employee signed the document.

        if parent[x] is None and not visited[x]:
            stack = [(x, False)]
            while stack:
                node, processed = stack.pop()
                if processed:
                    out_time[node] = time
                    time += 1
                    continue
                if visited[node]:
                    continue
                visited[node] = True
                in_time[node] = time
                time += 1
                # Push children in reverse order to process them in order
                children = []
                for child in range(1, n + 1):
                    if parent[child] == node and not visited[child]:
                        children.append(child)
                children.sort(reverse=True)
                stack.append((node, True))
                for child in children:
                    stack.append((child, False))

    # Build binary lifting tables
    max_level = 20
    up = [[-1] * max_level for _ in range(n + 1)]
    max_time_table = [[0] * max_level for _ in range(n + 1)]

    for x in range(1, n + 1):
        if parent[x] is not None:
            up[x][0] = parent[x]
            max_time_table[x][0] = time_par[x]
        else:
            up[x][0] = -1
            max_time_table[x][0] = 0

    for j in range(1, max_level):
        for x in range(1, n + 1):
            prev = up[x][j-1]
            if prev == -1:
                up[x][j] = -1
                max_time_table[x][j] = max_time_table[x][j-1]
            else:
                up[x][j] = up[prev][j-1]
                max_time_table[x][j] = max(max_time_table[x][j-1], max_time_table[prev][j-1])

    # Process queries
    for x, i in queries:
        if i > len(packets):
            print("NO")

        if x_i == x:

        if not (in_time[x] <= in_time[x_i] and out_time[x] >= out_time[x_i]):
            print("NO")
            continue

        # Compute max_time along the path from x_i to x
        current = x_i
        max_t = 0
        found = False
        while current != x and current != -1:
            # Find the highest j where up[current][j] is ancestor of x
            for j in reversed(range(max_level)):

                if in_time[x] <= in_time[next_node] and out_time[x] >= out_time[next_node]:

                    current = next_node
                    break
            else:
                # No higher jump possible, move one step
                next_node = up[current][0]
                if next_node == -1:

                max_t = max(max_t, max_time_table[current][0])
                current = next_node

2. **DFS for Ancestry Check**: By performing a DFS and computing in-time and out-time, we can quickly check if one node is an ancestor of another using interval containment.

3. **Binary Lifting**: This technique precomputes ancestors at powers of two steps, allowing efficient traversal and maximum time parameter calculation along paths. This reduces the complexity of path queries from O(n) to O(log n).

4. **Query Processing**: Each query is answered by checking ancestry using in-time and out-time intervals, then using binary lifting to compute the maximum time parameter along the path and compare it with the event time of the packet. This ensures efficient and accurate query resolution.
