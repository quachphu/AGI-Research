To solve this problem, we need to determine the maximum number of perfect teams that can be formed from given numbers of coders, mathematicians, and students with no specialization. A perfect team must have exactly three members, including at least one coder and one mathematician.

### Approach
The approach to solve this problem involves two key insights:
1. **Team Composition Constraints**: Each team must have at least one coder and one mathematician. The third member can be either a coder, mathematician, or a student with no specialization.
2. **Resource Constraints**: The number of teams is limited by the total number of students divided by 3 (since each team requires exactly 3 members) and the minimum number of coders or mathematicians available (since each team needs at least one of each).

The solution for each query is the minimum of:
1. The total number of students divided by 3.
2. The smaller count between the number of coders and mathematicians.

### Solution Code
```python
import sys

q = int(sys.stdin.readline())
for _ in range(q):
    c, m, x = map(int, sys.stdin.readline().split())
    total = c + m + x
    possible_teams = min(total // 3, min(c, m))
    print(possible_teams)
```

### Explanation
1. **Reading Input**: The code reads the number of queries and then processes each query line by line.
2. **Calculating Total Students**: For each query, the total number of students is computed as the sum of coders, mathematicians, and students with no specialization.
3. **Determining Possible Teams**: The possible number of teams is constrained by both the total number of students divided by 3 and the minimum number of coders or mathematicians. This ensures that each team has at least one coder and one mathematician, and does not exceed the available number of students.
4. **Output the Result**: For each query, the result is printed, which is the minimum of the two constraints mentioned above.

This approach efficiently computes the maximum number of perfect teams for each query in constant time, making it suitable for handling up to 10^4 queries efficiently.
