To solve this problem, we need to determine the optimal starting task for Dima such that the total power with which Inna tells him off is minimized. The key insight is to recognize that the power sum depends on the starting task's position modulo k, and we can efficiently compute the sum for each possible starting position using this observation.

### Approach
1. **Understanding the Problem**: Dima works in batches of k tasks. Inna scolds him for the first task of each batch. We need to find the starting task that minimizes the total scolding power.
2. **Modulo Insight**: The total scolding power for starting positions that are congruent modulo k will be the same. This allows us to compute the sum for each residue class modulo k efficiently.
3. **Efficient Calculation**: For each residue class modulo k, compute the sum of scolding powers for tasks at positions that are multiples of k apart. This reduces the problem to checking k possible sums instead of n, making the solution efficient.

### Solution Code
```python
def find_optimal_start():
    import sys
    input = sys.stdin.read().split()
    n = int(input[0])
    k = int(input[1])
    a = list(map(int, input[2:2+n]))
    m = n // k
    sums = [0] * k
    for r in range(k):
        total = 0
        for i in range(m):
            pos = r + i * k
            total += a[pos]
        sums[r] = total
    min_sum = min(sums)
    for r in range(k):
        if sums[r] == min_sum:
            print(r + 1)
            return

find_optimal_start()
```

### Explanation
1. **Reading Input**: The input is read and parsed into the number of tasks (n), the batch size (k), and the list of scolding powers (a).
2. **Residue Classes**: For each residue class modulo k (0 to k-1), compute the sum of scolding powers for tasks at positions `r, r + k, r + 2k, ...` up to `m` tasks, where `m = n // k`.
3. **Finding Minimum Sum**: Determine the residue class with the minimum total scolding power. If multiple residues have the same minimum sum, the smallest residue (and thus the smallest starting task) is chosen.

This approach efficiently reduces the problem size from O(n) to O(k), making it feasible for large input sizes up to 100,000 tasks.
