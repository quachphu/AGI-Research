### Approach
1. **Data Structures**: Use two dictionaries to maintain the times at which elements are added and removed. Each dictionary maps an element to a list of times, which are kept sorted.
2. **Insertion with Sorting**: For each add or remove operation, insert the time into the respective list while maintaining sorted order using binary insertion.
3. **Binary Search for Count**: For each count query, use binary search to determine how many times the element was added or removed up to the given time. The count is the difference between the number of additions and removals.

### Solution Code
```python
import bisect
from collections import defaultdict
import sys

def main():
    add_events = defaultdict(list)
    remove_events = defaultdict(list)
    n = int(sys.stdin.readline())
    output = []
    for _ in range(n):
        parts = sys.stdin.readline().split()
        a, t, x = map(int, parts)
        if a == 1:
            bisect.insort(add_events[x], t)
        elif a == 2:
            bisect.insort(remove_events[x], t)
        elif a == 3:
            adds = add_events.get(x, [])
            removes = remove_events.get(x, [])
            add_count = bisect.bisect_right(adds, t)
            remove_count = bisect.bisect_right(removes, t)
            output.append(str(add_count - remove_count))
    print('\n'.join(output))

if __name__ == "__main__":
    main()
```

### Explanation
- **Data Structures**: We use `defaultdict` to store lists of times for each element. `add_events` tracks when elements are added, and `remove_events` tracks when they are removed.
- **Insertion**: For each add or remove operation, we use `bisect.insort` to insert the time into the appropriate list while maintaining sorted order. This ensures efficient lookups later.
- **Counting**: For each count query, we use `bisect.bisect_right` to find the number of additions and removals up to the query time. The difference between these counts gives the current number of the element in the multiset at that time.

This approach efficiently handles up to 100,000 operations with each insertion and lookup operation being logarithmic in complexity, making it suitable for large input sizes.
