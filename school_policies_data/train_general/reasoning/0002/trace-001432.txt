To solve this problem, we need to determine the number of perfect squares between two given numbers (inclusive) that consist only of the digits 0, 1, 4, and 9. These digits are considered "perfect digits" because they are themselves perfect squares.

### Approach
1. **Precompute Valid Perfect Squares**: Generate all perfect squares up to \(10^{10}\) (since the maximum value of `b` is \(10^{10}\)) that consist only of the digits 0, 1, 4, and 9. This is done once at the start to avoid redundant computations for each test case.
2. **Efficient Query Handling**: For each test case, use binary search to quickly determine how many of the precomputed valid perfect squares fall within the given range [a, b]. This ensures efficient handling of up to 500 test cases.

### Solution Code
```python
import bisect

def main():
    import sys
    input = sys.stdin.read().split()
    T = int(input[0])
    cases = [(int(input[2*i+1]), int(input[2*i+2])) for i in range(T)]
    
    valid_digits = {'0', '1', '4', '9'}
    valid_squares = []
    max_x = 10**5  # since (10^5)^2 = 10^10
    
    for x in range(0, max_x + 1):
        square = x * x
        s = str(square)
        if all(c in valid_digits for c in s):
            valid_squares.append(square)
    
    for a, b in cases:
        left = bisect.bisect_left(valid_squares, a)
        right = bisect.bisect_right(valid_squares, b)
        print(right - left)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Precomputation**: We generate all perfect squares from 0 up to \(10^{10}\) (since \(10^5\) squared is \(10^{10}\)). Each square is checked to ensure all its digits are in the set {0, 1, 4, 9}. This list of valid squares is precomputed once and stored.
2. **Binary Search for Efficient Range Queries**: For each test case, we use binary search (via `bisect_left` and `bisect_right`) to find the indices of the smallest and largest valid squares within the range [a, b]. The difference between these indices gives the count of valid squares in the range.

This approach ensures that we efficiently handle up to 500 test cases by leveraging precomputation and binary search, resulting in optimal performance even for large input ranges.
