To solve this problem, we need to determine the two elements Valeriy will pull out of the deque for each query after performing a series of operations. The challenge is to efficiently handle very large input sizes and queries with values up to \(10^{18}\).

### Approach
1. **Initial Phase Simulation**: Simulate the operations until the maximum element in the deque is moved to the front. This phase ensures that once the maximum element is at the front, all subsequent operations will involve this maximum element and the next element in the deque.
2. **Cycle Detection**: Once the maximum element is at the front, the operations enter a steady phase where the elements after the maximum element form a cycle. Each cycle length is \(n-1\), where \(n\) is the number of elements in the deque.
3. **Query Handling**: For each query, if the query index is within the initial phase, directly use the precomputed results. For indices beyond the initial phase, use the cycle to determine the result efficiently.

### Solution Code
```python
import sys
from collections import deque

def main():
    input = sys.stdin.read().split()
    ptr = 0
    n, q = int(input[ptr]), int(input[ptr+1])
    ptr += 2
    a = list(map(int, input[ptr:ptr+n]))
    ptr += n
    
    M = max(a)
    precompute_steps = []
    current_deque = deque(a)
    K = 0
    
    while current_deque[0] != M:
        A = current_deque.popleft()
        B = current_deque.popleft()
        precompute_steps.append((A, B))
        K += 1
        if A > B:
            max_val, min_val = A, B
        else:
            max_val, min_val = B, A
        current_deque.appendleft(max_val)
        current_deque.append(min_val)
    
    x = list(current_deque)[1:]
    cycle_length = len(x)
    
    for _ in range(q):
        m_j = int(input[ptr])
        ptr += 1
        if m_j <= K:
            pair = precompute_steps[m_j - 1]
            print(pair[0], pair[1])
        else:
            offset = m_j - K - 1
            cycle_index = offset % cycle_length
            print(M, x[cycle_index])
    
if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the large possible input size.
2. **Initial Phase Simulation**: Using a deque, we repeatedly remove the first two elements, determine the order based on their values, and reinsert them such that the larger value is at the front and the smaller at the end. This continues until the maximum element is at the front.
3. **Cycle Detection**: Once the maximum element is at the front, the remaining elements form a cycle. The length of this cycle is \(n-1\), where \(n\) is the number of elements in the deque.
4. **Query Handling**: For each query, if the query index is within the number of steps taken to move the maximum element to the front (initial phase), we use precomputed results. For indices beyond this phase, we compute the result based on the detected cycle, using modular arithmetic to efficiently determine the position within the cycle.

This approach ensures that we handle up to the maximum constraints efficiently, avoiding the need to simulate each operation individually for very large indices.
