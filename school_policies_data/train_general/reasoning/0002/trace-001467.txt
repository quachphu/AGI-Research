To solve this problem, we need to determine the minimum number of repaints required to ensure that adjacent tiles have different colors. The solution involves comparing the given tile configuration with two possible valid patterns and selecting the one with the fewest required changes.

### Approach
1. **Identify Valid Patterns**: The valid patterns for alternating tiles are either starting with '0' (e.g., '010101...') or starting with '1' (e.g., '101010...').
2. **Count Mismatches**: For each tile in the input string, compare it with the expected tile in both valid patterns. Count how many changes are needed for each pattern.
3. **Determine Minimum Repaints**: The result is the minimum number of changes required between the two patterns.

### Solution Code
```python
def main():
    S = input().strip()
    count_start0 = 0
    count_start1 = 0
    for i in range(len(S)):
        current_char = S[i]
        if i % 2 == 0:
            expected0 = '0'
            expected1 = '1'
        else:
            expected0 = '1'
            expected1 = '0'
        if current_char != expected0:
            count_start0 += 1
        if current_char != expected1:
            count_start1 += 1
    print(min(count_start0, count_start1))

if __name__ == '__main__':
    main()
```

### Explanation
1. **Reading Input**: The input string `S` is read from standard input.
2. **Initializing Counters**: Two counters, `count_start0` and `count_start1`, are initialized to track the number of changes needed for each valid pattern.
3. **Iterating Through Tiles**: For each tile in the string:
   - Determine the expected character for both valid patterns (starting with '0' and starting with '1') based on the tile's position (even or odd index).
   - Compare the actual tile color with the expected colors and update the respective counters if a mismatch occurs.
4. **Output Result**: The minimum value of the two counters is printed, representing the minimum number of repaints required.

This approach efficiently computes the result in linear time, making it suitable for the upper constraint of the input size (up to 100,000 tiles).
