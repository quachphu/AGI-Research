To solve this problem, we need to find the smallest lucky number (composed only of the digits 4 and 7) whose digits sum to a given integer \( n \). If no such number exists, we should return -1.

### Approach
1. **Understanding Lucky Numbers**: Lucky numbers are those that consist only of the digits 4 and 7. The goal is to find the smallest such number whose digits sum to \( n \).
2. **Mathematical Formulation**: We need to find non-negative integers \( a \) (number of 4s) and \( b \) (number of 7s) such that \( 4a + 7b = n \). The smallest number will have the least number of digits, which translates to minimizing \( a + b \).
3. **Maximizing 7s**: Since 7 is larger than 4, using more 7s can help minimize the total number of digits. We start by checking the maximum possible number of 7s and reduce until we find valid values of \( a \) and \( b \).
4. **Lexicographical Order**: Once valid \( a \) and \( b \) are found, the smallest number is formed by placing all 4s before 7s to ensure the lexicographically smallest order.

### Solution Code
```python
def find_min_lucky():
    n = int(input())
    max_b = n // 7
    for b in range(max_b, -1, -1):
        remaining = n - 7 * b
        if remaining >= 0 and remaining % 4 == 0:
            a = remaining // 4
            print('4' * a + '7' * b)
            return
    print(-1)

find_min_lucky()
```

### Explanation
1. **Reading Input**: The function reads the integer \( n \) from standard input.
2. **Iterating Over Possible 7s**: The loop starts from the maximum possible number of 7s (max_b) and decrements to 0. For each value of \( b \), it calculates the remaining sum needed to reach \( n \) after accounting for the 7s.
3. **Checking Validity**: For each remaining sum, it checks if the remaining value can be formed using 4s (i.e., if the remaining value is non-negative and divisible by 4).
4. **Constructing the Result**: Once valid \( a \) and \( b \) are found, the function constructs the smallest number by concatenating \( a \) 4s followed by \( b \) 7s and prints it. If no valid pair is found, it prints -1.

This approach ensures that we efficiently find the smallest possible lucky number by leveraging mathematical insights and systematic iteration.
