To solve this problem, we need to determine which song is playing at specific moments in time during Eugeny's playlist. The playlist consists of songs played in sequence, each repeated a certain number of times, and each repetition taking a specific duration. We need to efficiently answer multiple queries about the song playing at given times.

### Approach
1. **Understanding the Playlist Structure**: Each song is played a certain number of times, and each play of the song has a fixed duration. The total duration contributed by each song is the product of the number of times it is played and its duration.
2. **Cumulative Duration Calculation**: We compute a cumulative duration array where each element at index `i` represents the total duration from the start of the playlist up to the end of the `i+1`-th song. This array helps in quickly determining the range in which each query time falls.
3. **Binary Search for Efficient Querying**: For each query, we use binary search on the cumulative duration array to find the first song whose cumulative duration is greater than or equal to the query time. This allows us to efficiently determine which song is playing at each queried time.

### Solution Code
```python
import sys
import bisect

def main():
    n, m = map(int, sys.stdin.readline().split())
    
    prefix = []
    current = 0
    for _ in range(n):
        ci, ti = map(int, sys.stdin.readline().split())
        current += ci * ti
        prefix.append(current)
    
    queries = list(map(int, sys.stdin.readline().split()))
    
    for v in queries:
        idx = bisect.bisect_left(prefix, v)
        print(idx + 1)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The first line of input contains the number of songs `n` and the number of queries `m`. The next `n` lines each contain two integers representing the count of plays and the duration of each play for a song. The subsequent line contains `m` query times.
2. **Cumulative Duration Array**: We compute an array where each element at index `i` is the cumulative duration of the playlist up to the end of the `i+1`-th song. This is done by iterating through each song and accumulating the total duration.
3. **Processing Queries**: For each query time, we use binary search (via `bisect_left`) to find the smallest index in the cumulative duration array where the value is at least the query time. The index found corresponds to the song number (adjusted for 1-based indexing).

This approach ensures that each query is processed in logarithmic time relative to the number of songs, making the solution efficient even for large input sizes.
