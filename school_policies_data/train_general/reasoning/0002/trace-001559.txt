To solve this problem, we need to determine the minimum number of spells required to ensure that no two adjacent slimes have the same color. The solution involves analyzing consecutive runs of the same color and determining the minimum changes needed to break these runs.

### Approach
The key insight is that each consecutive run of the same color can be optimally broken by changing every other element in the run. For example, a run of length `l` can be made non-consecutive by changing `l // 2` elements. This approach ensures that we minimize the number of changes required while adhering to the constraints.

### Solution Code
```python
n, *rest = map(int, open(0).read().split())
a = rest[:n]

if not a:
    print(0)
else:
    prev = a[0]
    run_length = 1
    res = 0
    for num in a[1:]:
        if num == prev:
            run_length += 1
        else:
            res += run_length // 2
            run_length = 1
            prev = num
    res += run_length // 2
    print(res)
```

### Explanation
1. **Reading Input:** The input is read and parsed into a list of integers representing the colors of the slimes.
2. **Initialization:** We initialize variables to track the previous color, the length of the current run of consecutive colors, and the result counter.
3. **Iterating Through Colors:** For each color in the list (starting from the second element), we check if it matches the previous color. If it does, we increase the run length. If it doesn't, we calculate the number of changes needed for the current run and reset the run length.
4. **Final Calculation:** After processing all elements, we add the changes required for the last run of consecutive colors.
5. **Output:** The result, which is the total number of changes required, is printed.

This approach efficiently processes each element in linear time, making it suitable for the given problem constraints.
