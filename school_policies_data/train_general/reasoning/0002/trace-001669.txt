To solve this problem, we need to determine the number of valid sequences of length `n` using distinct digits from 0 to 9 such that the weighted sum of the sequence equals a given value `s`. The weighted sum is calculated as `k1 + 2*k2 + 3*k3 + ... + n*kn` where `ki` is the ith element of the sequence.

### Approach
1. **Precomputation**: Generate all possible permutations of digits from 0 to 9 for each possible length `n` (from 1 to 10). For each permutation, compute the weighted sum and store the count of permutations that result in each possible sum.
2. **Efficient Query Handling**: For each input query, simply look up the precomputed counts to determine the number of valid sequences for the given `n` and `s`.

### Solution Code
```python
import itertools
from collections import defaultdict
import sys

# Precompute the counts for each n and s
counts = [defaultdict(int) for _ in range(11)]  # indices 0 to 10, 0 unused

for n in range(1, 11):
    for perm in itertools.permutations(range(10), n):
        total = sum((i + 1) * digit for i, digit in enumerate(perm))
        counts[n][total] += 1

# Process each line from stdin
for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    n, s = map(int, line.split())
    print(counts[n].get(s, 0))
```

### Explanation
1. **Precomputation**:
   - We use `itertools.permutations` to generate all possible permutations of digits from 0 to 9 for each length `n` (from 1 to 10).
   - For each permutation, we compute the weighted sum using the formula `1*k1 + 2*k2 + ... + n*kn`.
   - We store the count of each sum in a dictionary where the key is the sum and the value is the number of permutations that result in that sum.

2. **Query Handling**:
   - For each input query, we check the precomputed counts to quickly retrieve the number of valid sequences that match the given `n` and `s`.
   - If the sum `s` is not found in the precomputed data for the given `n`, we return 0.

This approach ensures that we efficiently handle multiple queries by leveraging precomputed results, thus reducing the time complexity for each query to O(1) after an initial preprocessing step. The preprocessing step, while computationally intensive, is feasible given the constraints and ensures quick responses to each query.
