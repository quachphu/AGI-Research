To solve this problem, we need to determine the minimum number of steps required to reduce a given integer \( n \) to 0 using two possible operations: subtracting 1 or dividing by \( k \) (only when \( n \) is divisible by \( k \)). The goal is to minimize the steps required for each query.

### Approach
1. **Subtract Until Divisible**: If \( n \) is not divisible by \( k \), subtract 1 repeatedly until \( n \) becomes divisible by \( k \). The number of subtractions needed here is \( n \% k \).
2. **Divide by \( k \)**: Once \( n \) is divisible by \( k \), divide \( n \) by \( k \). This operation is counted as one step.
3. **Repeat**: Continue the above steps iteratively until \( n \) becomes 0. If \( n \) becomes smaller than \( k \), subtract the remaining value of \( n \) in one step.

This approach ensures that we minimize the number of steps by leveraging division whenever possible and only subtracting when necessary.

### Solution Code
```python
t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    steps = 0
    while True:
        if n == 0:
            break
        if n < k:
            steps += n
            break
        rem = n % k
        if rem == 0:
            steps += 1
            n = n // k
        else:
            steps += rem
            n -= rem
            steps += 1
            n = n // k
    print(steps)
```

### Explanation
1. **Reading Input**: The number of test cases \( t \) is read first. For each test case, \( n \) and \( k \) are read.
2. **Loop Until Zero**: The loop continues until \( n \) is reduced to 0.
3. **Check Divisibility**: If \( n \) is smaller than \( k \), subtract \( n \) in one step. Otherwise, check the remainder when \( n \) is divided by \( k \).
4. **Subtract Remainder**: If \( n \) is not divisible by \( k \), subtract the remainder to make \( n \) divisible by \( k \), then divide by \( k \).
5. **Divide Directly**: If \( n \) is divisible by \( k \), divide it directly and increment the step count.

This approach efficiently reduces \( n \) by using division whenever possible, minimizing the number of operations needed. The loop runs in \( O(\log_k n) \) time, which is efficient even for very large values of \( n \) up to \( 10^{18} \).
