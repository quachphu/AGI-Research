To solve this problem, we need to determine the smallest non-negative integer \( X \) such that the quadratic polynomial \( A X^2 + B X + C \) meets or exceeds a given value \( K \). Given the constraints, an efficient solution is necessary to handle up to \( 10^5 \) test cases.

### Approach
1. **Immediate Check for Zero**: If the constant term \( C \) is already greater than or equal to \( K \), then \( X = 0 \) is the solution since the polynomial's value at \( X = 0 \) is \( C \).
2. **Exponential Search for Upper Bound**: For cases where \( C < K \), compute \( D = K - C \). Use exponential search to quickly find an upper bound where the quadratic value \( A X^2 + B X \) exceeds \( D \). This is done by doubling the upper bound until it is sufficiently large.
3. **Binary Search**: Once an upper bound is established, perform a binary search between 0 and the upper bound to find the smallest \( X \) that satisfies the condition \( A X^2 + B X \geq D \).

### Solution Code
```python
import sys

def find_x(A, B, D):
    low = 0
    high = 1
    while A * high * high + B * high < D:
        high *= 2
    while low < high:
        mid = (low + high) // 2
        val = A * mid * mid + B * mid
        if val >= D:
            high = mid
        else:
            low = mid + 1
    return low

def main():
    input = sys.stdin.read().split()
    idx = 0
    T = int(input[idx])
    idx += 1
    for _ in range(T):
        A = int(input[idx])
        B = int(input[idx+1])
        C = int(input[idx+2])
        K = int(input[idx+3])
        idx += 4
        if C >= K:
            print(0)
        else:
            D = K - C
            x = find_x(A, B, D)
            print(x)

if __name__ == '__main__':
    main()
```

### Explanation
1. **Reading Input Efficiently**: The input is read all at once and split into a list for efficient processing, which is crucial given the large number of test cases.
2. **Exponential Search**: This step quickly determines an upper bound by doubling the value of `high` until the quadratic value at `high` exceeds \( D \). This ensures that the upper bound is found in logarithmic time relative to the size of \( D \).
3. **Binary Search**: This step efficiently narrows down the smallest \( X \) by repeatedly halving the search interval, ensuring logarithmic time complexity relative to the upper bound found.

This approach ensures that each test case is handled in \( O(\log X) \) time, making the solution efficient and scalable even for the upper constraint limits.
