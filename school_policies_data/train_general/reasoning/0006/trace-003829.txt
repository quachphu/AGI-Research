To solve this problem, we need to determine the disorderliness index of a street, which is defined as the number of pairs of houses (i, j) such that i < j and the height of the house at i is greater than the height at j. This is equivalent to counting the number of inversions in an array, where an inversion is a pair of elements that are out of their natural order.

### Approach
The approach to solve this problem efficiently involves using a Binary Indexed Tree (BIT) to count inversions in O(n log n) time. The steps are as follows:

1. **Coordinate Compression**: Since the heights of the houses can be very large, we compress them into a smaller range (1 to n) based on their sorted order. This allows us to efficiently use the BIT.
2. **BIT Initialization**: We initialize a BIT to keep track of the counts of elements as we process them from right to left.
3. **Processing Elements**: For each element processed from right to left, we query the BIT to find how many elements to its right (already processed elements) are smaller than the current element. This count is added to the disorderliness index. We then update the BIT to include the current element.

### Solution Code
```python
class BIT:
    def __init__(self, size):
        self.size = size
        self.tree = [0] * (size + 2)  # 1-based indexing

    def update(self, index, delta):
        while index <= self.size:
            self.tree[index] += delta
            index += index & -index

    def query(self, index):
        res = 0
        while index > 0:
            res += self.tree[index]
            index -= index & -index
        return res

n = int(input())
arr = list(map(int, input().split()))
sorted_arr = sorted(arr)
rank = {v: i+1 for i, v in enumerate(sorted_arr)}  # Assign ranks based on sorted order

bit = BIT(n)
inversion_count = 0

# Process each element from right to left
for num in reversed(arr):
    r = rank[num]
    inversion_count += bit.query(r - 1)
    bit.update(r, 1)

print(inversion_count)
```

### Explanation
1. **Coordinate Compression**: By sorting the array and assigning each element a rank based on its position in the sorted array, we map each element to a compressed coordinate (rank) between 1 and n. This helps in efficiently using the BIT.
2. **BIT Operations**: The BIT is used to maintain the count of elements processed so far. For each element processed from right to left:
   - **Query**: We query the BIT to find how many elements to the right (already processed) are smaller than the current element. This is done by querying the prefix sum up to the rank of the current element minus one.
   - **Update**: After querying, we update the BIT to include the current element's rank, incrementing the count at that rank.
3. **Complexity**: The overall time complexity is O(n log n) due to the sorting step and the BIT operations (each update and query operation is O(log n)).

This approach efficiently counts the number of inversions, providing the solution within acceptable time limits even for large input sizes.
