To solve this problem, we need to determine the minimum number of turns required to change all squares in a row into the same color using the flood fill game. The game allows changing the color of the connected component containing the starting square in each turn.

### Approach
1. **Compress the Array**: First, we compress the input array into blocks of consecutive same colors. This helps in reducing the problem to working with distinct adjacent blocks.
2. **Dynamic Programming (DP)**: We use a DP approach to compute the minimum number of turns required to merge all blocks into a single color. The DP table `dp[i][j]` represents the minimum turns needed to merge blocks from index `i` to `j` into a single component.
3. **Recurrence Relation**:
   - If the colors of the first and last blocks in the current range are the same, the solution is `dp[i+1][j-1] + 1`.
   - Otherwise, the solution is the minimum of merging from the left or right plus one turn.

### Solution Code
```python
def main():
    import sys
    n = int(sys.stdin.readline())
    c = list(map(int, sys.stdin.readline().split()))
    
    # Compress the array into blocks of consecutive same colors
    blocks = []
    for color in c:
        if not blocks or blocks[-1] != color:
            blocks.append(color)
    m = len(blocks)
    if m <= 1:
        print(0)
        return
    
    # Initialize DP table
    dp = [[0] * m for _ in range(m)]
    
    # Fill DP table for all interval lengths starting from 2 up to m
    for length in range(2, m + 1):
        for i in range(m - length + 1):
            j = i + length - 1
            if blocks[i] == blocks[j]:
                # Since adjacent blocks are different, length must be at least 3 for i and j to be same
                dp[i][j] = dp[i + 1][j - 1] + 1
            else:
                dp[i][j] = min(dp[i + 1][j], dp[i][j - 1]) + 1
    
    print(dp[0][m - 1])

if __name__ == "__main__":
    main()
```

### Explanation
1. **Compression**: The input array is compressed into blocks where consecutive same colors are merged. This simplifies the problem by reducing the number of elements to consider.
2. **DP Table Initialization**: We initialize a 2D DP table where `dp[i][j]` will store the minimum turns needed to merge blocks from index `i` to `j`.
3. **Filling the DP Table**: For each possible interval length starting from 2 up to the number of blocks, we compute the minimum turns required. If the first and last blocks in the interval have the same color, we can merge the inner blocks first. Otherwise, we take the minimum of merging from the left or right and add one turn.
4. **Result**: The result is found in `dp[0][m-1]`, which gives the minimum turns needed to merge all blocks starting from the first block to the last block.

This approach efficiently computes the solution using dynamic programming, leveraging the structure of the problem to minimize the number of operations required.
