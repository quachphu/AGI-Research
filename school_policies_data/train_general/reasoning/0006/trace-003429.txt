To solve this problem, we need to determine if a given number \( n \) is "almost lucky." A number is considered almost lucky if it can be evenly divided by any lucky number. A lucky number is defined as a positive integer composed exclusively of the digits 4 and 7. 

### Approach
1. **Generate Lucky Numbers**: First, generate all possible lucky numbers up to 3 digits long. This is because the maximum value of \( n \) is 1000, and the largest 3-digit lucky number (777) is less than 1000.
2. **Check Divisibility**: For the given number \( n \), check if it is divisible by any of the generated lucky numbers that are less than or equal to \( n \).

### Solution Code
```python
import itertools

def is_almost_lucky():
    # Generate all possible lucky numbers with up to 3 digits
    lucky_numbers = []
    for length in range(1, 4):  # 1, 2, 3 digits
        for digits in itertools.product('47', repeat=length):
            num = int(''.join(digits))
            lucky_numbers.append(num)
    
    n = int(input())
    for num in lucky_numbers:
        if num > n:
            continue
        if n % num == 0:
            print("YES")
            return
    print("NO")

is_almost_lucky()
```

### Explanation
1. **Generating Lucky Numbers**: Using itertools.product, we generate all combinations of the digits 4 and 7 for lengths 1, 2, and 3. This results in a list of 14 lucky numbers: [4, 7, 44, 47, 74, 77, 444, 447, 474, 477, 744, 747, 774, 777].
2. **Reading Input**: The input number \( n \) is read from standard input.
3. **Checking Divisibility**: For each lucky number that is less than or equal to \( n \), we check if \( n \) is divisible by that number. If any such division is exact, the answer is "YES". If none divide \( n \) exactly, the answer is "NO".

This approach efficiently checks all possible lucky divisors up to the given number \( n \), ensuring correctness within the problem constraints.
