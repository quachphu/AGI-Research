To solve this problem, we need to generate a sequence of numbers that meets specific constraints and minimizes the sum of the sequence. The sequence must have a given GCD, each element must be strictly greater than the GCD, and the sequence must be non-decreasing. The solution must be efficient and handle large values up to \(10^{14}\).

### Approach
1. **Understanding the GCD Constraint**: The GCD of the sequence must be exactly \(g\). This means each element in the sequence can be expressed as \(g \times B_i\) where \(B_i\) is an integer greater than 1. The GCD of all \(B_i\) values must be 1.
2. **Non-Decreasing Sequence**: To ensure the sequence is non-decreasing, the values of \(B_i\) must be non-decreasing.
3. **Minimizing the Sum**: The optimal sequence is found by using the smallest possible values for \(B_i\) while ensuring their GCD is 1. The smallest values that meet these criteria are \(2\) and \(3\). Using \(n-1\) instances of \(2\) and one instance of \(3\) ensures the GCD is 1 and the sum is minimized.

### Solution Code
```python
def solve():
    import sys
    input = sys.stdin.read().split()
    T = int(input[0])
    ptr = 1
    for _ in range(T):
        g = int(input[ptr])
        n = int(input[ptr + 1])
        ptr += 2
        sequence = [2 * g] * (n - 1) + [3 * g]
        print(' '.join(map(str, sequence)))

solve()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints.
2. **Generating the Sequence**: For each test case, the sequence is constructed using \(n-1\) elements of \(2g\) followed by one element of \(3g\). This ensures the sequence is non-decreasing, each element is greater than \(g\), and the GCD of the entire sequence is exactly \(g\).
3. **Output**: The generated sequence is printed in the required format.

This approach efficiently constructs the sequence with minimal computational overhead, ensuring optimal performance even for the upper limits of the input constraints.
