To solve this problem, we need to find the number of beautiful subarrays in a given array. A subarray is considered beautiful if the bitwise XOR of all its elements is at least a given value \( k \). Given the constraints, an efficient approach is necessary to handle large input sizes.

### Approach
1. **Prefix XOR Array**: Compute the prefix XOR array where each element at index \( i \) represents the XOR of all elements from the start of the array up to index \( i \). This allows us to compute the XOR of any subarray \( (l, r) \) as `prefix_xor[r] ^ prefix_xor[l-1]`.
2. **Trie Data Structure**: Use a trie (prefix tree) to store the binary representations of the prefix XOR values. This helps efficiently count how many previous prefix XOR values, when XORed with the current prefix XOR, result in a value greater than or equal to \( k \).
3. **Efficient Querying**: For each current prefix XOR value, traverse the trie to determine how many existing entries in the trie satisfy the condition when XORed with the current value. This traversal is done bit by bit from the most significant bit (MSB) to the least significant bit (LSB).

### Explanation
1. **Trie Structure**: The trie stores each prefix XOR value bit by bit from MSB to LSB. Each node in the trie keeps track of how many times it has been visited, which helps in quickly counting valid subarrays.
2. **Insert Operation**: When inserting a number into the trie, each bit of the number is processed from MSB to LSB, creating nodes as necessary and incrementing the count for each node along the path.
3. **Query Operation**: For each current prefix XOR value, the query function traverses the trie to count how many existing values in the trie, when XORed with the current value, result in a value greater than or equal to \( k \). This is done by comparing each bit of the XOR result with the corresponding bit of \( k \) and maintaining a "tight" state to track if the current path in the trie matches the prefix of \( k \).

This approach efficiently handles the problem constraints with a time complexity of \( O(n \log \text{max_value}) \), making it suitable for large input sizes up to \( 10^6 \).
