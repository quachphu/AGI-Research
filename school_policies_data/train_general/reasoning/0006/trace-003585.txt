To solve this problem, we need to calculate the expected score in a game where each hit contributes to the score based on the square of the length of consecutive hits. The challenge is to efficiently compute this expectation given the probabilities of hitting each shot.

### Approach
1. **Understanding the Problem**: The score is determined by summing the squares of the lengths of consecutive hits. Using the linearity of expectation, we can break down the problem into manageable parts.
2. **Key Insight**: The expected value of the sum of squares of consecutive hits can be decomposed into two parts: the sum of individual hit probabilities and twice the sum of the probabilities of all pairs of consecutive hits.
3. **Dynamic Programming Approach**: Use a dynamic programming approach to efficiently compute the sum of probabilities for all intervals of consecutive hits. This avoids the need for an O(n^2) solution, which is infeasible for large n.

### Solution Code
```python
n = int(input())
p = list(map(float, input().split()))

sum_p = sum(p)
a_prev = 0.0
sum_a = 0.0

for pi in p:
    a_current = pi * (1 + a_prev)
    sum_a += a_current
    a_prev = a_current

S = sum_a - sum_p
expected = sum_p + 2 * S

print("{0:.6f}".format(expected))
```

### Explanation
1. **Sum of Probabilities (sum_p)**: This is the straightforward sum of all individual hit probabilities, representing the expected number of hits.
2. **Dynamic Programming Calculation (sum_a)**: Track the sum of probabilities for all intervals ending at each position. This is done using a dynamic programming variable `a_prev` which keeps track of the cumulative product up to the previous position.
3. **Sum of Consecutive Pairs (S)**: By subtracting the individual probabilities from the cumulative sum, we get the sum of probabilities for all intervals of length at least 2.
4. **Final Expected Value**: Combine the individual hit probabilities and twice the sum of consecutive pairs to get the final expected score, formatted to six decimal places.

This approach efficiently computes the required expectation in O(n) time, making it suitable for large input sizes up to 100,000.
