To solve this problem, we need to determine the winner of a card game between Conan and Agasa, where they take turns removing cards and all cards with a number strictly less than the chosen card. The game ends when a player cannot make a move, and the player who cannot move loses. Both players play optimally.

### Approach
The key insight to solve this problem is based on the parity of the counts of the highest remaining card. The solution can be determined by analyzing the sorted list of card values and their frequencies. The steps are as follows:

1. **Sort the Cards**: First, sort the list of card values in non-decreasing order.
2. **Check Frequencies**: Iterate through the sorted list from the highest value to the lowest. For each value, check its frequency.
3. **Determine Parity**: If the highest value with an odd frequency is found, Conan (the first player) can always win by choosing that value. If all values have even frequencies, Agasa (the second player) will win.

### Solution Code
```python
n = int(input())
a = list(map(int, input().split()))
a_sorted = sorted(a)

current = a_sorted[-1]
count = 1

for num in reversed(a_sorted[:-1]):
    if num == current:
        count += 1
    else:
        if count % 2 == 1:
            print("Conan")
            exit()
        current = num
        count = 1

if count % 2 == 1:
    print("Conan")
else:
    print("Agasa")
```

### Explanation
1. **Sorting the Cards**: The cards are sorted to facilitate the check from the highest to the lowest value.
2. **Frequency Check**: By iterating from the highest value downwards, we check the frequency of each card value. The first occurrence of a value with an odd frequency means Conan can take that card, remove all lower cards, and force Agasa into a losing position.
3. **Parity Check**: If all values have even frequencies, Agasa can mirror Conan's moves, ensuring she always has a move until Conan runs out of moves.

This approach efficiently determines the winner by leveraging the properties of sorted frequencies and parity checks, ensuring optimal play from both participants. The solution runs in O(n log n) time due to sorting, which is efficient for the given problem constraints.
