To solve this problem, we need to determine the number of days within a given period where Arkady's mobile phone account balance becomes negative after the daily payment. The solution involves efficiently processing the days when Arkady tops up his account and calculating the balance changes over intervals between these top-up days.

### Approach
1. **Initialization**: Start with an initial balance of 0 and track the current day.
2. **Process Top-Up Days**: For each top-up day, calculate the balance changes for the days leading up to the top-up day and update the balance accordingly.
3. **Check Balance After Each Top-Up**: After each top-up, adjust the balance and check if it becomes negative.
4. **Handle Remaining Days**: After processing all top-up days, check the remaining days up to the end of the period to determine if the balance goes negative.

### Solution Code
```python
n, p, m = map(int, input().split())
topups = [tuple(map(int, input().split())) for _ in range(n)]

current_balance = 0
current_day = 1
count = 0

for d, t in topups:
    if current_day < d:
        k = d - current_day
        B = current_balance
        if B < 0:
            cnt = k
        else:
            x_min = (B // p) + 1
            if x_min > k:
                cnt = 0
            else:
                cnt = k - x_min + 1
        count += cnt
        current_balance -= k * p
        current_day = d
    # Process day d
    current_balance += t
    current_balance -= p
    if current_balance < 0:
        count += 1
    current_day += 1

# Process remaining days after last topup
if current_day <= m:
    k = m - current_day + 1
    B = current_balance
    if B < 0:
        cnt = k
    else:
        x_min = (B // p) + 1
        if x_min > k:
            cnt = 0
        else:
            cnt = k - x_min + 1
    count += cnt

print(count)
```

### Explanation
1. **Initialization**: We start with `current_balance` set to 0 and `current_day` set to 1. The `count` variable keeps track of the number of days with a negative balance.
2. **Processing Top-Up Days**: For each top-up day `d`, we first handle the days from `current_day` to `d-1`. We calculate how many of these days result in a negative balance using mathematical operations to avoid iterating each day individually.
3. **Update Balance**: After processing the days leading up to the top-up day, we update the balance by adding the top-up amount and subtracting the daily payment. If the balance becomes negative, we increment the count.
4. **Remaining Days**: After all top-up days are processed, we check the remaining days from the last top-up day to the end of the period using the same method to determine negative balance days.

This approach efficiently handles large values of `m` and `n` by avoiding direct iteration over each day, instead using mathematical calculations to determine the number of negative balance days in each interval. This ensures the solution runs in O(n) time complexity, making it suitable for the given problem constraints.
