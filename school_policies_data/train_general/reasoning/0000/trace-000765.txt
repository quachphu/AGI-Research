To solve this problem, we need to balance the load of tasks across multiple servers such that the difference between the most loaded and the least loaded server is minimized. The goal is to determine the minimum number of seconds required to achieve this balance, where each second allows moving one task between any pair of servers.

### Approach
1. **Calculate Total Tasks**: Sum all the tasks across all servers.
2. **Determine Target Load**: Compute the average number of tasks per server (quotient `q` and remainder `r`). This helps in determining the target load for each server. `r` servers will have `q + 1` tasks, and the remaining servers will have `q` tasks.
3. **Sort Tasks**: Sort the list of tasks to facilitate efficient calculation of the excess tasks that need to be moved.
4. **Compute Excess Tasks**: Calculate the total number of excess tasks that need to be moved from servers with more than the target load to those with less. This is done by iterating through the sorted list and summing the excess tasks for servers that exceed their target load.

### Solution Code
```python
n = int(input())
m = list(map(int, input().split()))
total = sum(m)
q, r = divmod(total, n)
m.sort()

result = 0
# Process the first (n - r) elements which should be at most q
for i in range(n - r):
    if m[i] > q:
        result += m[i] - q

# Process the remaining r elements which should be at most q + 1
for i in range(n - r, n):
    if m[i] > q + 1:
        result += m[i] - (q + 1)

print(result)
```

### Explanation
1. **Input Reading**: The number of servers `n` and their respective tasks `m` are read from standard input.
2. **Total Tasks Calculation**: The total number of tasks is computed to determine the average load per server.
3. **Target Load Determination**: Using integer division and modulo operations, we determine the target load for each server. `q` is the base target load, and `r` servers will have `q + 1` tasks.
4. **Sorting**: The list of tasks is sorted to facilitate the efficient calculation of excess tasks.
5. **Excess Calculation**: For the first `n - r` servers (targeting `q` tasks), any server with more than `q` tasks contributes its excess. For the remaining `r` servers (targeting `q + 1` tasks), any server with more than `q + 1` tasks contributes its excess. The sum of these excess values gives the minimum number of seconds required to balance the load.

This approach ensures that we efficiently calculate the minimum moves required by focusing on the excess tasks from over-loaded servers, leveraging sorting and mathematical insights to achieve an optimal solution.
