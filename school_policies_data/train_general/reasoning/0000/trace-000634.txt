To solve this problem, we need to determine if a number represented in a given base is even or odd. The solution leverages modular arithmetic to efficiently compute the result without explicitly constructing the large number.

### Approach
1. **Understanding Parity**: The parity (even or odd) of a number depends solely on its remainder when divided by 2.
2. **Base Analysis**:
   - **Even Base**: If the base (b) is even, any number in this base will have its parity determined by the last digit. This is because all higher place values (which are powers of the even base) contribute even values, leaving only the last digit to affect the parity.
   - **Odd Base**: If the base (b) is odd, the parity of the number is determined by the sum of the parities of all its digits. This is because powers of an odd base remain odd, and the sum of the digits' parities modulo 2 gives the overall parity.

### Solution Code
```python
import sys

def main():
    b, k = map(int, sys.stdin.readline().split())
    digits = list(map(int, sys.stdin.readline().split()))
    if b % 2 == 0:
        last = digits[-1]
        print("even" if last % 2 == 0 else "odd")
    else:
        total = sum(d % 2 for d in digits)
        print("even" if total % 2 == 0 else "odd")

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The first line of input contains the base (b) and the number of digits (k). The second line contains the digits of the number.
2. **Check Base Parity**:
   - **Even Base**: Directly check the parity of the last digit. If the last digit is even, the number is even; otherwise, it is odd.
   - **Odd Base**: Sum the parities of all digits. If the sum is even, the number is even; otherwise, it is odd.
   
This approach ensures that we efficiently determine the parity without constructing the potentially very large number, leading to an optimal O(k) time complexity, which is suitable even for the upper constraint of k (100,000).
