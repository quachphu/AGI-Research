To solve this problem, we need to generate a Fibonacci-like sequence starting with two given numbers and determine the nth element of the sequence. The solution involves iteratively computing each subsequent element based on the sum of the two preceding elements.

### Approach
1. **Input Handling**: Read the first two elements of the sequence (a and b) and the position (n) of the element to be determined.
2. **Direct Cases**: If the position requested is 1 or 2, directly return the first or second element respectively.
3. **Iterative Calculation**: For positions 3 and beyond, iteratively compute each subsequent element by summing the previous two elements. Update the previous two elements at each step to reflect the most recent values.
4. **Output the Result**: After computing up to the nth element, print the result.

### Solution Code
```python
def main():
    a, b, n = map(int, input().split())
    if n == 1:
        print(a)
    elif n == 2:
        print(b)
    else:
        prev_prev, prev = a, b
        for _ in range(3, n + 1):
            current = prev_prev + prev
            prev_prev, prev = prev, current
        print(current)

main()
```

### Explanation
1. **Reading Input**: The input is read as three integers where the first two integers are the starting elements of the sequence, and the third integer is the position of the element to be determined.
2. **Handling Base Cases**: If the position is 1 or 2, the result is simply the first or second element respectively, which are directly printed.
3. **Iterative Calculation**: For positions greater than 2, we initialize the first two elements and iterate from the third position up to the desired position. In each iteration, the current element is calculated as the sum of the previous two elements. The previous elements are updated to the next elements in the sequence.
4. **Output**: After completing the iterations, the current element at the nth position is printed.

This approach efficiently computes the nth element with a time complexity of O(n), which is optimal for this problem as each element up to n is computed exactly once.
