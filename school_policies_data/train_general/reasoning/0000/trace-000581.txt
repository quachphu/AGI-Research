To solve this problem, we need to find the minimum possible integer that can be formed by swapping adjacent digits of different parity (even and odd). The key insight is that even digits can only be swapped with odd digits, preserving their relative order among themselves, and similarly for odd digits. Thus, the problem reduces to merging two sequences (evens and odds) while maintaining their internal order to form the smallest possible integer.

### Approach
1. **Split Digits**: Separate the digits of the input number into two lists: one for even digits and one for odd digits, preserving their original order.
2. **Merge Lists**: Merge these two lists into a single list by iteratively choosing the smallest possible next digit from the front of either the evens or odds list. This ensures the smallest lexicographical order.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    t = int(input[0])
    cases = input[1:t+1]
    for s in cases:
        evens = []
        odds = []
        for c in s:
            if int(c) % 2 == 0:
                evens.append(c)
            else:
                odds.append(c)
        res = []
        i = j = 0
        while i < len(evens) and j < len(odds):
            if evens[i] < odds[j]:
                res.append(evens[i])
                i += 1
            else:
                res.append(odds[j])
                j += 1
        res += evens[i:]
        res += odds[j:]
        print(''.join(res))

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints. The first value is the number of test cases, followed by each test case as a string.
2. **Splitting Digits**: Each digit is checked for evenness and added to the respective list (evens or odds) while preserving their order.
3. **Merging Lists**: Using two pointers, we compare the current elements of the evens and odds lists. The smaller digit is added to the result list first. This process continues until all elements from both lists are exhausted, ensuring the smallest possible integer is formed by maintaining the relative order of evens and odds.

This approach efficiently handles the constraints and ensures the solution is optimal, with a time complexity of O(n) per test case, where n is the length of the input string. This is feasible even for the upper limits of the problem constraints.
