To solve this problem, we need to find the length of the longest increasing subsequence (LIS) in a given sequence of integers. The solution must efficiently handle sequences up to 100,000 elements long.

### Approach
The optimal approach to solve this problem in O(n log n) time complexity involves using a dynamic list to maintain the smallest possible tail values for increasing subsequences of various lengths. Here's the detailed approach:

1. **Dynamic List (tails)**: Maintain a list where each element at index `i` represents the smallest possible tail value of all increasing subsequences of length `i+1`.
2. **Binary Search**: For each number in the sequence, use binary search to find the position in the `tails` list where this number can replace an existing element to maintain the smallest possible tail values. This ensures the list remains sorted.
3. **Update List**: If the number is larger than all elements in the `tails` list, append it. Otherwise, replace the first element in the `tails` list that is greater than or equal to the current number. This helps in maintaining the smallest possible tail values for potential longer subsequences.

### Solution Code
```python
import bisect

def find_lis_length():
    n = int(input())
    a = [int(input()) for _ in range(n)]
    tails = []
    for num in a:
        idx = bisect.bisect_left(tails, num)
        if idx == len(tails):
            tails.append(num)
        else:
            tails[idx] = num
    print(len(tails))

find_lis_length()
```

### Explanation
1. **Reading Input**: The input is read as an integer `n` followed by `n` integers forming the sequence.
2. **Initialization**: An empty list `tails` is initialized to keep track of the smallest tail values of increasing subsequences.
3. **Processing Each Element**:
   - For each element in the sequence, determine its position in the `tails` list using binary search (`bisect_left`).
   - If the element is larger than all elements in `tails`, it extends the longest subsequence, so we append it.
   - If not, replace the first element in `tails` that is greater than or equal to the current element to maintain the smallest possible tail value for that subsequence length.
4. **Result**: The length of the `tails` list after processing all elements gives the length of the longest increasing subsequence.

This approach ensures that each element is processed in logarithmic time relative to the current length of the `tails` list, leading to an overall time complexity of O(n log n), which is efficient for large input sizes.
