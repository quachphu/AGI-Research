To solve this problem, we need to determine the number of ways to paint `n` bricks using `m` colors such that exactly `k` bricks have a different color from their immediate left neighbor. The result should be computed modulo 998244353.

### Approach
The problem can be efficiently solved using dynamic programming (DP). The key idea is to track two states for each position and each possible number of color changes:
1. `same[i][j]`: The number of ways to paint the first `i` bricks with `j` changes where the `i-th` brick is the same color as the `(i-1)-th` brick.
2. `diff[i][j]`: The number of ways to paint the first `i` bricks with `j` changes where the `i-th` brick is a different color from the `(i-1)-th` brick.

#### Transitions:
1. **Same Color Transition**: If the `i-th` brick is the same as the `(i-1)-th` brick, the number of ways is the sum of the ways where the `(i-1)-th` brick was either the same as the `(i-2)-th` brick or different.
2. **Different Color Transition**: If the `i-th` brick is different from the `(i-1)-th` brick, the number of ways is derived from all previous ways where the `(i-1)-th` brick could be either the same or different, multiplied by `(m-1)` possible color choices.

### Solution Code
```python
n, m, k = map(int, input().split())
mod = 998244353

if k > n - 1:
    print(0)
    exit()

# Initialize DP tables
same = [[0] * (k + 1) for _ in range(n + 1)]
diff = [[0] * (k + 1) for _ in range(n + 1)]

same[1][0] = m % mod  # First brick can be any color, no changes possible

for i in range(2, n + 1):
    max_j = min(k, i - 1)
    # Update same[i][j] for all j in 0..max_j
    for j in range(0, max_j + 1):
        same[i][j] = (same[i - 1][j] + diff[i - 1][j]) % mod
    # Update diff[i][j] for j starting from 1
    for j in range(1, max_j + 1):
        prev_j = j - 1
        sum_prev = (same[i - 1][prev_j] + diff[i - 1][prev_j]) % mod
        diff[i][j] = (sum_prev * (m - 1)) % mod

ans = (same[n][k] + diff[n][k]) % mod
print(ans)
```

### Explanation
1. **Initialization**: The first brick can be painted in `m` ways, which initializes `same[1][0] = m`.
2. **Dynamic Programming Transitions**:
   - For each subsequent brick `i`, compute the number of ways to paint up to `i` bricks with `j` changes.
   - Update `same[i][j]` by considering both cases where the previous brick was the same or different.
   - Update `diff[i][j]` by considering transitions from previous states where a new color change is introduced.
3. **Result Calculation**: The final result is the sum of ways where the last brick is either the same or different, modulo 998244353.

This approach efficiently computes the number of valid colorings using dynamic programming with a time complexity of O(n*k), which is feasible given the problem constraints.
