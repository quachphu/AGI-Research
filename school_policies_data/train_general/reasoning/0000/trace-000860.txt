To solve this problem, we need to determine the number of days where the price of the berPhone is considered "bad". A day is considered bad if there exists any subsequent day with a lower price. The solution must efficiently handle up to 10,000 test cases with a combined total of 150,000 days.

### Approach
1. **Problem Analysis**: For each day, we need to check if there is any subsequent day with a lower price. A naive approach checking each subsequent day for every day would be too slow (O(n^2)). Instead, we use a more efficient approach by precomputing the minimum price from the end of the list to the start.

2. **Efficient Minimum Calculation**: We compute an array `min_after` where `min_after[i]` stores the minimum price encountered from day `i+1` to the end of the list. This allows us to determine in O(1) time if a day is bad by checking if the price on that day is greater than `min_after[i]`.

3. **Algorithm**:
   - For each test case, read the number of days and the list of prices.
   - Traverse the list from the end to the start to compute the `min_after` array.
   - Count the number of days where the price is greater than the minimum price in the subsequent days.

def main():
    import sys
    input = sys.stdin.read().split()
    ptr = 0
    t = int(input[ptr])
    ptr += 1
    for _ in range(t):
        n = int(input[ptr])
        ptr += 1
        a = list(map(int, input[ptr:ptr + n]))
        ptr += n
        if n == 0:
            print(0)
            continue
        min_after = [0] * n
        current_min = float('inf')
        for i in reversed(range(n)):
            min_after[i] = current_min
            current_min = min(current_min, a[i])
        count = 0
        for i in range(n):
            if a[i] > min_after[i]:
                count += 1
        print(count)

if __name__ == "__main__":

1. **Reading Input**: The input is read all at once for efficiency, especially given the large constraints. We use a pointer to traverse the input data sequentially.
2. **Computing `min_after` Array**: We traverse the list from the end to the start, maintaining a running minimum of the prices encountered. This allows us to efficiently fill the `min_after` array where each entry at index `i` contains the minimum price from index `i+1` to the end.
3. **Counting Bad Days**: For each day, we check if the price is greater than the minimum price in subsequent days (using the `min_after` array). If it is, we increment our count of bad days.
