To solve this problem, we need to determine the minimum energy the robot spends to collect all items using either the left or right hand, considering the extra energy cost if the same hand is used consecutively. The optimal strategy involves balancing the number of items taken from each side to minimize the total energy expenditure.

### Approach
1. **Prefix and Suffix Sums**: Compute prefix sums for the weights of items taken from the left and suffix sums for the weights of items taken from the right. This allows efficient calculation of the energy cost for any number of items taken from either side.
2. **Iterate Over Possible Splits**: For each possible number of items taken from the left (k), calculate the remaining items taken from the right (n - k). Compute the total energy cost for each split, including the extra penalties for consecutive same-hand usage.
3. **Calculate Penalties**: Determine the extra penalties based on the difference between the number of items taken from each side. If one side is used more than the other by more than one, add the corresponding penalty for each extra consecutive use.

### Solution Code
```python
n, l, r, Ql, Qr = map(int, input().split())
w = list(map(int, input().split()))

prefix = [0] * (n + 1)
for i in range(1, n + 1):
    prefix[i] = prefix[i-1] + w[i-1]

suffix = [0] * (n + 1)
for i in range(1, n + 1):
    suffix[i] = suffix[i-1] + w[-i]

min_total = float('inf')

for k in range(0, n + 1):
    m = n - k
    sum_l = prefix[k] * l
    sum_r = suffix[m] * r
    if k > m:
        extra = (k - (m + 1)) * Ql
    elif m > k:
        extra = (m - (k + 1)) * Qr
    else:
        extra = 0
    total = sum_l + sum_r + extra
    if total < min_total:
        min_total = total

print(min_total)
```

### Explanation
1. **Prefix and Suffix Sums**: The prefix sum array `prefix` stores cumulative weights of items taken from the left, while the suffix sum array `suffix` stores cumulative weights of items taken from the right. This allows quick calculation of the energy cost for any number of items taken from either side.
2. **Energy Calculation**: For each possible split of items taken from the left (`k`) and right (`n - k`), compute the base energy cost using the prefix and suffix sums. Adjust the total energy by adding penalties for consecutive same-hand usage if the number of items from one side exceeds the other by more than one.
3. **Optimal Check**: Iterate through all possible splits (from taking all items from the left to all from the right) and track the minimum energy expenditure.

This approach ensures we efficiently compute the minimum energy using a linear scan of possible splits, making the solution both optimal and efficient with a time complexity of O(n).
