To solve this problem, we need to determine the minimum possible sum of the number of marks strictly below the water level (di) over all days. The key insight is to minimize the sum of di by efficiently managing the marks added each day, ensuring that we either reuse existing marks or add new ones in a way that optimally balances future requirements.

### Approach
1. **Reverse Processing for Requirements**: Compute the minimum number of marks required before each day to handle future days efficiently. This is done by processing the days in reverse order to determine the necessary constraints for each day.
2. **Dynamic Programming for Required Marks**: For each day, calculate the minimum number of marks required to either reuse an existing mark or add a new one, considering future days' needs.
3. **Forward Simulation**: Using the precomputed requirements, simulate each day forward, deciding whether to reuse an existing mark or add a new one based on the constraints derived from the reverse processing.

### Solution Code
```python
n = int(input())
m = list(map(int, input().split()))
required = [0] * (n + 1)

for i in range(n - 1, -1, -1):
    add_option = max(required[i + 1] - 1, m[i])
    reuse_option = max(required[i + 1], m[i] + 1)
    required[i] = min(add_option, reuse_option)

sum_T = 0
T_prev = 0
for i in range(n):
    mi = m[i]
    if T_prev >= mi + 1 and T_prev >= required[i + 1]:
        sum_T += T_prev
    else:
        sum_T += T_prev + 1
        T_prev += 1

sum_di = sum_T - sum(m) - n
print(sum_di)
```

### Explanation
1. **Reverse Processing**: We start from the last day and move backwards to compute the minimum number of marks required (`required` array) before each day. This helps us ensure that each day's constraints are met while considering future days.
2. **Dynamic Programming**: For each day, we calculate two options:
   - **Add Option**: The minimum marks needed if we add a new mark on the current day.
   - **Reuse Option**: The minimum marks needed if we reuse an existing mark on the current day.
   We then take the minimum of these two options to determine the required marks for the current day.
3. **Forward Simulation**: Using the precomputed `required` array, we simulate each day forward. For each day, we check if we can reuse an existing mark or if we need to add a new one. This ensures that we maintain the minimum number of marks required while efficiently managing the sum of marks.

This approach ensures that we minimize the total number of marks (sum_T), which directly translates to minimizing the sum of di values. The complexity of this solution is O(n), making it efficient for large inputs up to 100,000 days.
