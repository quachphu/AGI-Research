To solve this problem, we need to compute the sum of the number of connected components in a tree for all possible ranges of vertex values. The tree is structured as a linear chain, and each vertex has a value. The key insight is to efficiently calculate the contributions of each vertex and edge to the total sum without iterating through all possible ranges explicitly.

### Approach
1. **Sum of Nodes Contribution**: Each vertex contributes to the sum based on how many intervals include its value. This can be calculated as the product of the number of valid starting points (l) and ending points (r) for the intervals that include the vertex's value.
2. **Sum of Edges Contribution**: Each edge (between consecutive vertices) contributes negatively to the sum based on how many intervals include both vertices' values. This is determined by the product of valid starting and ending points for intervals that include both values.

### Solution Code
```python
n = int(input())
a = list(map(int, input().split()))
sum_nodes = 0
for v in a:
    sum_nodes += v * (n - v + 1)
sum_edges = 0
for i in range(n - 1):
    ai = a[i]
    aj = a[i + 1]
    mn = min(ai, aj)
    mx = max(ai, aj)
    sum_edges += mn * (n - mx + 1)
print(sum_nodes - sum_edges)
```

### Explanation
1. **Sum of Nodes Contribution**: For each vertex with value `v`, the number of intervals `[l, r]` that include `v` is calculated as `v * (n - v + 1)`. This is because `l` can range from 1 to `v` and `r` can range from `v` to `n`.
2. **Sum of Edges Contribution**: For each edge between consecutive vertices with values `a` and `b`, the number of intervals `[l, r]` that include both values is calculated as `min(a, b) * (n - max(a, b) + 1)`. This is because `l` must be at most the smaller value and `r` must be at least the larger value.

By subtracting the sum of edges' contributions from the sum of nodes' contributions, we efficiently compute the required result in linear time, making the solution suitable for large inputs up to 100,000 vertices.
