To solve this problem, we need to determine the minimum number of packets required to distribute `n` coins such that any amount from 1 to `n` can be formed using a subset of these packets. Each packet can be used only once in forming a particular amount, but can be reused for different amounts.

### Approach
The key insight here is to use a greedy algorithm to construct the packets. The strategy is to build packets in such a way that each new packet allows us to cover a larger range of numbers up to `n`. The approach involves:
1. Starting with the smallest possible packet (1 coin).
2. Each subsequent packet is chosen to be as large as possible, but not exceeding the sum of all previous packets plus 1. This ensures that we can form all numbers up to the sum of the packets so far.
3. Continue this process until the total sum of the packets equals `n`.

This method ensures that each new packet maximizes the range of numbers we can form, leading to the minimum number of packets required.

### Solution Code
```python
def minimal_packets():
    n = int(input())
    sum_so_far = 0
    count = 0
    while sum_so_far < n:
        next_p = min(sum_so_far + 1, n - sum_so_far)
        sum_so_far += next_p
        count += 1
    print(count)

minimal_packets()
```

### Explanation
1. **Initialization**: Start with `sum_so_far` set to 0 and `count` set to 0.
2. **Loop Until Total Sum Reaches `n`**: While the sum of the packets formed so far is less than `n`, determine the next packet size.
3. **Determine Next Packet Size**: The next packet size is the minimum of `sum_so_far + 1` (to ensure we can form the next consecutive number) and the remaining coins needed to reach `n`.
4. **Update Sum and Count**: Add the next packet size to `sum_so_far` and increment the packet count.
5. **Output the Result**: Once the loop exits, the count will be the minimum number of packets required.

This approach efficiently constructs the packets in a way that each new packet extends the range of formable numbers as much as possible, ensuring the minimal number of packets are used. The algorithm runs in O(log n) time complexity, making it suitable for very large values of `n` up to 10^9.
