To solve this problem, we need to convert all occurrences of the pointer operator "->" in a given code snippet to the dot operator ".", but only when they appear in the code part and not within comments. Comments are defined as any text following "//" on the same line.

### Approach
1. **Input Reading**: Read each line of input code.
2. **Splitting Code and Comments**: For each line, determine if there is a comment by checking for the presence of "//". If found, split the line into two parts: the code part (before "//") and the comment part (from "//" onwards).
3. **Replacing Operators**: Replace all occurrences of "->" with "." in the code part of the line.
4. **Reconstructing Lines**: Combine the modified code part with the unchanged comment part to form the new line.
5. **Output**: Print each processed line to produce the transformed code.

### Solution Code
```python
import sys

def process_code():
    for line in sys.stdin:
        line = line.rstrip('\n')  # Preserve original line endings except newline
        split_pos = line.find('//')
        if split_pos == -1:
            code_part = line
            comment_part = ''
        else:
            code_part = line[:split_pos]
            comment_part = line[split_pos:]
        modified_code = code_part.replace('->', '.')
        new_line = modified_code + comment_part
        print(new_line)

process_code()
```

### Explanation
1. **Reading Input**: The function reads each line from standard input.
2. **Splitting Lines**: Each line is split into a code part and a comment part based on the first occurrence of "//". If "//" is not found, the entire line is treated as code.
3. **Replacing Operators**: The code part is processed to replace all instances of "->" with ".", ensuring that only the code (not comments) is modified.
4. **Reconstructing Lines**: The modified code part is combined with the original comment part to form the final line, which is then printed.

This approach efficiently processes each line to ensure that the pointer operators are correctly replaced outside of comments, adhering to the problem constraints and requirements.
