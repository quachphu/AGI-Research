To solve this problem, we need to efficiently handle two types of queries on a sequence initialized with values from 1 to N. The queries involve either swapping two adjacent sequences at a given boundary or retrieving the value at a specific position. Given the constraints, a direct simulation approach is infeasible, so we need an optimized solution.

### Approach
The key insight is to recognize that each swap operation can be interpreted as a left rotation of the array. By maintaining a cumulative rotation offset, we can efficiently compute the effect of multiple swaps. Each swap at position `k` effectively rotates the array left by `k` positions. The total rotation offset is the sum of all such `k` values modulo `N`. For each query to retrieve the value at position `k`, we compute the original index using the cumulative rotation offset.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    idx = 0
    N = int(input[idx])
    idx += 1
    Q = int(input[idx])
    idx += 1
    total_rotation = 0
    for _ in range(Q):
        t = int(input[idx])
        idx += 1
        k = int(input[idx])
        idx += 1
        if t == 1:
            total_rotation += k
            total_rotation %= N
        else:
            res = (k - 1 + total_rotation) % N + 1
            print(res)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input:** The input is read in one go for efficiency, especially given the large possible size of Q.
2. **Tracking Rotation:** The `total_rotation` variable keeps track of the cumulative effect of all swap operations. Each swap at position `k` adds `k` to `total_rotation`, modulo `N` to handle wrap-around.
3. **Handling Queries:** For each swap query, update the cumulative rotation. For each retrieval query, compute the original index using the formula `(k - 1 + total_rotation) % N + 1`, which adjusts the current position by the cumulative rotation to find the original value.

This approach ensures that each operation (swap or retrieval) is handled in constant time, making the solution efficient even for the upper constraint limits.
