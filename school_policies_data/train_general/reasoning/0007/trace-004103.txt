To solve this problem, we need to efficiently track the maximum sum of contiguous non-destroyed elements in an array after each element is destroyed in a given order. The solution involves processing the destruction order in reverse and using a Disjoint Set Union (DSU) data structure to manage merging and tracking sums of contiguous segments.

### Approach
1. **Reverse Processing**: Instead of destroying elements one by one, we simulate the process by adding elements back in reverse order of their destruction. This allows us to efficiently merge segments and track their sums using DSU.
2. **Union-Find Data Structure**: We use DSU to manage the merging of segments. Each element, when added back, can merge with its left and right neighbors if they are already added (alive). This helps in maintaining the sum of the contiguous segment efficiently.
3. **Tracking Maximum Sum**: After each addition, we update the maximum sum of contiguous segments and store these values. Finally, we reverse the stored results to match the original destruction order.

### Solution Code
```python
import sys
sys.setrecursionlimit(1 << 25)

def main():
    import sys
    input = sys.stdin.read
    data = input().split()
    
    n = int(data[0])
    a = list(map(int, data[1:n+1]))
    d = list(map(lambda x: int(x)-1, data[n+1:2*n+1]))
    
    add_order = reversed(d)
    
    parent = list(range(n))
    sum_ = [0] * n
    size = [1] * n
    alive = [False] * n
    max_sum = 0
    answers = [0]
    
    def find(u):
        while parent[u] != u:
            parent[u] = parent[parent[u]]  # Path compression
            u = parent[u]
        return u
    
    for pos in add_order:
        if alive[pos]:
            answers.append(max_sum)
            continue
        alive[pos] = True
        parent[pos] = pos
        sum_[pos] = a[pos]
        current_sum = a[pos]
        
        # Merge left neighbor
        if pos > 0 and alive[pos-1]:
            root_left = find(pos-1)
            root_current = find(pos)
            if root_left != root_current:
                if size[root_left] > size[root_current]:
                    parent[root_current] = root_left
                    sum_[root_left] += sum_[root_current]
                    size[root_left] += size[root_current]
                else:
                    parent[root_left] = root_current
                    sum_[root_current] += sum_[root_left]
                    size[root_current] += size[root_left]
        
        # Merge right neighbor
        if pos < n-1 and alive[pos+1]:
            root_current = find(pos)
            root_right = find(pos+1)
            if root_current != root_right:
                if size[root_right] > size[root_current]:
                    parent[root_current] = root_right
                    sum_[root_right] += sum_[root_current]
                    size[root_right] += size[root_current]
                else:
                    parent[root_right] = root_current
                    sum_[root_current] += sum_[root_right]
                    size[root_current] += size[root_right]
        
        # Update max_sum
        root = find(pos)
        current_total = sum_[root]
        if current_total > max_sum:
            max_sum = current_total
        answers.append(max_sum)
    
    reversed_answers = answers[::-1]
    for i in range(n):
        print(reversed_answers[i+1])

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the constraints.
2. **Reverse Order Processing**: The destruction order is processed in reverse to simulate adding elements back to the array.
3. **Union-Find Operations**: The `find` function uses path compression to keep the tree flat, ensuring efficient lookups. When merging segments, the larger segment is chosen as the parent to maintain balance.
4. **Tracking Sums**: Each time an element is added back, we check its neighbors and merge segments if possible, updating the sum of the resulting segment.
5. **Output**: The results are collected in reverse order and then reversed to provide the correct output for each destruction step.

This approach ensures that each operation (union and find) is nearly constant time, making the solution efficient even for large input sizes.
