To solve this problem, we need to determine the minimum number of stones to remove from a row such that no two neighboring stones have the same color. The solution involves analyzing consecutive stones and removing duplicates to ensure neighboring stones are different.

### Approach
1. **Problem Analysis**: The key insight is that any consecutive sequence of stones with the same color needs to be reduced to a single stone. For example, a sequence like "RRR" must be reduced to a single "R" to avoid consecutive duplicates.
2. **Group Consecutive Stones**: Iterate through the string and group consecutive stones of the same color. For each group of length `m`, we need to remove `m - 1` stones to leave just one stone.
3. **Sum Removals**: Sum the number of removals needed for each group to get the total number of stones to remove.

### Solution Code
```python
def main():
    import sys
    n = int(sys.stdin.readline())
    s = sys.stdin.readline().strip()
    
    if n <= 1:
        print(0)
        return
    
    total = 0
    prev = s[0]
    current_len = 1
    
    for c in s[1:]:
        if c == prev:
            current_len += 1
        else:
            total += current_len - 1
            prev = c
            current_len = 1
    
    total += current_len - 1
    print(total)

main()
```

### Explanation
1. **Reading Input**: The input consists of an integer `n` (number of stones) and a string `s` representing the colors of the stones.
2. **Edge Case Handling**: If there is 0 or 1 stone, no removals are needed, so we directly output 0.
3. **Iterate Through Stones**: We iterate through the string starting from the second stone. For each stone, we check if it is the same as the previous one. If it is, we increase the current group length. If it is different, we calculate the removals needed for the current group and reset the group.
4. **Final Group Calculation**: After the loop, we add the removals needed for the last group of stones.
5. **Output Result**: The total number of removals is printed.

This approach efficiently processes each stone in linear time, ensuring optimal performance even for the upper constraint of 50 stones.
