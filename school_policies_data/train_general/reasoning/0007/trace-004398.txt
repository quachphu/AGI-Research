To solve this problem, we need to compute the sum of total scores for all possible subsets of rolls made by Limak, considering that each subset's score is calculated based on the original order of the rolls. The solution must be efficient to handle up to 200,000 rolls.

### Approach
1. **Understanding Contribution**: Each roll's contribution to the total score depends on its position in the subset. For a roll at position `i` in the original list, its position in any subset is determined by the number of elements before `i` that are included in the subset plus one.
2. **Modular Arithmetic**: Given the constraints, we need to compute results modulo \(10^9 + 7\). This involves efficiently calculating powers and their modular inverses.
3. **Efficient Calculation**: For each roll, we compute its contribution across all subsets using the formula derived from combinatorial analysis. The key insight is that each roll's contribution can be expressed in terms of powers of 2 and modular inverses.

### Solution Code
```python
MOD = 10**9 + 7

n = int(input())
a = list(map(int, input().split()))

pow_2n = pow(2, n, MOD)
inv4 = pow(4, MOD - 2, MOD)
factor = (pow_2n * inv4) % MOD

result = 0
for idx in range(n):
    i = idx + 1
    term = a[idx] * (i + 1) % MOD
    term = term * factor % MOD
    result = (result + term) % MOD

print(result)
```

### Explanation
1. **Modular Exponentiation**: We compute \(2^N \mod (10^9 + 7)\) using Python's built-in `pow` function with three arguments for efficient modular exponentiation.
2. **Modular Inverse**: The inverse of 4 modulo \(10^9 + 7\) is computed using Fermat's Little Theorem, which states that the inverse of a number `a` modulo `p` (a prime) is `a^(p-2) % p`.
3. **Factor Calculation**: The factor `2^(N-2) % MOD` is derived as \((2^N \mod MOD) \times (4^{-1} \mod MOD)\).
4. **Summing Contributions**: For each element in the list, compute its contribution considering its position and the precomputed factor, then sum these contributions modulo \(10^9 + 7\).

This approach ensures that we efficiently compute the required sum in linear time, making it feasible even for the upper constraint of 200,000 rolls.
