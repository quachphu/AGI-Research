To solve this problem, we need to split a list of cards into two non-empty parts such that the absolute difference between the sums of the two parts is minimized. The solution involves using prefix sums to efficiently compute the sums of all possible splits and determine the minimum difference.

### Approach
1. **Prefix Sum Calculation**: Compute the prefix sums of the list to quickly determine the sum of any subarray starting from the beginning. This allows us to compute the sum of the first k elements in constant time.
2. **Total Sum Calculation**: Calculate the total sum of all elements in the list. This helps in determining the sum of the remaining elements after splitting at any point k.
3. **Iterate and Compute Differences**: For each possible split point k (from 1 to N-1), compute the absolute difference between twice the prefix sum up to k and the total sum. Track the minimum difference encountered during these iterations.

### Solution Code
```python
n = int(input())
a = list(map(int, input().split()))

prefix = [0] * (n + 1)
for i in range(1, n + 1):
    prefix[i] = prefix[i - 1] + a[i - 1]

total = prefix[n]
min_diff = float('inf')

for k in range(1, n):
    current = abs(2 * prefix[k] - total)
    if current < min_diff:
        min_diff = current

print(min_diff)
```

### Explanation
1. **Prefix Sum Calculation**: The prefix array is constructed such that `prefix[i]` holds the sum of the first i elements of the input list. This allows us to quickly access the sum of any initial segment of the list.
2. **Total Sum**: The total sum of all elements is derived from the last element of the prefix array, which is the sum of the entire list.
3. **Iterate Over Possible Splits**: For each valid split point k (from 1 to N-1), compute the absolute difference between twice the sum of the first k elements and the total sum. This difference is minimized to find the optimal split.

This approach ensures that we efficiently compute the required sums using prefix sums, leading to an O(N) time complexity, which is optimal for handling the upper constraint of N up to 200,000.
