To solve this problem, we need to determine the K-th character in a string that undergoes exponential growth over a very large number of days. Each digit in the string (except '1') is replaced by multiple copies of itself each day. Given the constraints, directly simulating the string's growth is impossible, so we need an efficient approach to determine the K-th character without explicit construction.

### Approach
1. **Understanding Exponential Growth**: Each digit (from '2' to '9') grows exponentially each day. For example, '2' becomes '22', '3' becomes '333', and so on. After a very large number of days (5e15), the length of each non-'1' digit's expansion becomes astronomically large.
2. **Key Insight**: The K-th character will be determined by the first non-'1' digit in the original string. This is because the expansion of any non-'1' digit after 5e15 days will be so large that it will exceed any practical value of K (up to 1e18). If K falls within the expansion of a non-'1' digit, that digit is the answer. If K falls within the positions occupied by '1's, then the answer is '1'.

### Solution Code
```python
def find_kth_character():
    import sys
    S, K = sys.stdin.read().split()
    K = int(K)
    sum = 0
    for c in S:
        if c == '1':
            if sum + 1 >= K:
                print('1')
                return
            else:
                sum += 1
        else:
            if sum < K:
                print(c)
                return
            else:
                continue
    # The loop covers all cases, so this return is just a fallback
    print('1')

find_kth_character()
```

### Explanation
1. **Reading Input**: The input consists of the string `S` and the integer `K`.
2. **Iterating Through Characters**: We iterate through each character in `S` while maintaining a cumulative sum of the lengths contributed by each character processed so far.
3. **Handling '1'**: For each '1', we check if adding its contribution (which is always 1) to the cumulative sum reaches or exceeds K. If so, the answer is '1'.
4. **Handling Non-'1' Characters**: For any non-'1' character, if the cumulative sum is less than K, the K-th character must be within the expansion of this character. Since the expansion is exponentially large, we immediately return this character as the answer.

This approach efficiently determines the K-th character by leveraging the exponential growth properties of the digits, avoiding the need for explicit string construction.
