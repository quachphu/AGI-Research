To solve this problem, we need to determine the shortest possible length of the longest log after making at most K cuts, and then round the result up to the nearest integer. The solution involves using a binary search approach to efficiently find the optimal maximum length.

### Approach
1. **Binary Search on Maximum Length**: We perform a binary search on the possible values of the maximum length of the logs after cutting. The search range is between 1 (minimum possible length) and the maximum initial log length (since without any cuts, the maximum length remains the same).
2. **Feasibility Check**: For each candidate maximum length during the binary search, we check if it's possible to cut all logs such that each piece is at most this candidate length using at most K cuts. This is done by calculating the required number of cuts for each log and summing them up.
3. **Rounding Up**: Once the optimal length is found using binary search, we round it up to the nearest integer to get the final result.

### Solution Code
```python
import math

def main():
    import sys
    input = sys.stdin.read().split()
    N = int(input[0])
    K = int(input[1])
    A = list(map(int, input[2:2+N]))
    max_A = max(A)
    
    if K == 0:
        print(max_A)
        return
    
    low = 1e-9
    high = max_A
    
    for _ in range(100):
        mid = (low + high) / 2
        total_cuts = 0
        for a in A:
            # Calculate the number of cuts needed for each log
            # Equivalent to ceil(a / mid) - 1
            cuts = (a + mid - 1) // mid
            total_cuts += cuts - 1
            if total_cuts > K:
                break  # Early exit if we exceed K
        
        if total_cuts <= K:
            high = mid  # Try for a smaller maximum length
        else:
            low = mid  # Need to increase the maximum length
    
    print(math.ceil(high))

if __name__ == '__main__':
    main()
```

### Explanation
1. **Reading Input**: The input is read and parsed to get the number of logs (N), the maximum number of cuts allowed (K), and the list of log lengths.
2. **Handling Zero Cuts**: If no cuts are allowed (K=0), the result is simply the maximum initial log length.
3. **Binary Search Initialization**: The search range is initialized with a lower bound just above zero and an upper bound as the maximum log length.
4. **Binary Search Loop**: The loop iterates up to 100 times to ensure precision. For each midpoint value, the total number of cuts required to split all logs into pieces of at most the midpoint length is calculated.
5. **Feasibility Check Adjustment**: Depending on whether the total cuts required are within the allowed K cuts, the search range is adjusted to narrow down the optimal maximum length.
6. **Result Calculation**: After the binary search completes, the upper bound of the search range is rounded up to the nearest integer to get the final result.

This approach efficiently narrows down the optimal maximum length using binary search, ensuring the solution is both optimal and efficient, even for large input sizes.
