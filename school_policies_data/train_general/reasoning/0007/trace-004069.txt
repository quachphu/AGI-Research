To solve this problem, we need to simulate the behavior of a Least Recently Used (LRU) cache after processing a sequence of accesses. The goal is to determine the state of the cache after all accesses, ordered from the most recently used to the least recently used.

### Approach
1. **Understanding LRU Cache**: The LRU cache evicts the least recently accessed item when it is full and a new item is added. Each access to an item moves it to the most recently used position.
2. **Data Structure Choice**: Use an `OrderedDict` from Python's `collections` module. This structure maintains the insertion order and allows efficient reordering of elements.
3. **Operations**:
   - **Access Existing Item**: If the item is already in the cache, move it to the end to mark it as most recently used.
   - **Add New Item**: If the item is not in the cache and the cache is full, remove the least recently used item (the first item in the `OrderedDict`). Add the new item to the end.
4. **Result Extraction**: After processing all accesses, the cache's keys (from least to most recent) are reversed to get the order from most to least recent.

### Solution Code
```python
import sys
from collections import OrderedDict

def main():
    n, m = map(int, sys.stdin.readline().split())
    cache = OrderedDict()
    for _ in range(n):
        key = int(sys.stdin.readline())
        if key in cache:
            cache.move_to_end(key)
        else:
            if len(cache) >= m:
                cache.popitem(last=False)
            cache[key] = None  # Value is irrelevant, we track keys only
    # Reverse to get most recent first
    for k in reversed(cache.keys()):
        print(k)

if __name__ == "__main__":
    main()
```

### Explanation
- **Reading Input**: The first line reads the number of accesses (N) and the cache size (M). Subsequent lines are the sequence of accessed IDs.
- **Processing Accesses**: For each ID:
  - If it exists in the cache, it is moved to the end to mark it as most recently used.
  - If it does not exist and the cache is full, the least recently used item (first item) is evicted before adding the new item to the end.
- **Output**: The keys in the cache are reversed to produce the order from most recent to least recent access, which is then printed.

This approach efficiently handles up to 100,000 operations with an average time complexity of O(1) per operation, leveraging the properties of `OrderedDict` for maintaining order and efficient reordering.
