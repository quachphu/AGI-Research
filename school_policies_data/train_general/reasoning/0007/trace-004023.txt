To solve this problem, we need to determine the maximum number of coins Tima can collect from judges, following the rule that he cannot collect coins from two consecutive judges. This problem is a classic example of the "House Robber" problem, which can be efficiently solved using dynamic programming.

### Approach
1. **Dynamic Programming Insight**: For each judge, Tima has two choices: either take the coins from the current judge and add them to the coins collected up to two judges before, or skip the current judge and take the maximum coins collected up to the previous judge. This leads to the recurrence relation:
   - `dp[i] = max(dp[i-1], dp[i-2] + A[i])`
   
2. **Space Optimization**: Instead of maintaining an entire DP array, we can optimize space by using two variables to keep track of the maximum coins collected up to the previous two judges. This reduces the space complexity to O(1).

3. **Edge Cases**: Handle cases where there are no judges (N=0) or only one judge (N=1) separately to ensure correct results.

### Solution Code
```python
import sys

def main():
    T = int(sys.stdin.readline())
    for _ in range(T):
        # Read N, handling possible leading/trailing empty lines
        N_line = sys.stdin.readline().strip()
        while N_line == '':
            N_line = sys.stdin.readline().strip()
        N = int(N_line)
        
        # Read the list of coins
        A_line = sys.stdin.readline().strip()
        while A_line == '':
            A_line = sys.stdin.readline().strip()
        A = list(map(int, A_line.split()))
        
        if N == 0:
            print(0)
            continue
        if N == 1:
            print(A[0])
            continue
        
        prev_prev = A[0]
        prev = max(A[0], A[1])
        for i in range(2, N):
            current = max(prev, prev_prev + A[i])
            prev_prev, prev = prev, current
        
        print(prev)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read line by line to handle each test case separately. This ensures that we correctly read the number of judges and their respective coins even if there are empty lines in the input.

2. **Dynamic Programming Calculation**: For each test case:
   - If there are no judges, the result is 0.
   - If there is one judge, the result is the coins from that judge.
   - For more than one judge, iterate through the list of coins while maintaining two variables (`prev_prev` and `prev`) to track the maximum coins collected up to the previous two judges. Update these variables iteratively to compute the maximum coins without using extra space.

This approach efficiently computes the solution in O(N) time for each test case with O(1) space, making it suitable for large input sizes up to 100,000 judges.
