To solve this problem, we need to determine the k-th number in the sorted sequence of numbers visited by Rasta on a Darie circle, where he starts at 1 and jumps p positions clockwise each time until he revisits a number. The solution must efficiently handle up to 100,000 test cases with values up to 1,000,000.

### Approach
1. **Understanding the Cycle**: The numbers visited by Rasta form a cycle determined by the greatest common divisor (gcd) of n (the number of positions) and p (the jump length). The length of this cycle is `n // gcd(n, p)`.
2. **Cycle Elements**: The elements in the cycle are in an arithmetic sequence starting from 1, with a step size equal to the gcd of n and p. This is because the gcd determines the interval between consecutive elements in the cycle.
3. **Direct Calculation**: Instead of simulating each jump, we can directly compute the k-th element using the properties of the arithmetic sequence formed by the cycle elements. If k exceeds the number of elements in the cycle, the result is -1.

### Solution Code
```python
import sys
import math

def main():
    input = sys.stdin.read().split()
    t = int(input[0])
    idx = 1
    for _ in range(t):
        n = int(input[idx])
        p = int(input[idx+1])
        k = int(input[idx+2])
        idx += 3
        d = math.gcd(n, p)
        m = n // d
        if k > m:
            print(-1)
        else:
            print(1 + (k-1)*d)
            
if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the large number of test cases.
2. **Cycle Calculation**: For each test case, compute the gcd of n and p. The number of elements in the cycle is `n // gcd(n, p)`.
3. **Determine k-th Element**: Using the arithmetic sequence properties, the k-th element is calculated as `1 + (k-1) * gcd(n, p)`. If k exceeds the number of elements in the cycle, output -1.

This approach ensures that each test case is processed in constant time, making the solution efficient even for the upper limits of input constraints.
