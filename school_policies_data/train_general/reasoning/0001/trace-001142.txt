To solve this problem, we need to simulate a series of cutting operations on a deck of cards and determine which card ends up on top after all operations. The operations involve moving a specific number of cards from a given position to the top of the deck.

### Approach
1. **Initialization**: Start with a deck of `n` cards numbered from `n` to `1` (from top to bottom).
2. **Processing Operations**: For each cutting operation, extract the specified number of cards from the given position and move them to the top of the deck.
3. **Output the Result**: After processing all operations for a dataset, output the card at the top of the deck.

### Solution Code
```python
import sys

def main():
    while True:
        line = sys.stdin.readline()
        if not line:
            break
        n, r = map(int, line.strip().split())
        if n == 0 and r == 0:
            break
        deck = list(range(n, 0, -1))  # Initial deck from top to bottom: n, n-1, ..., 1
        for _ in range(r):
            p, c = map(int, sys.stdin.readline().split())
            sublist = deck[p-1 : p-1 + c]
            deck = sublist + deck[:p-1] + deck[p-1 + c:]
        print(deck[0])

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input consists of multiple datasets. Each dataset starts with two integers `n` (number of cards) and `r` (number of operations). The end of input is marked by `0 0`.
2. **Deck Initialization**: The deck is initialized such that the top card is `n` and the bottom card is `1`. This is achieved using `list(range(n, 0, -1))`.
3. **Cutting Operations**: For each operation, the specified cards are extracted from the deck and moved to the top. This is done using list slicing to split the deck into the relevant parts and recombine them in the new order.
4. **Output**: After processing all operations for a dataset, the top card of the resulting deck is printed.

This approach efficiently handles the operations by directly manipulating the list representing the deck, ensuring correctness and simplicity. Each operation is processed in linear time relative to the number of cards, making the solution efficient given the problem constraints.
