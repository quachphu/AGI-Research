To solve this problem, we need to determine if we can repeatedly combine pairs of integers with the same parity (both even or both odd) until only one integer remains on the blackboard.

### Approach
The key insight is to recognize that the parity (even or odd) of the integers plays a crucial role in determining whether we can reduce the list to a single integer. Specifically, we need to focus on the count of odd integers:
1. If the number of odd integers is even, we can pair all odd integers and combine them into even integers. After this, we can combine all even integers until only one remains.
2. If the number of odd integers is odd, we will always be left with one odd integer after pairing the others, and combining the remaining even integers will leave us with one even and one odd integer, which cannot be combined further.

Thus, the solution hinges on checking if the count of odd integers is even. If it is, the answer is "YES"; otherwise, it is "NO".

### Solution Code
```python
n, *rest = map(int, open(0).read().split())
a = rest[:n]
odd_count = sum(x % 2 != 0 for x in a)
print("YES" if odd_count % 2 == 0 else "NO")
```

### Explanation
1. **Reading Input:** The input is read and parsed to extract the list of integers.
2. **Counting Odd Integers:** We count how many of the integers are odd.
3. **Checking Parity of Odd Count:** If the count of odd integers is even, we print "YES" because we can pair all odd integers and combine the resulting even integers. If the count is odd, we print "NO" because we will inevitably be left with one unpaired integer.

This approach efficiently determines the result in linear time, making it suitable for large input sizes up to 100,000 integers.
