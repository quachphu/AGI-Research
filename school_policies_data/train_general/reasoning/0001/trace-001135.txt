To solve this problem, we need to transform a given sequence of positive integers into a "good sequence" by removing the minimum number of elements. A good sequence is defined as one where each element x occurs exactly x times.

### Approach
1. **Frequency Counting**: First, we count the frequency of each element in the input sequence using a dictionary.
2. **Determine Contributions**: For each element x, check if its frequency is at least x. If it is, we can contribute exactly x elements to the good sequence. Otherwise, we cannot include x in the good sequence.
3. **Calculate Minimum Removals**: The minimum number of elements to remove is the total number of elements in the original sequence minus the sum of contributions from all valid elements.

### Solution Code
```python
import sys
from collections import Counter

def main():
    input = sys.stdin.read().split()
    n = int(input[0])
    a = list(map(int, input[1:n+1]))
    freq = Counter(a)
    sum_kept = 0
    for x in freq:
        if freq[x] >= x:
            sum_kept += x
    print(n - sum_kept)

if __name__ == '__main__':
    main()
```

### Explanation
1. **Reading Input**: The input is read from standard input and parsed into an integer list.
2. **Frequency Calculation**: Using the `Counter` from the `collections` module, we count how many times each element appears in the list.
3. **Valid Contributions**: For each unique element in the frequency dictionary, we check if its count is sufficient to form a valid contribution (i.e., the count is at least the element's value). If valid, we add the element's value to the sum of kept elements.
4. **Result Calculation**: The result is derived by subtracting the sum of valid contributions from the total number of elements in the original sequence. This gives the minimum number of elements to remove to form a good sequence.

This approach efficiently determines the optimal elements to keep, ensuring minimal removals while adhering to the constraints of forming a good sequence. The algorithm runs in linear time relative to the input size, making it suitable for large inputs up to the given constraint limits.
