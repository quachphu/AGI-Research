To solve this problem, we need to count the number of ways to split an array into three contiguous parts such that each part has the same sum. The solution involves checking if the total sum of the array is divisible by three and then using prefix sums to efficiently determine valid split points.

### Approach
1. **Check Divisibility by Three**: First, check if the total sum of the array is divisible by three. If not, it's impossible to split the array as required, and the answer is zero.
2. **Calculate Target Sums**: If the total sum is divisible by three, compute the target sum for each part as one-third of the total sum. The sum of the first two parts must be two-thirds of the total sum.
3. **Prefix Sum Tracking**: Use prefix sums to track cumulative sums up to each index. As we iterate through the array, count how many times we encounter the target sum (one-third of the total) and use this count to determine valid splits when encountering two-thirds of the total sum.

### Solution Code
```python
n = int(input())
a = list(map(int, input().split()))

prefix = [0] * (n + 1)
for i in range(n):
    prefix[i + 1] = prefix[i] + a[i]

total = prefix[n]
if total % 3 != 0:
    print(0)
else:
    t = total // 3
    t2 = 2 * t
    count_t = 0
    ways = 0
    for i in range(1, n):  # i ranges from 1 to n-1 (since j can be up to n)
        if prefix[i] == t2:
            ways += count_t
        if prefix[i] == t:
            count_t += 1
    print(ways)
```

### Explanation
1. **Prefix Sum Array**: Construct a prefix sum array where each entry at index `i` represents the sum of the array elements up to the `i`-th element.
2. **Divisibility Check**: If the total sum of the array is not divisible by three, immediately return zero as no valid split is possible.
3. **Target Sums**: Compute the target sum for each part (`t`) and twice this target (`t2`), which helps in identifying the end of the second part.
4. **Iterate and Count**: Traverse the prefix sum array. For each index:
   - If the prefix sum equals `t2`, add the count of times we've seen the prefix sum `t` to the result. This is because each occurrence of `t` before `t2` indicates a valid start of the second part.
   - If the prefix sum equals `t`, increment the count of valid starting points for the second part.

This approach efficiently counts valid splits in linear time, making it suitable for large arrays up to the constraint limits.
