To solve this problem, we need to determine if Mike can change exactly one character in a given string to make it a palindrome. A palindrome reads the same forwards and backwards. The solution involves checking the number of mismatched character pairs in the string and determining if changing one character can result in a valid palindrome.

### Approach
1. **Count Mismatched Pairs**: Compare each character from the start of the string with its corresponding character from the end. Count the number of mismatched pairs.
2. **Check Conditions**:
   - If there is exactly one mismatched pair, changing one character in this pair will make the string a palindrome.
   - If there are no mismatched pairs, check the length of the string. If the length is odd, changing the middle character will still result in a palindrome. If the length is even, changing any character will break the palindrome.
   - If there are more than one mismatched pairs, changing a single character cannot make the string a palindrome.

### Solution Code
```python
def main():
    s = input().strip()
    n = len(s)
    diff_count = 0
    for i in range(n // 2):
        if s[i] != s[n - 1 - i]:
            diff_count += 1
    if diff_count == 1:
        print("YES")
    elif diff_count == 0:
        print("YES" if n % 2 == 1 else "NO")
    else:
        print("NO")

main()
```

### Explanation
1. **Reading Input**: The input string is read and its length is determined.
2. **Counting Mismatches**: We iterate through the first half of the string, comparing each character with its corresponding character from the end. Mismatches are counted.
3. **Decision Based on Mismatches**:
   - **Exactly One Mismatch**: Changing one character in this pair will resolve the mismatch, resulting in a palindrome.
   - **No Mismatches**: If the string length is odd, changing the middle character (which doesn't affect the palindrome property) is allowed. For even lengths, any change will break the palindrome.
   - **More Than One Mismatch**: Changing one character cannot resolve all mismatches, hence the result is "NO".

This approach efficiently checks the necessary conditions with a linear scan of half the string, ensuring optimal performance even for the maximum input size.
