To solve this problem, we need to determine the minimum possible final health of the last monster alive after a series of attacks. The key insight here is that the problem can be reduced to finding the greatest common divisor (GCD) of all initial health values of the monsters. This is because the process of attacking monsters and reducing their health mimics the steps of the Euclidean algorithm used to compute the GCD.

### Approach
1. **Understanding the Problem**: Each attack reduces the health of the attacked monster by the current health of the attacking monster. This process continues until only one monster remains. The goal is to find the minimum possible health of the last remaining monster.
2. **Key Insight**: The minimum possible final health is determined by the GCD of all initial health values. This is because the GCD is the smallest value that can be obtained through a series of reductions similar to the Euclidean algorithm.
3. **Algorithm**: Compute the GCD of all the initial health values. This can be efficiently done using the `math.gcd` function in Python and iterating through the list of health values.

### Solution Code
```python
import math
from functools import reduce

def main():
    import sys
    input = sys.stdin.read().split()
    n = int(input[0])
    a = list(map(int, input[1:n+1]))
    gcd = reduce(math.gcd, a)
    print(gcd)

if __name__ == "__main__":
    main()
```

### Explanation
- **Reading Input**: The input is read from standard input, which includes the number of monsters and their respective health values.
- **Computing GCD**: Using the `reduce` function from the `functools` module and `math.gcd`, we compute the GCD of all health values. The `reduce` function applies the `math.gcd` function cumulatively to the items of the list, resulting in the GCD of the entire list.
- **Output**: The computed GCD is printed, which represents the minimum possible final health of the last remaining monster.

This approach efficiently computes the result in O(N) time complexity, where N is the number of monsters, making it suitable even for large input sizes up to 100,000.
