To solve this problem, we need to determine the maximum number of Grey hats (numbers) that can be selected from a given range [L, R] such that no two selected numbers form a volatile pair. A volatile pair is defined as two numbers i and j (i < j) where j ≤ i * K. 

### Approach
The key insight is to recognize that to avoid volatile pairs, each subsequent number in the selected set must be greater than the previous number multiplied by K. This ensures that no two selected numbers will form a volatile pair. The strategy is to start with the smallest number in the range and iteratively select the next smallest number that is greater than the current number multiplied by K. This greedy approach ensures we maximize the count of selected numbers.

### Solution Code
```python
import sys

def max_grey_hats():
    input = sys.stdin.read().split()
    T = int(input[0])
    idx = 1
    for _ in range(T):
        L = int(input[idx])
        R = int(input[idx+1])
        K = int(input[idx+2])
        idx += 3
        
        count = 0
        current = L
        if current > R:
            print(0)
            continue
        count = 1
        while True:
            next_val = current * K + 1
            if next_val > R:
                break
            count += 1
            current = next_val
        print(count)

max_grey_hats()
```

### Explanation
1. **Reading Input:** The input is read in one go for efficiency, especially given the constraints.
2. **Initialization:** For each test case, initialize the count of selected numbers and start with the smallest number in the range, L.
3. **Greedy Selection:** Check if the next number (current * K + 1) is within the range [L, R]. If it is, increment the count and update the current number. If it exceeds R, the loop terminates.
4. **Output the Result:** After processing all test cases, the results are printed.

This approach efficiently ensures that each selected number is the smallest possible to avoid forming volatile pairs, thus maximizing the count of selected numbers. The algorithm runs in O(log_K(R)) time per test case, which is efficient given the problem constraints.
