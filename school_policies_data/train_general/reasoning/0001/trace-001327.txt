To solve this problem, we need to efficiently track the number of dummy calls made when inserting objects into a hash table using linear probing. The challenge is to handle both insertions and deletions efficiently, even for large input sizes.

### Approach
1. **Hash Table Structure**: The hash table is divided into `g` classes based on the greatest common divisor (gcd) of the table size `h` and the collision resolution step `m`. Each class `r` (0 ≤ r < g) contains cells that are congruent to `r` modulo `g`.

2. **Cycle Order**: For each class, we precompute the order in which cells are probed. This order is a cycle generated by starting at cell 0 and repeatedly adding the step size `m'` (where `m' = m / g`).

3. **Available Cells Tracking**: For each class, we maintain a sorted list of available cells in the order they are probed. This allows us to quickly find the next available cell using binary search.

4. **Insertions and Deletions**: When inserting an object, we use the precomputed cycle order to determine the next available cell and count the dummy calls. When deleting an object, we update the available cells list to reflect the freed cell.

### Solution Code
```python
import sys
from math import gcd
from bisect import bisect_left, insort

def main():
    h, m, n = map(int, sys.stdin.readline().split())
    g = gcd(h, m)
    h_prime = h // g
    m_prime = m // g

    # Prepare each class's data
    classes = []
    for r in range(g):
        visited = set()
        current = 0
        cycle_order = []
        while current not in visited:
            visited.add(current)
            cycle_order.append(current)
            current = (current + m_prime) % h_prime
        # Create a mapping from cell index k to its position in cycle_order
        cell_to_cycle = {k: idx for idx, k in enumerate(cycle_order)}
        available = list(range(len(cycle_order)))  # Initially all available
        classes.append((available, cycle_order, cell_to_cycle))

    id_map = {}
    total = 0

    for _ in range(n):
        parts = sys.stdin.readline().split()
        if parts[0] == '+':
            # Add operation
            id = int(parts[1])
            hash_t = int(parts[2])
            r = hash_t % g
            q = hash_t // g
            available, cycle_order, cell_to_cycle = classes[r]
            current_k = q
            current_cycle_idx = cell_to_cycle[current_k]

            pos = bisect_left(available, current_cycle_idx)
            if pos < len(available):
                found_cycle_idx = available[pos]
                dummy = found_cycle_idx - current_cycle_idx
            else:
                if available:
                    found_cycle_idx = available[0]
                    dummy = (len(cycle_order) - current_cycle_idx) + found_cycle_idx
                else:
                    dummy = 0  # As per problem statement, this won't happen

            # Remove the found_cycle_idx from available
            if pos < len(available):
                available.pop(pos)
            else:
                if available:
                    available.pop(0)
            total += dummy

            # Record the cell's k in the class
            found_k = cycle_order[found_cycle_idx]
            id_map[id] = (r, found_k)
        else:
            # Delete operation
            id = int(parts[1])
            r, k = id_map.pop(id)
            available, cycle_order, cell_to_cycle = classes[r]
            found_cycle_idx = cell_to_cycle[k]
            insort(available, found_cycle_idx)

    print(total)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Class Division**: The hash table is divided into `g` classes based on the gcd of `h` and `m`. Each class has `h_prime = h / g` cells.

2. **Cycle Order Calculation**: For each class, we precompute the order in which cells are probed using linear probing. This order is stored in `cycle_order`.

3. **Available Cells Management**: Each class maintains a sorted list of available cells using their indices in `cycle_order`. This allows efficient lookup and update operations.

4. **Insertion Handling**: When inserting an object, we determine the starting cell and use binary search to find the next available cell in the cycle. The number of dummy calls is the difference between the starting index and the found available cell's index in the cycle.

5. **Deletion Handling**: When deleting an object, the corresponding cell is marked as available again and reinserted into the sorted list of available cells for its class.

This approach ensures efficient handling of both insertions and deletions, achieving the required performance even for large input sizes.
