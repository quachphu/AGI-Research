The challenge is to find the optimal sequence of operations to minimize the total steps.

### Approach
1. **Direct Division**: Calculate the steps required if we never increment `b` and only use the division operation.
2. **Increment to Exceed `a`**: Calculate the steps required if we increment `b` until it exceeds `a`, then perform a single division.
3. **Increment and Check**: Iterate over a range of possible increments (up to 100) to find the optimal number of increments followed by divisions.

### Solution Code
```python
def steps_to_zero(a, b_prime):
    if b_prime == 1:
        return float('inf')
    steps = 0
    current = a
    while current > 0:
        current = current // b_prime
        steps += 1
    return steps

def compute_min_operations(a, b):
    min_steps = float('inf')
    
    # Case 1: No increments (k=0)
    if b != 1:
        steps = steps_to_zero(a, b)
        min_steps = min(min_steps, steps)
    
    # Case 2: Increment until b_prime > a
    if b > a:
        steps_case2 = 1
    else:
        steps_case2 = (a + 1 - b) + 1
    min_steps = min(min_steps, steps_case2)
    
    # Case 3: Check k from 0 to 100
    max_k = min(100, a)  # To avoid unnecessary iterations when a is small
    for k in range(0, max_k + 1):
        b_prime = b + k
        if b_prime == 1 and a > 0:
            continue
        current_steps = k + steps_to_zero(a, b_prime)
        if current_steps < min_steps:
            min_steps = current_steps
    
    return min_steps

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    print(compute_min_operations(a, b))
```

### Explanation
1. **Direct Division**: If `b` is 1, it's impossible to reduce `a` to 0 by division alone. For other values of `b`, we repeatedly divide `a` by `b` until `a` becomes 0.
2. **Increment to Exceed `a`**: If `b` is incremented until it exceeds `a`, only one division is needed to reduce `a` to 0. The steps here are the increments needed plus one division.
3. **Increment and Check**: By iterating over a reasonable range of increments (0 to 100), we check each possible value of `b` after increments and compute the total steps required. This balances the trade-off between increment steps and subsequent division steps.

This approach efficiently explores the possible sequences of operations, ensuring we find the minimal steps required without exhaustive checks for all possible increments.
