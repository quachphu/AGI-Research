To solve this problem, we need to determine the ratio of characters typed in Jhool's Semantic Mind-Reader browser compared to a normal browser for a given list of websites. The key insights involve understanding the specific optimizations provided by Jhool's browser, such as omitting the 'www.' prefix and predicting all vowels in the main part of the website name (excluding the '.com' suffix).

### Approach
1. **Input Reading**: Read the number of test cases followed by each website name.
2. **Normal Browser Character Count**: The length of the website name as provided.
3. **Jhool's Browser Character Count**:
   - Remove the 'www.' prefix and the '.com' suffix to isolate the main part of the website.
   - Count the consonants in the main part (vowels are predicted and thus not typed).
   - Add 4 to account for the '.com' suffix which is still required.
4. **Ratio Calculation**: Compute the ratio of characters typed in Jhool's browser to the normal browser and print it as a fraction.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().splitlines()
    tc = int(input[0])
    for i in range(1, tc + 1):
        website = input[i].strip()
        original_length = len(website)
        main_part = website[4:-4]
        consonants = sum(1 for c in main_part if c not in 'aeiou')
        jhool_length = consonants + 4
        print(f"{jhool_length}/{original_length}")

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once and split into lines for efficient processing.
2. **Processing Each Website**:
   - **Original Length**: Directly obtained from the length of the website string.
   - **Main Part Extraction**: The part between 'www.' and '.com' is isolated by slicing the string from index 4 to -4.
   - **Consonant Counting**: Iterate through each character in the main part, counting non-vowel characters.
   - **Jhool's Character Count**: Sum of consonants in the main part and the fixed 4 characters for '.com'.
3. **Output**: The ratio is formatted as a fraction and printed for each website.

This approach efficiently processes each website in linear time relative to the length of the website name, ensuring optimal performance even for the upper constraint limits.
