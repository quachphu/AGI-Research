To solve this problem, we need to determine the maximum number of stones Chef can remove from the table when both Chef and Roma play optimally. Chef takes the first turn, and each player aims to maximize their own total stones removed.

### Approach
1. **Understanding Optimal Play**: Both players will aim to pick the largest available pile on their turn to maximize their total. This means the optimal strategy for both players is to always pick the largest remaining pile.
2. **Sorting**: By sorting the list of piles in descending order, we can simulate the optimal play where each player picks the largest available pile on their turn.
3. **Alternating Selection**: Chef (first player) will pick the piles at even indices (0, 2, 4, ...) after sorting, while Roma (second player) will pick the piles at odd indices (1, 3, 5, ...). Summing the elements at even indices gives Chef's maximum possible stones.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    idx = 0
    T = int(input[idx])
    idx += 1
    for _ in range(T):
        N = int(input[idx])
        idx +=1
        A = list(map(int, input[idx:idx+N]))
        idx += N
        A.sort(reverse=True)
        total = 0
        for i in range(0, N, 2):
            total += A[i]
        print(total)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the constraints. We parse the number of test cases first.
2. **Sorting**: For each test case, we read the number of piles and the list of stones. The list is sorted in descending order to facilitate optimal play.
3. **Summing Even Indices**: By iterating over the sorted list and summing elements at even indices (0, 2, 4, ...), we effectively simulate Chef picking the largest remaining pile each time it's his turn. This ensures Chef's total is maximized under optimal play by both players.

This approach ensures that we efficiently determine the maximum stones Chef can remove by leveraging sorting and a simple summation of elements at strategic positions. The complexity is dominated by the sorting step, making it O(N log N) per test case, which is efficient given typical constraints.
