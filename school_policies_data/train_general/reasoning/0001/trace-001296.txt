To solve this problem, we need to determine how many times the numbers 0 and 1 are printed when computing the nth Fibonacci number using a specific recursive algorithm. The algorithm prints 0 and 1 when it encounters the base cases (n=0 and n=1 respectively) during recursion. 

### Approach
The key insight is to recognize that the number of times 0 and 1 are printed follows the same recurrence relation as the Fibonacci sequence itself. This allows us to use dynamic programming to efficiently precompute these counts for all values up to the maximum constraint (n=40).

1. **Define Recurrence Relations**:
   - Let `zero(n)` be the number of times 0 is printed when computing the nth Fibonacci number.
   - Let `one(n)` be the number of times 1 is printed when computing the nth Fibonacci number.
   - Base cases:
     - `zero(0) = 1` (since n=0 directly prints 0)
     - `one(0) = 0` (no 1s printed here)
     - `zero(1) = 0` (no 0s printed here)
     - `one(1) = 1` (since n=1 directly prints 1)
   - For n >= 2:
     - `zero(n) = zero(n-1) + zero(n-2)`
     - `one(n) = one(n-1) + one(n-2)`

2. **Precomputation**:
   - Precompute the values of `zero` and `one` for all values from 0 to 40 using the above recurrence relations. This allows each query to be answered in constant time.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    T = int(input[0])
    cases = list(map(int, input[1:T+1]))
    
    max_n = 40
    zero = [0] * (max_n + 1)
    one = [0] * (max_n + 1)
    
    zero[0] = 1
    one[0] = 0
    if max_n >= 1:
        zero[1] = 0
        one[1] = 1
    
    for i in range(2, max_n + 1):
        zero[i] = zero[i-1] + zero[i-2]
        one[i] = one[i-1] + one[i-2]
    
    for n in cases:
        print(f"{zero[n]} {one[n]}")

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read all at once for efficiency, especially given the constraints.
2. **Precomputation**: Arrays `zero` and `one` are initialized and filled using the recurrence relations derived. This ensures that each value from 0 to 40 is computed once and stored for quick lookup.
3. **Query Handling**: For each test case, the precomputed values are directly accessed and printed, resulting in an efficient O(1) response per query.

This approach ensures that even for the upper constraint of N=40, the solution remains efficient and handles up to 50 test cases seamlessly.
