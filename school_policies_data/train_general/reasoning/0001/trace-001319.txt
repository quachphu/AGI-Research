To solve this problem, we need to determine the minimum number of moves required to transform a number \( n \) into \( m \) using only multiplications by 2 or 3. If it is impossible to achieve \( m \) from \( n \) using these operations, we should return -1.

### Approach
1. **Check Divisibility**: First, check if \( m \) is divisible by \( n \). If not, it's impossible to reach \( m \) from \( n \) using the allowed operations, so we return -1.
2. **Compute Quotient**: If \( m \) is divisible by \( n \), compute the quotient \( q = m / n \).
3. **Factorize the Quotient**: Factorize \( q \) into its prime factors, but only consider factors 2 and 3. Count the number of times \( q \) can be divided by 2 and 3.
4. **Check Remaining Quotient**: After removing all factors of 2 and 3 from \( q \), if the remaining value is 1, the sum of the counts of divisions by 2 and 3 gives the required number of moves. If the remaining value is not 1, it means \( q \) had other prime factors, making the transformation impossible, so return -1.

### Solution Code
```python
def main():
    import sys
    n, m = map(int, sys.stdin.readline().split())
    if m % n != 0:
        print(-1)
        return
    quotient = m // n
    steps = 0
    # Check factors 2 and 3
    for factor in [2, 3]:
        while quotient % factor == 0:
            steps += 1
            quotient //= factor
    print(steps if quotient == 1 else -1)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Divisibility Check**: The transformation is only possible if \( m \) is a multiple of \( n \). If \( m \% n \neq 0 \), we immediately return -1.
2. **Quotient Calculation**: The quotient \( q = m // n \) represents how many times \( n \) needs to be multiplied by 2 or 3 to reach \( m \).
3. **Factorization**: By repeatedly dividing \( q \) by 2 and 3, we count the number of such operations (steps). Each division by 2 or 3 corresponds to a valid move in the transformation process.
4. **Validation**: If after removing all factors of 2 and 3, the quotient reduces to 1, the transformation is possible, and the total steps are the sum of divisions by 2 and 3. Otherwise, it is impossible, and we return -1.

This approach efficiently checks the necessary conditions and counts the required operations in linear time relative to the logarithm of the quotient, making it suitable for large input values up to \( 5 \times 10^8 \).
