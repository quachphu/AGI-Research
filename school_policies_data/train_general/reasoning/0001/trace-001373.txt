To solve this problem, we need to determine the number of ways Rohit can select `n` marbles such that he has at least one marble of each of `k` different colors. This problem can be efficiently solved using combinatorial mathematics, specifically the stars and bars theorem.

### Approach
The problem can be translated into a combinatorial problem where we need to distribute `n` marbles into `k` colors such that each color has at least one marble. This is equivalent to finding the number of ways to partition `n-1` items into `k-1` groups, which can be computed using the binomial coefficient `C(n-1, k-1)`.

To compute this binomial coefficient efficiently, especially for large values of `n` and `k`, we use an iterative approach that avoids large intermediate values. This approach involves multiplying terms from the numerator and dividing by terms from the denominator step-by-step to keep the intermediate results manageable.

### Solution Code
```python
import sys

def main():
    input = sys.stdin.read().split()
    T = int(input[0])
    idx = 1
    for _ in range(T):
        n = int(input[idx])
        k = int(input[idx + 1])
        idx += 2
        a = n - 1
        b = k - 1
        if b == 0:
            print(1)
            continue
        # Compute C(a, b) using the multiplicative formula
        if b > a - b:
            b = a - b
        res = 1
        for i in range(1, b + 1):
            res = res * (a - b + i) // i
        print(res)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input**: The input is read in one go for efficiency, especially given the constraints.
2. **Iterative Calculation**: For each test case, we compute the binomial coefficient `C(n-1, k-1)` using an iterative approach. This involves:
   - Adjusting `b` to be the smaller of `k-1` and `n-k` to minimize the number of iterations.
   - Multiplying the terms of the numerator and dividing by the terms of the denominator incrementally to keep intermediate results small.
3. **Edge Cases**: Directly handle cases where `k=1` since the result is trivially 1.

This approach ensures that we efficiently compute the result even for large values of `n` and `k` within the given constraints, leveraging Python's ability to handle arbitrary-precision integers.
