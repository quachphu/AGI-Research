To solve this problem, we need to determine if the number of Fibonacci numbers within a given range [X, Y] is even. If the count is even, the code is considered valid; otherwise, it is invalid.

### Approach
1. **Precompute Fibonacci Numbers**: Generate all Fibonacci numbers up to the maximum possible value of Y (100,000) and store them in a list. This allows us to efficiently check each test case without recalculating Fibonacci numbers repeatedly.
2. **Count Fibonacci Numbers in Range**: For each test case, count how many of the precomputed Fibonacci numbers fall within the given range [X, Y].
3. **Check Evenness of Count**: Determine if the count of Fibonacci numbers in the range is even or odd and output the result accordingly.

### Solution Code
```python
import sys

def main():
    # Precompute all Fibonacci numbers up to 100000
    fibs = [1, 1]
    while True:
        next_f = fibs[-1] + fibs[-2]
        if next_f > 100000:
            break
        fibs.append(next_f)
    
    # Read input and process each test case
    T = int(sys.stdin.readline())
    for _ in range(T):
        X, Y = map(int, sys.stdin.readline().split())
        count = 0
        for num in fibs:
            if X <= num <= Y:
                count += 1
        print("VALID" if count % 2 == 0 else "INVALID")

if __name__ == "__main__":
    main()
```

### Explanation
1. **Precompute Fibonacci Numbers**: The list `fibs` is initialized with the first two Fibonacci numbers (1, 1). Subsequent numbers are generated by summing the last two elements of the list until the next number exceeds 100,000.
2. **Reading Input**: The number of test cases (T) is read first. For each test case, the values X and Y are read and converted to integers.
3. **Counting in Range**: For each Fibonacci number in the precomputed list, check if it lies within the range [X, Y]. The count of such numbers is incremented accordingly.
4. **Check Evenness**: After counting, the result is determined by checking if the count is even. The result for each test case is printed as "VALID" or "INVALID".

This approach ensures that we efficiently handle up to 10 test cases with ranges up to 100,000 by leveraging precomputation and a simple linear scan for each range check.
