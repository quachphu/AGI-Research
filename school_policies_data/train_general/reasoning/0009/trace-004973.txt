To solve this problem, we need to determine if a given integer \( n \) can be expressed as the sum of \( k \) distinct positive odd integers for multiple test cases. The solution involves checking two key conditions based on parity and minimum sum requirements.

### Approach
1. **Parity Check**: The sum of \( k \) odd integers will be even if \( k \) is even and odd if \( k \) is odd. Therefore, \( n \) and \( k \) must have the same parity (both even or both odd).
2. **Minimum Sum Check**: The minimum sum of \( k \) distinct positive odd integers is \( k^2 \). If \( n \) is less than \( k^2 \), it is impossible to form the sum. Otherwise, it is possible.

### Solution Code
```python
import sys

def solve():
    input = sys.stdin.read().split()
    t = int(input[0])
    idx = 1
    for _ in range(t):
        n = int(input[idx])
        k = int(input[idx + 1])
        idx += 2
        if (n % 2) != (k % 2):
            print("NO")
        else:
            min_sum = k * k
            if n >= min_sum:
                print("YES")
            else:
                print("NO")

solve()
```

### Explanation
1. **Reading Input Efficiently**: The input is read all at once for efficiency, especially given the large possible number of test cases.
2. **Parity Check**: For each test case, we check if \( n \) and \( k \) have the same parity. If they do not, the answer is immediately "NO".
3. **Minimum Sum Check**: If the parity check passes, we compute the minimum possible sum \( k^2 \). If \( n \) is at least this minimum sum, the answer is "YES"; otherwise, it is "NO".

This approach ensures that each test case is processed in constant time \( O(1) \), making the solution efficient even for the upper limits of the input constraints.
