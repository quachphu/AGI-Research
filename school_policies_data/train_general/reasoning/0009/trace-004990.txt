To solve this problem, we need to determine the winner of a game played by Ashima and Aishwarya with three piles of biscuits. The game rules allow players to take biscuits from one, two, or all three piles in each move, and the player who cannot make a move loses. The solution involves precomputing the winning and losing positions using dynamic programming to efficiently answer each query.

### Approach
1. **Dynamic Programming (DP) Setup**: We use a 3D DP array `dp[a][b][c]` where `a`, `b`, and `c` represent the number of biscuits in the three piles. The value of `dp[a][b][c]` is `True` if the current player can force a win from the state `(a, b, c)`, and `False` otherwise.

2. **Precomputation**: We precompute the DP array for all possible states `(a, b, c)` where each pile can have between 0 and 100 biscuits. This is done by iterating through all possible sums of the three piles and checking all valid moves from each state.

3. **Move Generation**: For each state `(a, b, c)`, generate all possible next states by considering valid moves (taking 1 from a single pile, 1 from two piles, or 1 from all three piles). Check if any of these next states are losing positions for the opponent.

4. **Query Processing**: After precomputing the DP array, each query is answered in constant time by checking the precomputed result.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    idx = 0
    Q = int(input[idx])
    idx += 1
    queries = []
    max_pile = 100  # As per constraints, maximum possible pile size is 100
    
    # Read all queries
    for _ in range(Q):
        n1 = int(input[idx])
        n2 = int(input[idx+1])
        n3 = int(input[idx+2])
        queries.append((n1, n2, n3))
        idx += 3
    
    # Initialize DP table
    dp = [[[False]*(max_pile+1) for _ in range(max_pile+1)] for __ in range(max_pile+1)]
    dp[0][0][0] = False  # Base case: all piles empty, losing position
    
    # Process all possible sums of a + b + c in increasing order
    for s in range(1, 3 * max_pile + 1):
        for a in range(0, max_pile + 1):
            for b in range(0, max_pile + 1):
                c = s - a - b
                if c < 0 or c > max_pile:
                    continue  # Skip invalid c values
                
                possible_next = []
                # Single pile moves
                if a > 0:
                    possible_next.append((a-1, b, c))
                if b > 0:
                    possible_next.append((a, b-1, c))
                if c > 0:
                    possible_next.append((a, b, c-1))
                # Two pile moves
                if a > 0 and b > 0:
                    possible_next.append((a-1, b-1, c))
                if a > 0 and c > 0:
                    possible_next.append((a-1, b, c-1))
                if b > 0 and c > 0:
                    possible_next.append((a, b-1, c-1))
                # Three pile move
                if a > 0 and b > 0 and c > 0:
                    possible_next.append((a-1, b-1, c-1))
                
                # Determine if current state is winning
                is_winning = False
                for (na, nb, nc) in possible_next:
                    if not dp[na][nb][nc]:
                        is_winning = True
                        break
                dp[a][b][c] = is_winning
    
    # Answer queries
    for (n1, n2, n3) in queries:
        if dp[n1][n2][n3]:
            print("Ashima")
        else:
            print("Aishwarya")

if __name__ == "__main__":
    main()
```

### Explanation
- **Dynamic Programming Setup**: The DP array `dp` is initialized to keep track of whether the current player can force a win from any given state `(a, b, c)`.
- **Precomputation**: We iterate through all possible sums of the three piles, generating each valid state `(a, b, c)` and determining if it's a winning or losing position by checking all possible moves.
- **Move Generation**: For each state, we generate all valid moves and check if any of these moves leads to a losing position for the opponent. If so, the current state is marked as a winning position.
- **Efficiency**: By precomputing all possible states, each query is answered in constant time, making the solution efficient even for the upper constraint of 10,000 queries.
