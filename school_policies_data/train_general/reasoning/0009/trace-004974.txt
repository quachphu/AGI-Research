To solve this problem, we need to determine the minimum number of operations required to make either of two variables, `a` or `b`, exceed a given value `n` using only the operations `a += b` or `b += a`.

### Approach
The key insight is to recognize that the optimal strategy involves always adding the smaller variable to the larger one. This approach maximizes the growth rate of the variables, ensuring that we reach the target value in the fewest steps. By repeatedly applying this strategy, we can simulate the process efficiently, as each step significantly increases one of the variables, leading to a logarithmic number of steps relative to the target value `n`.

### Solution Code
```python
def main():
    import sys
    input = sys.stdin.read().split()
    T = int(input[0])
    idx = 1
    for _ in range(T):
        a = int(input[idx])
        b = int(input[idx+1])
        n = int(input[idx+2])
        idx +=3
        steps = 0
        while a <= n and b <= n:
            if a < b:
                a += b
            else:
                b += a
            steps += 1
            if a > n or b > n:
                break
        print(steps)

if __name__ == "__main__":
    main()
```

### Explanation
1. **Reading Input:** The input is read in one go for efficiency, especially given the constraints. The first value `T` represents the number of test cases.
2. **Processing Each Test Case:** For each test case, the initial values of `a`, `b`, and `n` are read.
3. **Simulating Operations:** The loop continues until either `a` or `b` exceeds `n`. In each iteration, the smaller variable is added to the larger one to maximize growth. The number of steps is counted and incremented with each operation.
4. **Termination Check:** After each operation, we check if either variable has exceeded `n`. If so, the loop breaks, and the current step count is printed.

This approach ensures that we minimize the number of operations by leveraging the exponential growth characteristic of adding smaller values to larger ones, leading to an efficient solution even for large values of `n`.
